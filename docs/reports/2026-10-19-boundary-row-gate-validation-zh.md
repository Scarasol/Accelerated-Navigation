# Boundary 端口空行外提：正确性与完整查询验证

日期：2026-10-19。证据根：`.tmp/boundary-row-gate-20261019-v1/`。
用户确认合法起点已在位图中、O(1) 判断值得验证后，独立实施本次验证。

## 结论

**位图确实已经存在，空行外提有局部收益；本次实现的完整冷查询结果不支持采用，保留 C。**

- 完整 Boundary 局部净测：平地耗时 -6.07%/-8.48%，选定城市列 -28.09%/-27.83%。
- 全端口行非空的人工压力输入：耗时 +2.77%/+0.59%，新增判断成本没有被删除。
- 完整冷 air：查询均值 +8.52%/+19.92%，中位数 +8.21%/+22.00%，两对均不利。
- 冷 distinct 均值 +0.60%/+0.77%；mixed -1.89%/-3.37%，不足以覆盖 air 的不利。
- 没有输出、参数异常、引用账目或类来源错误；没有因此证明方法本身无效，
  也没有定位到足以解释完整查询回退的具体根因。

本轮停止的是**这一行外提的当前 P 实现**，不把“封存”当作否定全部端口位图方法的理由。
不追加相同测试挑选结果，不重写 helper 或叠加边界快照复制优化。
生产源码、默认 JAR、旧 B/R2/C/C2/D 与历史结果保持；未提交、推送或接入生产。

## 修改及比较口径

C 为冻结的 `component-build-shortcuts-20261019-v1/C`。
P 从 C 复制，仅在 `SuperClusterTopology.boundaryLinks` 的 GROUND 路径中，
进入方向、距离和 dy 循环之前增加：

```java
if (source.portBits().faceRow(face, inset, v) == 0) continue;
```

原 `candidates` 内的空行判断保留，非空行仍执行原筛选和严格碰撞。
没有重算合法起点、创建新索引、改变事实/halo/stamp、owner、缓存或依赖范围。
VOLUME 仍走原标量分支，参数和几何/邻接检查位置不变。
源码差分精确限定为一个文件、一条新增判断。

本轮数值是直接 **P/C**，用于判断这一项在 C 上的增量。
[此前直接 C/B 数据](2026-10-19-interface-aligned-c-baseline-validation-zh.md)只作背景，
不将两轮百分比连乘为 P/B；没有启动 B/R2/C/P 多方矩阵。
本轮未复测热 readyGraph，其测量窗口不包含本次修改的 Boundary 构建；
这只是测试范围说明，不据此宣称热接口已取得新的不退化证明。

## 固定筛选与取舍

测前协议要求：局部 flat/city 和 dense 两顺序耗时不高于 C 的 3%；
各冷模式/顺序的均值、中位数不高于 C 的 3%，完整分配不高于 3%；
至少两种冷模式的跨顺序查询均值几何比改善达到 3%。
CPU 因已知短窗口粒度仅描述，不用零读数放行稳定 CPU。

局部门通过；冷控制门和收益门未通过：
air 两对均值与中位数明显超过 3%，distinct 第一对中位数 +3.65%，
mixed 第二对中位数 +3.41%。
跨顺序查询均值几何变化为 air +14.08%、distinct +0.69%、mixed -2.63%，
没有两种模式达到约定改善。
`screen.promising=false`，`selected=C`。

本轮没有发现测试接口错配、错误 oracle 或候选类加载回退；
这不等于已解释完整查询回退。
保留局部证据和方法适用边界，不把一次实现的停止升级成永久否定，
也不因局部成绩有利而追加候选改法或扩样。
后续若继续，应针对完整路径实际额外成本提出有依据的最小修改，
不能只凭 O(1)、静态循环数或历史候选封存状态判断优先级。
