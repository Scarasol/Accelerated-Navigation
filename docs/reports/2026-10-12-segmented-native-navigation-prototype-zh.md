# 宏观走廊引导原版分段寻路：离线原型结果

本轮原型验证已完成。**宏观走廊提供阶段目标、原版地面 Navigation 计算局部路径的简化方向，在最新城市基础图的四个方向上成立。建议先以每段最多跨两个宏观连接作为对接起点。** 跨四个连接也全部成功，但总时间没有稳定优于跨两个连接。

这是诊断参考，不是游戏内实体执行认证或正式生产验收。只修改新工作区的临时原型和文档，没有修改生产、旧工作区或测试源集，也没有 Git 操作、委派或启动游戏世界。

## 输入、路线与“分段”的含义

输入为北京时间 **2026-10-12 00:13** 导出的最新基础图：半径270格，19765个 READY 区段，缺失与失败为0，捕获期间稳定且完整。其中5837个区段含地面组件。原始导出、四个事实区域文件及四个世界方块区域文件只读复制到原型目录；副本身份在 `input-identities.json`。

| --- | --- | --- |
| 楼梯正向 | (-23,100,-198) | (-37,100,-195) |
| 楼梯反向 | (-37,100,-195) | (-23,100,-198) |
| 城市正向 | (-23,100,-198) | (83,94,-264) |
| 城市反向 | (83,94,-264) | (-23,100,-198) |

“连接”指宏观走廊中相邻地面组件之间的一个连接，可能位于区段内部或跨区段边界。**跨两个连接不是两格，也不是保证两个区块。** 楼梯走廊有57个连接，城市走廊有65个连接。本次比较整条原版搜索，以及每段最多跨一个、两个、四个连接：

- 阶段目标由实际边界通口和组件格产生，不用组件代表点替代通口。
- 每次最多给原版搜索8个候选目标，按当前位置距离加少量终点距离排序；本次没有根据测量结果调整排序权重。
- 原版计算成功后，仅把路径末端作为下一段的起点；没有实际移动实体。
- 三个指令端点坐标都位于完整方块内。原版坐标入口会把目标调整到地面上；原始请求坐标、原版目标和实际末端分别保存。
- 中间阶段要求准确到达所选目标格；最终阶段采用原版 `moveTo` 的一格曼哈顿到达容差。不是要求实体中心与原始整数坐标重合。

最新导出与事实 Store 逐内容核对，并核对80488个 Halo 引用。用于原版读取的4032个区段中，4031个在图捕获范围内，其存档版本逐一匹配；另一个在捕获范围外。未知范围返回障碍并计数。所有成功分段链的未知读取为0。

## 实际入口与计时边界

宏观部分复用当前实际 `MacroSearch`、基础图连接和正向走廊恢复；离线图适配器使用反向索引及零启发式。它没有经过完整生产宏观调度入口，因此不重新认证宏观服务。

详细部分调用实际 `GroundPathNavigation → PathFinder → WalkNodeEvaluator`。只替换只读区域数据源，方块状态、碰撞形状、原版标签和能力注册来自实际 Minecraft/Forge 1.20.1 依赖。没有复制一份寻路算法冒充原版。测试体型约0.6×1.95，禁止流体、禁止开门，搜索距离512格、固定节点限额16384。

单次计时由 `NativeReplay.find` 开始，在原版请求返回且评估器清理后结束：

| 计入搜索时间 | 在搜索计时外 |
| --- | --- |
| 最终坐标目标的原版调整、区域索引创建、评估器准备、搜索、路径恢复及清理 | JVM启动、注册与方块缓存初始化、读盘、宏观图恢复与搜索、通口枚举、候选排序、站立姿态回放、断言、统计、输出 |

累计搜索时间是该路线各次原版调用的墙钟时间之和；最大单段是其中最慢一次调用。**它不是基础图构建时间、整个区域构图时间、实体走完全程的时间，也不是完整模组请求总时间。** 原版区域的区块索引创建仍在计时内，但真实服务器区块访问与调度未模拟。

展开计数与未知读取探针在调用内，没有估计扣除探针、GC或调度时间；因此这些数据用于相同离线环境的诊断比较，不称无探针生产净性能。

## 建议的下一步与保留边界

保留简化方向，不恢复自研完整详细后端或全面沿途版本校验。对接起点是**宏观走廊→最多跨两连接的阶段目标→原版局部路径→原版执行，实际到达后再生成下一段**。跨四连接可以作为减少调用和路径绕行的候选，当前没有稳定的总体速度优势。

本次8候选排序、512格搜索距离和16384节点限额属于原型配置，尚未批准为所有NPC的生产配置。本次基础图不启用开门；不把结果扩大为能开门的移动执行已通过。

下一步需要的是小范围真实实体接续验证，确认原版路径执行、段间切换与受阻终止能够工作。无需重建过去的大型测试包。生产接入仍待用户决定，本轮停止于原型报告。
