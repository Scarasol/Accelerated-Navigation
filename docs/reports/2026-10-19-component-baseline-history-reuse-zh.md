# C 与原基线：历史证据复用

日期：2026-10-19。

按用户“历史数据优先复用，不需要直接三方对照”的指示，本轮只读取已有源码、
封存和测量数据，完成离线复核。新增性能测量、Java JVM 和 Java 实现均为0。
本报告补充此前 C 的验证记录，未改写旧性能门或旧数据。

## 结论

1. 历史 B/R2 的热 API 数据、本轮两组 C/R2 的冷查询数据均可直接复用，
   分别保留原配对、负载和计量窗口，不要求先重跑 B/R2/C。
2. 源码核对确认 B 与 R2 的 `buildGroundEdges`、`boundaryLinks` 两个方法相同。
   C 跳过的无效循环在原基线 B 中也存在，支持保留 C 的构图减量价值。
3. C/R2 的12组对照中，查询均值、中位数、P95、完整耗时均值、
   查询分配和完整分配均下降。原始完整 CPU 为9组较低、1组较高、2组受零读数影响。
   这不是稳定 CPU 收益证明，首轮 mixed 的 +2.94% 仍保留。
4. 现有材料尚不能给出整次冷查询的 C/B 实测百分比。
   B/R2 热 API 和 C/R2 冷查询覆盖不同工作，不能把两者比例连乘来估算 C/B。
   当前以这些已有证据保留 C，不启动新三方矩阵。

## 身份与源码

这里的 B 是 `.tmp/runtime-maintenance-validation-20261018-v1/B/main`，
即引入连续空气段优化之前冻结的加速版本，不是原生 bypass N。
R2 是同目录下的 `R2/main`；C 是
`.tmp/component-build-shortcuts-20261019-v1/C/main`。

离线分析校验了被读取文件在既有封存中的身份，并复核：

- B 与 R2 的 `buildGroundEdges` 完整方法一致。
- B 与 R2 的 `boundaryLinks` 完整方法一致；整个 SuperClusterTopology 源码也一致。
- C 的 TopologyWorkerRuntime 与 R2 源码一致。
- C 的两个构图方法包含此前验证的早返改动，未使用 C2。

因而，对相同的零/单组件 Base、含空端点 Boundary 输入，
B 与 R2 都有可被 C 省掉的原循环。既有 R2 诊断六次均记录：
98,304次 Base 格位遍历、96,768次移动候选检查、120,960次空端点 Boundary
候选迭代可省。这些数量仍标为 R2 诊断实测；对 B 的适用性是同输入下的
源码推断，不冒充本轮运行过 B，也不折算成 B 的 CPU 百分比。
