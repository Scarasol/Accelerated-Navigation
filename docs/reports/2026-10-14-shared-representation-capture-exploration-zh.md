# 共享图表示与捕获开销探索

日期：2026-10-14。用户授权研究运行表示与捕获开销，可查阅互联网、通过 WSL 无头 DeepSeek 达成方案共识，达成共识后直接验证。动态预算由另一对话负责。

## 本轮结论

**分块表示的空间收益和避免重复捕获的机制已取得原型证据，限定研究审核通过；稳定的生产性能收益仍未认证。** DeepSeek 独立审核 ACCEPT_WITH_GATES，本轮必须修改项为无；不能把这个结论扩大为生产接入或尾延迟通过。

最终实现与并发控制为 `.tmp/shared-runtime-optimization-20261014/candidate-v5/`；最终有限实体回归为 `native-v2/`；相同冻结编译产物的性能复跑为 `performance-v1/`。源码在临时目录隔离修改，生产共享实现、动态预算、用户世界和共享构建输出未修改，未提交或推送。

后续建议保留有效 Slot 复用的研究分支，并保留按块共享的表示候选。不能依据窗口中位数直接接生产：尾延迟、单位时间到达负载、组件/上层图相容及真实 tick 成本仍需独立资格。

## 实现与外部方案

参考 Boost 官方 CSR 图说明的偏移表/连续出边数组、Clojure 官方不可变数据结构的结构共享，以及 OpenJDK JMH 官方 Forking 示例对 JVM 编译画像相互影响的说明。本轮使用这些思路，未引入 Boost/Clojure/JMH 依赖，也不是 JMH 微基准。

来源定位见证据根 `plan.md`。Boost 最新文档路径已迁移，旧短路径 404；已对齐实际可读取的 `doc/html/graph/graph_classes/compressed_sparse_row.html`。外部资料只启发数据组织与测量，不作为项目正确性证据。

`RowStorage` 将 section 分为 64 个块，每块覆盖 64 个源格：`char[65]` 偏移表、`char[]` 目标格、`long[]` 有向能力掩码。目标域为 0..4095，保留全部掩码；不是落盘压缩。升级只重建触及的块，未触块保持对象身份。目标精确行与基础行的目标和掩码完全相同时，保存基础引用位；不是仅凭能力包含推断相等。各目标条件的合法性仍独立保存。

`evaluated` 位图区分未知与已求值空行。空行可以替换基础非空行，门禁连接不会因并集而重新出现。所有数组发布后保持不可变；每个运行任务继续独占局部计算 scratch。当前 legal 数组和 evaluated 位图仍整层复制，未宣称所有发布成本都已分块化。

捕获快路径在实际 Runtime 锁内检查已有 Slot 的输入 lease；有效时直接进入已有 flight/worker 流程，不再取得立即释放的额外 `BaseGraphView`。无 Slot 或失效仍走旧捕获入口。发布与锁外交付保留输入/halo/loadIdentity、请求当前性、TTL 和关闭检查。`maxCaptures` 只约束实际捕获，`maxSlots` 只限制新建槽位；有效复用不增加槽位，仍受 flight 准入约束。未实现冷捕获按 section 去重。

Software `retained` 计费为当前表示的估计载荷，包含块表、偏移/目标/掩码和共享标志；基础引用不重复计算基础。它不是整个 JVM 的硬内存上限。SizeAgent 另行独立测量实际可达图对象，不能用估计倒推仪器化结果。

初版 candidate-v4 每条边反复寻找块、解码基础引用，水域和混合查询较慢；candidate-v5 把块和区间解析移到每个被展开节点一次。只比较各版本内同协议消融，不能把跨 JVM 的耗时变化全部归因于这项修改。

## 正确性与实际实体

四个实际启动 JVM 分别验证对象/分块 × 重复捕获/Slot 复用。宿主 PID 与 Java 自报 PID 一致；各 30 个 Runtime 场景通过。分块快路径/对象快路径分别 1,255 条驱动检查，对象捕获/分块捕获分别 1,254 条。检查数不是游戏成功率，不把重复变体当新增场景。

每个控制 JVM 另执行相同的直接分块存储测试：172,717 项内部比较，随机合法目标及 30 位掩码、20 次分散发布、旧版本保持、全域空行替换；605 次实际未变块共享、285 个基础行引用。四份最终 4096 格出边记录由独立 Node 读取器比较目标与掩码。该直接存储控制在对象模式也固定运行分块实现，不能称对象层有分块共享。

Runtime 控制保留同键 128 订阅合并与 leader 取消、两个真实 worker 的同层/异层重叠发布、8 调用线程/512 请求、全部取消、Error 结算、订阅函数异常、输入及 halo 变化、卸载重载、准入、TTL、关闭和引用归零。新增有效 Slot 在捕获/新槽位额度为零时继续使用，以及结算后交付前输入变化拒绝与新输入真正封闭的对照。冷捕获上限控制仍单独执行。台阶/跨沟/落差的三种图分别比较全部 30 个 MovementKey 与紧凑图，并独立重算交付边。

candidate-v1 在卸载重载控制中失败：原驱动仅等待 lease 失效就立即重载，未等待卸载事件批处理结束。新驱动明确等待 pending/active 事件为空后重载，保留旧结果拒绝和新 loadIdentity 正控制；这是修订测试时序，不修改生产事件实现、不宣称解决任意事件排列。candidate-v3 的驱动局部变量重名导致编译失败，原件保留；candidate-v2 为早期冒烟，不替代最终资格。

最终 native-v2 五个场景预期通过：四项实体实际到达、一项铁门正确 UNAVAILABLE。320 个双体型候选全部结算；17 次实际原版详细搜索，未登记入口 0，原 accuracy/range/visited multiplier/region offset 保持。413 条驱动检查、696 项独立读取器核对通过；后一计数包含驱动核对与 class 身份，不能相加当独立样本。48 个原发行导航、调度和 Mixin 类保持，六份核心源码与 candidate-v5 相同；服务器完整停止、退出 0，Runtime 引用及共享状态归零。

范围仍为 section 内 GROUND、width<=1、heightCells>=2 候选接口；没有组件/Boundary/Super 重构、全部消费者、物理水流、生产接入或持久化资格。

## 性能协议与干扰记录

五模式：现行紧凑 Runtime 宏观接口，以及统一研究实现内对象/分块 × 捕获/复用四种候选接口。对象基线多了薄 RowStorage 访问器，是本轮消融基线，不是逐字节 runtime-v11 可执行程序。紧凑接口返回走廊，共享接口还返回锚点候选，不能当作纯算法同接口对照。

每场景每模式固定：冷首请求 1，预热 20×64，正式热态 12×64，输入变化首请求 1，变化后 64。三场景在三个独立 JVM 中分别轮转先后，五模式逐轮交错。共 1,575 窗口、95,130 请求终态；正式每格 36 窗口。独立读取器 268,909 项核对通过，包含四变体驱动、原始终态、导出出边、源码/class、PID、重复运行绑定和环境记录。

candidate-v5 初次性能的三个启动记录均观察到另一对话服务器 Java，原样保留，不用于声称无干扰收益。performance-v1 使用同一 candidate-v5 编译产物重新启动三进程，不重新制造四份并发资格。启动前记录为空，运行期间 16 次周期抽查未观察到其他 Java 重叠；这不是证明没有其他进程或操作系统干扰。既有首轮数据没有删除或改成失败。

保留 LogCompilation XML 和逐窗口 compilationDeltaMs。正式窗口仍有后台编译，模式也共享 JVM 编译画像，不能宣称完成稳定 JIT 或每模式独立 fork 的微基准认证。XML 内 uncommon_trap 记录含编译描述，不能把其总数当实际去优化次数。冷/变化首请求每模式只有三个样本，不给稳定首次延迟结论。

## 耗时与消融结果

64 请求热态完整窗口中位数，单位 ms。每格 36 窗口；窗口包含提交和全部结算。queryWork 单独记录，不能用 latency-work 推导纯排队时间。

| 场景 | 对象+捕获 | 分块+捕获 | 对象+复用 | 分块+复用 | 紧凑参考接口 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 平地 | 0.588 | 0.688 | 0.472 | 0.540 | 1.347 |
| 水域升级后 | 0.577 | 0.625 | 0.573 | 0.513 | 1.354 |
| 五条件混合 | 1.058 | 0.760 | 0.784 | 0.782 | 1.596 |

逐 JVM、逐轮匹配的 36 对窗口，变化比例先对每对计算再取中位数，**不是上表两个中位数的比例**：

| 改动 | 平地 | 水域 | 混合 |
| --- | ---: | ---: | ---: |
| 只去重复捕获，对象表示 | -18.3% | -12.1% | -12.7% |
| 只去重复捕获，分块表示 | -24.7% | -10.2% | +1.0% |
| 只分块，保留捕获 | +8.5% | +9.2% | -12.9% |
| 只分块，已有复用 | +17.2% | +1.0% | -13.1% |
| 两项一起，相对对象+捕获 | -13.9% | -7.0% | -31.2% |

负值为更快。两项合并窗口分别 22/36、24/36、27/36 对更快，不是每个请求或每个窗口必然更快。分块主要取得空间收益，平地仍有遍历/组织代价；捕获收益也没有跨表示/场景全部一致。

**尾延迟反例不能隐藏。** 单请求 P95 对象+捕获/分块+复用，平地 0.223/0.538ms、水域 0.221/0.328ms、混合 0.864/0.785ms。对象+复用混合 P95 达 1.848ms。较快提交改变固定 64 请求的入队节奏，可能改变排队分布，但本轮没有提交/入队事件轨迹证明该因果；JIT 与运行噪声也保持。不将吞吐改善等同单请求尾延迟优化。
