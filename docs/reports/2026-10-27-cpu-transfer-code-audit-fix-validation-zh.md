## 3. 集中修复

### 组件标记

旧行程实现先对每段写满临时逐格标签，但后续合并只读取行程起止位和parent，
不读取这些临时标签；保存根及最终编号时又覆盖它们。
删除这遍无消费者的写入，以及第一遍不再需要的终点提取。

旧实现先对相邻两行的全部重叠格检查门，再合并行程。
改为先查两行程的根：已连通直接跳过；
未连通时仅检查该行程对的重叠位置，找到一个可通行连接即停止。
每个行程内部已经由精确X方向门规则保证连通，
因此同一行程对一个可通行交叉足够建立连通，不要求逐个确认所有交叉。
最小根合并、稳定编号和元数据不变；体积Y连接仍不新增门检查。
删除新行程算法已不再调用的旧BFS enqueue方法。

### 共享邻接

旧直接输出为天然有序而交换了循环：
每个候选重新用范围判断和取模重建方向与距离，边界不再像原循环一样提前break，
合法位/prism缓存的访问顺序也改变。

修复保持生产原方向→距离→dy的评估次序和边界break。
唯一目标写入72个固定槽，由两个long占用位图记录有效槽，
输出时只枚举置位，仍按目标格升序。
不扫描旧缓冲脏项，也不对全部候选重新排序或建立TreeMap。
返回数组独立分配，无结果时复用原不可变EMPTY。
每个LocalKernel缓冲载荷仍864字节。

### 能力与成本

原通用能力入口为任意三元组保留范围判断和回退，
而构图/共享行的移动循环已限定水平1—3、dy为-4—1。
热调用改用这18种移动对应的能力表，避免重新拆分、通用检查和零mask判断；
通用supportingCapabilities恢复原循环，边界连接和原超范围行为不变。
新表初始化调用原算法，载荷144字节，不增加长期请求缓存。

成本恢复原Math.sqrt，放弃成本查表。这里没有找到成本表数值错误或越界；
不能把撤除成本表称为已经修复了391%的根因。
上述修改集中于一份新候选，未逐项消融，不给每项单独分配节省比例。
