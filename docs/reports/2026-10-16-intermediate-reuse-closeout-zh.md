# packed 行复用接入前收尾

日期：2026-10-16。工作目录 `.tmp/intermediate-reuse-closeout-20261016/`，来自上一轮已封存源码的独立复制。**本轮已完成并与 DeepSeek 达成负结果共识：当前 weak packed 暂不接入生产，复杂场景 GC 门未通过，首 Path 未显示收益。** 生产源码未改，不提交推送。

## 本轮修复

上一轮 strong packed 使用 `IdentityHashMap<PackedFacts,Rows>` 和源对象 FIFO，会因缓存强引用延长完整几何的生命。合法上限源使用 4096 项 palette，其中 4093 个独特非保留 shape，每 shape 64 boxes。Instrumentation 实测单源 3,334,032B，64 源缓存闭包 213,506,976B／worker；现有两个 worker 约 407.23MiB。原版本超过测前登记的 8MiB／worker 门，不具备直接接入资格。

本轮 weak packed 只修改缓存对源的持有方式：`WeakHashMap<PackedFacts,Rows>`，FIFO 存 `WeakReference<PackedFacts>`。`PackedFacts` 为 final，equals/hashCode 继承 Object，弱键因此仍按引用区分。Rows 只包含两个 primitive 数组，不反向引用源。构图期间 BuildInput 保持源强可达；不再使用的源可由 GC 清理，其行以后按需重建。每次插入同步限制 FIFO≤64，map 活条目不多于 FIFO；clear 清空两个容器。转置、精确检查、门回退与其他构图语义不变。

复杂源强可达缓存实测 142,640B／worker，两个 worker 285,280B；外部引用释放后 64 个源全部回收，clear 后 1,328B。该数字是缓存增加的强可达内存，不表示运行时其他正常所有者也释放了源。弱条目及其 Rows 在下一次 map 清理前可能暂留，仍受 64 条界限制。不同容器容量下完整正确性检查的缓存为 142,656B、clear 后 2,016B，单列保留。

## 正确性与实际工作

新版本通过 58 fixtures×21 Geometry，另加同体型64、混合256和复杂256次真实捕获构建及身份/halo代次控制，共 1,804 对完整图、20,928 条断言。完整快照、legal/prism/volume/ground/haloUsed 一致；新增弱源回收、FIFO 身份、同内容不同源分离、Object equality 假设和 clear 检查通过。测试在 `.tmp`。

复杂场景在原平地通路周边加入 Minecraft slab、stair、fence、wall、trapdoor、door，并在通路附近放置 fence；尺寸 .6×1.8/.9×1.4/.8×2.4/1×2.8。独立诊断实际发生 256 次构建、13 源、264 次精确碰撞检查、72 次含门原行回退、55,040 次行命中。16 实体自然到达，无 whole fallback，清理通过。JFR 256 个消费与阶段工作关联一致，DataLoss=0。只代表这个可复现受控场景，不代表用户历史 spark 场景的覆盖率。

捕获器会强持捕获源，JMH 也固定持有输入集合。因此这些命中计数用于证明机制和分支覆盖，不能当作关闭捕获后的实际留存期或生产命中率。独立服务器性能对照关闭源捕获和逐格计数，弱键的实际 GC 行为由该对照及独立回收检查验证。

## 探针与窗口

用户允许双方相同探针干扰。冷图反射检查移至 ready+29秒，真实派发在另一个 tick、ready+30秒以后，检查工作量和耗时另记。诊断运行冷检查遍历 203,136 次，耗时 82.48ms，tick581；派发 tick601。该大开销没有被改名为构图成本，也不进入派发至自然终态的固定请求窗口。

保留相同的完整 tick 包装器与每 tick 16 实体观察方法。观察器共用源码与设置，每侧记录调用量、实体访问量、累计耗时；运行时长不同会改变总调用次数。首 Path 是 tick 末首次观察 nodes，最多受到 tick 采样量化影响。完整 tick 含请求派发、移动和观察器；没有通过扣探针平均数合成“净 tick”。

tick 计时包围原 `tickServer` 及预算 envelope，包括上述观察器；记录 tick 的尾部 Map 分配在计时结束点之后，两侧一致。不能将该口径当作包含全部记录开销的无探针生产绝对耗时。

JMH 与服务器净对照关闭逐格计数和深度 JFR；服务器双方同开 GC 日志，按 uptime 对齐请求窗口与暂停区间。GC 日志 1ms 时间戳分辨率单列，未见暂停不能推出长期 GC 无成本。

## 收尾判断

当前版本修复了复杂源强持留问题，图正确性和局部构建收益得到保留；但未同时完成全部接入门，也未证明目标冷首次请求更快。**保留 weak packed 作为有局部收益的研究原型，本轮结束，暂不移植或默认启用。** 不为取得正结果延长矩阵或重设门，不追加生产热点优化。

这不是证明行复用方向无效。后续若重启，需要先提出聚焦实际目标收益或 GC 负担的新方案，不能继续沿用“已具备生产接入条件”的说法。

## 审核与证据

DeepSeek 使用 WSL 原生 dsh headless，provider=deepseek、model=deepseek-v4.1-flash，各包无上下文、自足，900秒本地期限。首方法包3676B审查扩展到文件检查，在本地901秒结束且无最终答复，记录为超时，不是共识。拆为禁止继续读文件的代码包2649B、方法包2614B后，35秒 ACCEPT_WITH_GATES、63秒 READY_TO_VALIDATE，本轮必须修改项均无。

方法答复将 GC 窗口误读为包含 ready/冷检查；实际只统计提交至最后终态，6440B结果包明确纠正，并送入上述失败结果及暂不接入建议。15.9秒返回 REQUEST_CHANGES，明确拒绝移植；其要求定位/复测 GC、验证实际目标收益，作为未来接入前仍未完成的条件保留。

随后3016B自足负结果包纠正“1804断言”为“1804对图、20928断言”，并确认 GC 口径已正式记入报告。14.2秒返回 **ACCEPT_WITH_GATES（仅报告）**：本轮报告必须修改项无，同意拒绝接入的负结果封存，**可开始生产移植：否；生产发布已批准：否**。这不撤销移植拒绝，不把 GC 条件销项为通过。4个成功审核包、1个本地超时包全部保留，最大6440B，实际 provider/model 与配置哈希前后一致。

`results-v1.json` 保留16 JVM与全部门；`complex-work-gate-v1.json`、`checks-packed-v2.json`、`memory-strong-v1.json`、`memory-weak-v1.json`、每次原始 GC/JFR/日志、JMH rawData 均保留。首次强键内存测试编译类及从本轮最初补丁恢复的对应源码另存 `memory-strong-classes/`、`memory-strong-source/`；没有将后加入外部持源列表的弱键测试壳冒充首次强键测量源码。
