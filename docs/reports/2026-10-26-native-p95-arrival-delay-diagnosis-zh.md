# 相对原生P95到达延后的定位

日期：2026-10-26。承接用户“最大延后暂按换线算，重点寻找P95的411.07ms原因”。
使用[累计距离修复后的正式候选](2026-10-25-native-walked-distance-fix-isolated-validation-zh.md)
与原生历史数据，不将本轮只读诊断计时作为新的性能样本。

## 结论

P95及以上41条正式请求，每条首动后的耗时增量均大于首动前增量；
这些请求各自的候选PathFinder累计wall最多0.436ms，搜索wall增量最多0.023ms。
**时延位置已收敛到首次移动之后的执行、接续和接近目标阶段，
不能用这些请求自身的详细搜索计算增加来解释数百毫秒延后。**
这没有排除共享工作、运行节奏或接续等待的间接作用。

补充的原生/候选只读诊断中，门口、斜线、转角三条请求均观察到：
候选先走到跨界交接点，再转向最终目标；返回的节点路径和观测移动距离更长，
首次移动至到达均多7个tick，而三处第一段完成至第二段发布均在同tick。
这些证据**与临时交接目标带来的路径质量损失一致**，
因此把最后一次跨界搜索的临时目标约束列为下一项待验证假设，
这是基于代码和诊断的研究取舍，不是上尾统计唯一推出的优化结论。
没有将端口约束、碰撞、终点接近方式各自的因果份额独立隔离，
也没有恢复原正式路径，因此不能断言全部历史P95或139条负项均由同一机制造成。

秒级最大值暂按换线处理是本轮工程假设，不升级为已证事实；
全部802条共同到达请求继续进入正式统计，没有因该假设删除负项。
中位+116.6882ms满足用户当前中位目标，P95+411.0743ms仍未压至200ms。
本轮没有修改生产或候选业务，也没有开始新的优化候选或取得生产批准。

## P95对应请求

256实体/8格，门口tile6 slot4，起点(93,81,-126)，目标(93,81,-134)。

| 正式指标 | 原生 | 本轮候选 | 差值 |
| --- | ---: | ---: | ---: |
| 首Path，自身提交起，ms | 0.2092 | 16.6120 | +16.4028 |
| 首次移动，自身提交起，ms | 25.0379 | 49.4539 | +24.4160 |
| 首次移动至到达，ms | 2573.9969 | 2960.6552 | +386.6583 |
| 实际到达，自身提交起，ms | 2599.0348 | 3010.1091 | +411.0743 |
| 提交至到达的tick序号差 | 52 | 60 | +8 |
| 首动至到达的tick序号差 | 52 | 59 | +7 |
| PathFinder累计wall，ms | 0.2009 | 0.0587 | -0.1422 |
| 搜索次数 | 1 | 2 | +1 |
| partial / 恢复 | 0 / 0 | 0 / 0 | 0 / 0 |

该请求的点对点恒等式为24.4160+386.6583=411.0743ms，
首动后增量约占94.1%，不是独立分位数相加。
firstPath并不等于PathFinder计时，不能把0.0587ms与16.6120ms混同或抵消。

正式日志首次非最终搜索4节点、末次搜索10节点，两条结果日志墙钟相隔733ms。
以首Path为近似锚点映射，首次结果至末次搜索15tick、末次搜索至到达45tick，
末次tick在锚点偏移±2ms下保持。
733ms与第一段执行重叠，不是搜索CPU、独占队列延迟，也不是额外等待窗口。

从保存的完整tick起点和实体事件时间计算，411.0743ms可记账为：
名义8*50=400ms，加事件在tick内的相位差10.3204ms，
再加实测tick起点跨度相对名义50ms节奏的差0.7539ms。
这里400ms仅为tick序号差的名义换算，不是实测的8tick算法工作量；
相位和节奏也不作为独立算法成本。

## 代码与历史联系

冻结候选仍按“到实际起点平方距离+0.05*到最终目标平方距离”排序端口，
最多八点交给原生多目标详细寻路，中间段accuracy=0。
多目标搜索不承诺按端口排序第一名执行，也没有计算到最终目标的完整剩余路线代价。
到达最后一个宏观组件后，再单独对最终目标执行accuracy=1的搜索。
局部目标与整条路线质量存在差别，本轮三例与该结构性缺口一致。

三例最终接续不再准备worker窗口；observe→settle→nextSegment→findSegment的就绪任务
由无预算调度器继续处理，源码没有预算耗尽或固定时间截止门。
stable并非每段完成后重新等3tick，三例完成时已满足条件。
这些事实不能替代其它请求的实际等待证据。

生产历史及修复前候选中，这三例已有相同的window/search摘要：
门口和转角均4+10节点，斜线均6+4，range及连接跨度也相同。
本轮相对生产的三条到达分别早98.7173/93.1336/98.7596ms；
相对修复前候选分别早1.6252/1.4696/1.5753ms。
因此没有证据把它们对原生的完整增量归为本轮累计距离修复新引入的回退。
摘要相同仍不等于历史完整路径相同。

下一研究优先评估：剩余宏观走廊已抵达最终组件时，
让最后一次跨界搜索直接面向最终目标，是否能消除强制临时端口及额外末段搜索。
这是待研究方向，不是已经实现或验证的优化方案；
不能直接扩大所有搜索，也不能未经核对改变range、访问上限、碰撞或有效性语义。
本轮不启动正式候选验证，不宣称P95已达标。
