## 当前热点与可以准确说明的收益

源与上轮诊断src冻结25项没有漂移。证据来自[联合性能诊断](2026-10-11-idea-spark-hotspots-zh.md)及原始采样，不新开世界。两个会话独立：IDEA约295秒墙钟采样覆盖多个线程；spark219.449秒、4ms Java线程栈采样仅覆盖服务器线程。

| 已有证据 | 当前值与口径 | 方案对应 |
| --- | --- | --- |
| 主线程事实采集 | spark累计采样权重13.968秒；其中整格判断子路径6.672秒，约47.8% | 标准形状快判减少Guava访问及访问队列维护 |
| 实际形状获取 | 同一spark中getCollisionShape子路径1.020秒 | 仍保留，不能承诺这部分消失 |
| 几何调色板生成 | spark累计权重1.880秒，与判整格是采集的不同子路径，均已含在13.968秒中 | 常见ID避免逐格HashMap查找 |
| 临时对象 | IDEA整会话估计CollisionSample3.64GiB、队列Node3.25GiB、Cell2.01GiB | 共享不可变对象、跳过不必要Guava调用；不是单请求或存活内存 |
| 后台写入 | IDEA模组活动样本54.0%，存储线程写入占91.3%；写入链67.6%叶样本在Deflater | 批量编码减少小写调用，完整编码+压缩收益仍未知 |
| 开发环境 | spark调试器栈捕获约16.96秒累计采样权重 | 后续正常Run对照，不直接从日志扣掉该值 |

**现在能证明的是减少的动作，而非总体加速百分比：**标准整格可绕过一次Guava访问；常见Cell不再逐次分配；全为常见形状的4096格不再做4096次Map查找；索引写调用4096次降为1次，原8192字节没有减少。实际形状比例、JIT逃逸分析、GC、压缩及排队会改变收益，不能将47.8%/54.0%当作可交付提速，也不把采样权重换算成单次构图耗时。

编码前已有BufferedOutputStream。Java17.0.18的writeShort是一次两字节数组写，不是两次write(int)；新候选减少方法调用，绝不以再加缓冲解释收益。批量输入可能影响Deflater执行与压缩字节数，保持同算法/级别仍须测完整路径和压缩大小，不能承诺压缩耗时完全不受影响。

## 事实采集职责的六个契约块

**生产目的与边界。** 仍由TopologyService在加载/恢复和变化时采集原生碰撞事实，由SectionGeometry构成区段几何。优化只降低这项现有工作的重复开销；不新增模块、碰撞模型或搜索接口。下游PackedFacts、派生图、边界几何和导出继续消费相同值。

**入口、接口与身份。** Forge服务器tick/区块加载 → runOneRecovery或finishTick → scanSection → collisionSample；变化观察sampleColumnFacts → collisionGeometryFingerprint也消费collisionSample。getter/BlockPos、当前BlockState、碰撞上下文、loadIdentity/section version与全部发布身份保持。只在已经得到真实shape后检查标准单例，LiquidBlock仍先走原分支。

**所有权、并发与资源。** 三个Cell、六个Sample由类初始化唯一创建，只引用不可变Shape；不保存世界、BlockState或位置。Shape坐标仍构造时复制，无写出口；Cell/Sample是不可变record，可安全共享。初始化顺序保证Shape→Cell→Sample，flags常量先可用。每次扫描的数组、部分几何和Map仍局部拥有、扫描后释放；没有新增可变共享缓存、队列或引用。

**生命周期与算法。** 每格读取真实状态/流体/形状，选择原flags和geometry；扫描后按下方碰撞补GROUND_OPEN、生成原PackedFacts。空分支与液体分支不得因共享Cell而合并flags。标准单例是数学上的整个单位体积，快判不会因包围盒相同而误判有孔形状。其他满形状仍使用原判断。调色板前三项固定，部分shape按原首次出现/equals规则追加，所有输出数量与FNV指纹保持。原生读取异常仍被原扫描捕获、拒绝AVAILABLE并进入原恢复失败；取消/卸载/关闭及迟到版本由原Runtime/Service处理，新增常量不持有这些操作。

**依赖、替换和原子关系。** 依赖MC1.20.1 Shapes.block标准单例与当前Block.isShapeFullBlock fallback。替换三个common Cell工厂、fromFlags常见构造、三个采样分支、fromCells common查找；删除被替代构造/三Map预置，不新留平行选择器。粗collisionClassification有真实生产消费者，保留。采集内部小项能独立编译，不强制扩大成Runtime/Store联合原子改造。

**验证、规模、风险与批准。** 在现有轻量控制中验证标准full、非同对象full、相同bbox有孔形状、empty/liquid/含水、部分形状、木/铁门与动态变化；逐格flags、palette、门标记、指纹和输出字节与冻结旧拷贝一致。已有门/边界机制复用，补受影响的路径。规模为上表估算；残余风险是命中比例/EA/实际环境收益未知，由有限对照解决。当前用户仅批准研究与评审，**实施未批准**。

## 后台编码职责的六个契约块

**生产目的与边界。** 仍将SectionRecord编码到原RegionFile中。仅降低4096个索引的小调用成本；不更换压缩或存储格式，不减少必要几何，也不调整写入何时发生。

**入口、接口与身份。** Service的FactDecision → Store.continueWrite → scheduleWriteLocked → IO worker出队 → writeChunk → writeChunkRecord → SectionGeometry.write。write私有包内签名改为DataOutput+scratch；生产唯一调用和CoreContracts/DoorContracts两个当前调用共同适配。dimension/chunk/section/version、batch和回执身份保持。

**所有权、并发与资源。** 每Store一个`CELL_COUNT*Short.BYTES`数组，当前8KiB，由唯一IO worker借用；不放进每图缓存、ThreadLocal或全局池。入口一次检查长度至少8192，循环只填4096个short、只写8192字节，允许较长数组但不写旧尾部。DataOutputStream/BufferedOutputStream复制或下沉数据；Deflater写循环到needsInput才返回，写/异常收尾前不得覆盖scratch。测试给独立缓冲，禁止与并发Store共享。

**生命周期与算法。** 原magic/schema6/facts7/sectionCount/sectionY/version/packed bytes/palette header及坐标不变；索引按原顺序高字节在前。每次重新覆盖全部8192有效字节，成功返回后才能复用。格式读者/尺寸校验和通行消费者不改。正常完成、IO异常、取消、迟到、卸载、关闭、flush及完成回调由原Store/Runtime负责；不引入新异步提交/完成状态。原IO失败处理继续成立；不要求错误发生于相同第几次write调用，负控制按写出字节边界注入，避免新调用次数使夹具误判。

**依赖、替换和原子关系。** 依赖Java17.0.18大端DataOutput与同步Deflater输入消费、MC的RegionFile装饰顺序。替换旧4096次writeShort及其无消费者旧签名，不加兼容重载。signature/一个生产调用/两个当前测试调用必须同时编译，历史冻结原型不被修改或当成当前消费者。

**验证、规模、风险与批准。** 比较原未压缩字节、旧读者解码、混合门palette、同scratch连续两次/异常后复用、正常/失败回执与关闭。编码公式已对全部65536个无符号short值验证大端等价，仅是公式核对，不构造非法SectionGeometry或冒充真实IO资格。新增8KiB与10–20净行估算；全编码+压缩耗时和压缩大小须实测。收益不足/出现可复现耗时或大小退步就放弃，不能仅挑编码小阶段改善。**实施未批准**。
