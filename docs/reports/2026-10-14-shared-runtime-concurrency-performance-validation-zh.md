# 共享图与局部升级的 Runtime 并发及性能原型验证

日期：2026-10-14。授权：用户要求验证共享图与局部升级接入 Runtime 后的并发正确性，并检查性能是否优化。动态预算由另一对话负责，本轮未修改其实现、测试或方案。

## 当前结论

**限定并发控制与原型复审通过，性能没有证明稳定的生产优化。** 首审 REQUEST_CHANGES 的两项必须修正已完成，复审 ACCEPT_WITH_GATES 且必须修改项为无；不能据此上线共享表示、恢复持久化或宣称完整生产接入完成。

修订并发及成本证据为 `.tmp/shared-runtime-validation-20261014/runtime-v11/`；真实实体修订证据为 `native-v4/`。v10/v3 与首审原件保持，所有早期目录保留，编译、驱动失败没有改写为通过。

本轮使用实际 `TopologyWorkerRuntime` 的隔离源码副本：事实事件、输入 pin、版本 stamps、两个实际 worker、Runtime 锁和关闭入口都参与。没有改生产共享实现，没有使用独立线程池冒充 Runtime worker。基础几何为用户决定的 `(1.0F,2.0F,1,0,3,false,true)`；默认请求能力、真实实体体型与原版详细搜索参数仍分别保留。

接口只生成 **section 内候选锚点**。邻 section 作为 halo 当前性控制；没有发布新的组件身份、Boundary/Super 聚合或改造全部 Navigation/Goal/Brain/POI 消费者。已有紧凑 Base 输入捕获仍保留，因此共享版成本包含该紧凑基准与额外锚点行，不能只统计升级行而遗漏基础构图。

## 并发控制与修订

`runtime-v11`：1,003 条驱动检查全部成立，独立 Node 读取器 30,089 项核对通过。检查数是断言和证据核对数，不是游戏成功率，独立核对包含对驱动检查的逐项核验，不相加当作独立测试数。

控制包括：

- 同一完整查询 128 订阅者合并为一项工作，取消首个订阅者后其余 127 个仍成功；同几何不同端点目前不按行去重。
- 两个实际 Runtime worker 同时处理不同几何，以及同几何不同端点；重叠精确行一致，两个结果合并，不覆盖彼此，旧数组与旧版本保持。
- 8 个调用线程共 512 请求，全部结算；每项任务独占 LocalKernel/scratch。
- 中心版本、缺失 halo 加载、已加载 halo 版本、卸载/新 loadIdentity 重载时旧结果拒绝；新输入有成功或封闭负控制，避免恒拒绝假通过。
- 请求/能力代次、单订阅取消、全部取消、交付 TTL、零升级额度 UNKNOWN_LIMIT、查询及基础构图 AssertionError、订阅检查函数异常均结算。
- flight、slot、估计行载荷字节及 pending capture 分别有准入限制；资源拒绝、失败基础退役后可重新请求。
- 关闭与基础构图/查询发布交错时等待者结算，已交付候选从 beginStopping 起失效；worker 结束后共享 slots/flights/captures/载荷、Runtime 输入引用及构图需求清零。
- 完整目标紧凑图对照、每条交付边独立重算，以及台阶、水平跨沟和落差 MovementKey 掩码对照。

实际修正了锁内 future 回调、一个订阅者异常拖住其他订阅者、失败缓存引用保留、等待基础捕获未设单独上限、以及旧候选关闭后仍报告 current 的问题。executor 提交采用 Runtime 既有锁外提交/待提交计数机制；future 的用户回调及自定义订阅检查在锁外执行。

门视为空气仍重算普通支撑，铁门、真实门框及不开门条件的空行替换保留。补修了门上非空形状的固有支撑，以及 section 底部的 lower halo 支撑，不增加特殊落点规则。真实采集对照证明本轮常规木门转换一致。

**额外输入边界：** 当前 PackedFacts 不保留“空碰撞的流体格具有自身支撑，还是支撑由其下方木门添加”的原始分类来源。移除木门后若遇到这种歧义，研究版明确拒绝该基础输入并清理引用，不能冒充已支持所有流体/门组合；这与用户暂不处理水流执行特性的决定是两个问题。GROUND、宽度不超过 1、heightCells 至少 2 是本轮接口边界，小动物、大体型及其他通道未认证。

TTL 修订后在**锁外交付回调内重新读取 System.nanoTime()**，在订阅当前性检查后判定是否过期；不再使用 flight 结算时保存的时间。新增控制卡住结算后的交付：实测 settleObserved < expires <= released，过期订阅者拒绝、同批未过期订阅者成功、expired 仅计一次。这个反例能使旧实现失败。它仍不是独立定时器或所有事实等待的主动超时认证。

byte cap 是当前行载荷估计，不是整个 JVM 的硬内存上限；工作中的 scratch、旧快照、事实和其他 Runtime 缓存另计。全部取消会撤销等待者和可取消的排队工作，已运行的有限任务允许返回，但不发布无人订阅的升级。

## 性能协议与结果

最终副本使用三个独立 JVM，各模式交替顺序，同一冻结事实、目标、MovementKey、升级额度。每个场景每模式：冷首请求 1 次，预热 2×64，正式热态 5×64，输入变化后首请求 1 次，再变化后批量 64。三个场景、三个模式、三个 JVM 共 **270 个完整窗口、13,878 个请求终态**，没有删除慢样本或负向结果。

三个模式为当前生产紧凑 Runtime `requestMacroQuery`、Runtime 上缓存完整目标锚点行、Runtime 上共享基础和按需目标行。紧凑接口返回宏观走廊，两个锚点接口额外返回锚点候选；用途相近但接口工作不完全相同。完整行基线采用每体型捕获/缓存，共享研究接口还逐请求捕获基准。这项差异正是当前接入开销之一，不能把它隐藏，也不能把纯锚点基线的结果叫生产收益。

64 请求热态完整窗口的中位数（每格 15 窗口，单位 ms）：

| 场景 | 当前紧凑生产接口 | 完整目标锚点行 | 共享及局部升级 |
| --- | ---: | ---: | ---: |
| 平地复用 | 6.513 | 0.766 | 3.534 |
| 水域升级后复用 | 2.587 | 0.422 | 3.062 |
| 五种目标几何/流体条件混合 | 3.131 | 0.432 | 3.120 |

v11 平地共享窗口中位数约快 46%，单请求 P95 为 3.299ms，紧凑版为 5.321ms；水域窗口约慢 18%，混合基本持平。v10 原始平地共享 P95 反而比紧凑版更差，混合约慢 19%，原件保留。这些跨轮波动不能归因于仅修 TTL 的代码变化，也不能只挑较快一轮作为稳定收益。完整目标行热态更快，说明“少建行”不能自动等同“重复查询更快”。本轮未取得一致优于当前生产接口的证据。

确实修掉一项重复成本：原来已有精确行的负向查询仍创建完整 scratch；现在只有缺行/缺合法性时才创建。混合场景 worker 临时分配从 v5 的每 64 请求约 39.14MB，下降到 v11 约 3.20MB。跨版本壁钟值含运行噪声，不把其耗时比例作为单独严格因果结论。v11 共享版为 3,204,352 B，紧凑版为 613,376 B，差值为 2,590,976 B，即约 2.59MB（十进制），约 5.2 倍。这里只统计 worker 分配，不能称为全进程分配或主线程占用。

所有冷首请求、变化后首请求及变化后窗口原样保存在 performance JSON 与独立汇总中；每类冷/首请求只有三个样本，JIT、类初始化及运行顺序影响仍存在。worker CPU 在短窗口中经常量化为 0，不能用它宣称 CPU 零成本。完整窗口包含提交和结算；latency 减 work 不是纯队列等待。

| --- | ---: | ---: | ---: |

没有执行持久化或压缩研究。性能缺口主要指向锚点行表示、逐请求捕获/发布以及查询方式，先改善运行表示与接入成本，比立即把当前全部行落盘更合理。1×2 没有与其他主基准做最优参数认证。

## 真实原版与实体控制

修订 `native-v4`：5 个场景全部取得预期终态，4 项实际到达、铁门 1 项正确 UNAVAILABLE；5×64=320 个双目标体型并发候选请求全部结算。17 次实际原版详细搜索全部记录，未登记入口 0；413 条驱动检查及 690 项独立读取器核对通过（690 包含前述 413 条检查和 145 份 class 核对）。导航、调度和 Mixin 的 48 个原发行类字节保持，五个核心源码与 runtime-v11 的性能副本逐字节一致。服务器正常停止、退出 0，无超时，每个研究 Runtime 关闭后状态与输入 pin 清零。

读取器实际调用为 `node .tmp/shared-runtime-validation-20261014/analyze-native.mjs native-v4 runtime-v11`，结果 JSON 保存 invocation；冻结读取器默认版本也已改为该组合，避免隐含参数指向旧 v7。此前 native-v3 的 413/545 检查与运行原件保留，不覆盖为修订数据。

该控制只验证 worker 候选到真实原版分段及实际 Husk 执行；没有把宏观连通伪造为 canReach，也没有整条执行回退。主线程真实搜索参数 accuracy=0、visited multiplier=1、region offset=8、range=35 保持；动态预算没有参与此次成本对照。

`native-v1` 不开门绕行原始 EXHAUSTED 保留。根据代码差异和失败位置，推断简化研究消费者将中间段真实节点消费完毕，当成整个任务失败；v1 没有保存足以直接证明该归因的 cursor 记录。`native-v2` 改为在中间段 canReach 且真实 Path.isDone 时从实际位置正常换段，取得 4 次到达和铁门正确负控制，并实际记录 consumedIntermediateHandoffs。最终目标仍要求真实最后段可达与实际目标格成立；物理停滞不进行固定两次自动重搜。该分支修订没有修改宏观算法或放宽原参数。
