# 宏观选路差异的输入与因果边界修正

日期：2026-10-23。用户指出：算法未改且完整输入固定时，
不能仅以输出路线不同就将版本间秒级差异归为选路质量问题。
本补充修正[上一报告](2026-10-23-route-choice-source-confirmation-zh.md)
第1、6节将宏观质量优化列为已确定首要方向的结论。
原报告、诊断日志及封存证据保留，不改写既有观察。

## 已确认与未确认

再次核对冻结NS、NT源码，宏观搜索、拓扑运行时、窗口枚举及Service相同，
两版仍仅相差AutomaticNavigationMixin的节点计时修复；
前轮坐标确认没有新增业务改动。

已有对齐覆盖测试接口、模板清单、起终点、负载请求序列等显式条件，
没有证明每次宏观搜索消费的完整输入和运行状态相同。
已观察到输出路线、交接候选和详细结果变化，
这些是输出及下游输入差异，不能反过来证明宏观算法本身出现质量回退。

尚未取得的关键证据包括：

- 实际使用的起终组件候选全集、能力参数及完整相关拓扑邻接和边代价。
- 搜索各次续行消费的依赖内容、交付批次及次序，以及相关数据何时可用。
- 是否命中共享走廊、缓存键和结果来源，或是否执行了新的物理搜索。
- 实际搜索方向、层级分支及同分节点处理顺序的一致性。

源码允许这些状态影响搜索过程，并不证明其中哪一项在本次发生了变化。
没有显式随机选路调用，也不能用“异步”一词替代上述具体取证。
跨进程revision数值不同本身也不是地形内容变化的证明：
签名包含版本、邻域及geometry.hashCode等内容，不能充当完整拓扑等价比较。

## 修正后的结论和下一步

保留三个观察事实：历史六条首段全集16→2、新诊断存在不同宏观绕行、
288组正常目标及range符合原规则。
它们不足以将本轮性能差异归为宏观算法质量问题，
也不足以证明NT修改导致宏观退化，或为既有宏观算法排除全部问题。

下一步首先定位完整有效输入或运行状态从哪里开始分叉；
在相关输入及状态固定后，再判断同一算法是否仍产生不同结果，
以及是否需要改实现、输入传播或选路策略。
“按几何改善宏观等代价路线”降为待研究的优化可能，不再作为已确定下一候选。
本次未将其转为性能回退根因，也不将全部秒级差异定性为纯计时波动。

历史性能基线继续有效，已有比较保留其观测意义；
输入一致性的缺口限制的是算法归因，不自动导致全部历史数据失效。
不默认重跑矩阵，不以补配对为由复跑基线。
