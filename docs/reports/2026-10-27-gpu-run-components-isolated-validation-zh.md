# GPU组件行程压缩隔离验证

日期：2026-10-27。承接[图内并行候选](2026-10-27-gpu-intra-graph-parallel-isolated-validation-zh.md)，
验证上一轮定位的混合体型组件构建成本。
隔离目录：`.tmp/gpu-run-components-isolated-20261027-v1/`。

## 1. 结论

**本轮组件优化有效，值得保留为后续候选基础。**
混合体型完整流程中位数49.4182→33.8400ms，下降31.52%；
单体型7.5179→6.9588ms，下降7.44%。
正确性控制全部通过，组件标签、元数据及下游结果保持一致。

热查询仍有负项：中位数分别增加0.1177/0.1300ms。
本轮没有修改热查询执行代码，原因尚未隔离确认。
本结论是冻结事实原型的局部优化结论，尚未完成真实生产宏观GPU后端接线。

## 2. 改动

只替换正式fresh构图的组件入口：
`parallel_components`→`run_components`。
宿主流程仅切换该内核句柄，源码装载器加入新CL文件及更新身份说明。
原有几何、连接边、边界、父图、查询、任务分组、事件和执行器代码保持。

1. 按X方向，把已经通过原规则确认相连的相邻合法格压成连续行程。
   有门时逐条X邻接沿用原精确几何判据，阻断处切开，不能跨门强行压缩。
2. 用16位起止位图定位相邻行的重叠行程，同一对行程有多个合法连接时只合并一次。
   地面保留同Y层平面连接；体积通道保留相邻Y层的原六邻接。
3. 并查集放入工作组局部内存，用32位原子CAS合并与路径缩短。
   父指针始终向较小格编号，最终根仍是组件最小格。
4. 合并结束后独立保存根，按原格编号前缀生成稳定组件ID，再回填逐格标签。
   包围盒按行程两端和Y/Z归约，anchor直接使用最小根。

这是将精确相连的子图收缩后求连通分量，没有引入近似选路、启发式或跨请求缓存。
合并结果再展开为原4096格标签；下游仍读取相同的数据结构。
本轮将行程压缩、局部内存和路径缩短作为一个候选验证，没有分别消融，
不能把收益全部归给其中某一项。

## 4. 正确性

默认一条乱序队列、强制五条有序队列、共享精确行三项控制，
各自覆盖单体型/混合体型，全部通过：

- 逐格合法位、组件标签、组件编号、anchor及包围盒；
- 组件连接能力/成本和邻居位图；
- 边界band及原始记录的完整顺序；
- 父图展开/凝缩CSR、元数据和witness；
- 查询路径、成本和同分结果；
- 共享精确行101218/394845条邻接与生产LocalKernel一致。

执行器各类失败数均为0；控制中的搜索仍能在无关构图结束前启动。
新内核每图64项工作组，实际内核允许上限256。
barrier全组一致，根保存完成后才复用parent为组件ID，
行程标签回填不会覆盖其他行程起点的根暂存。
每行支持最多16条行程，不假定连续合法位之间总能连通。
这些检查不等于对任意动态世界、取消或失效场景作出了完整生产证明。
