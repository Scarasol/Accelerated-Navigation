## 方案的实际内容

1. 原 worker 仍完整准备正常候选和恢复邻域，列表、日志、关闭契约保持。
2. 从原合法、去重列表增建本窗口的目标位图和非空行摘要。
   原始位存储约 544 B，另外计数组／对象头、元数据、查询与目标对象；
   构建多扫 N 个原候选，不免费。
3. 在原选点调用中，用整数 a/t 算评分中心。
   行内以左右最近置位作两头合并，跨非空行保留原最多八个不同目标。
4. 保留旧 double 评分、X/Y/Z 同分顺序、等待闭包和原生参数。
   不缩成一个点，不按位编号随便选，不向主线程迁移准备或恢复。
5. 不满足数值门、非正常 Boundary、失败集合非空等情况直接用已准备好的旧列表排序。
   没有额外 worker 物化或等待。已生成却未使用的索引成本仍计入。

质量目标是与旧 top8 相同，不是只保证候选合法。
设计证明不等同实现已经通过等价性控制，
更不等于地形变化后能 100% 到达。

## 复杂度和价值边界

单行选举固定次数位运算，O(1)；
完整查询 O(8R)，R≤256，最坏至多 2048 次逐行输出尝试，
另外计头比较、摘要扫描、合并及最后排序。
这不是 2048 条 CPU 指令，也不是整条连接严格 O(1)。
严格整连接 O(1) 与质量／低索引成本兼得的方法尚未确定。

稀疏时 R 可以接近 N，旧方法原本也可能很快。
仅选择器版本保留原窗口分配，还新增索引，不能声称正常／恢复总分配下降。
一并比较直接扫描旧候选的容量八选择器：它不建索引，但仍逐点评分。
旧 S1 bundle 失败不能否定独立 heap8，也不能替它证明收益。
本轮没有测量两者，不设拍脑袋阈值，不增加第三方性能矩阵。

### 首次有效审查的意见

对方认可实数恒等式、行内两侧单调和跨行 top8 证明的方向，
但要求补齐：

1. a/t 必须是整数 BlockPos，并提供原评分运算顺序和等待时机证据。
2. 数值门覆盖完整目标盒和全部轴，行内／跨行／停行使用同一旧比较器。
3. FULL_LAZY 的旧顺序、关闭后数据和保留成本缺口必须关闭。
4. main 不能因惰性 API 临时展开全部候选或恢复数据。
5. 不得称整个查询为 O(1)，更不能未经测量称全面优于旧方法。

V3 采纳 SELECTOR-ONLY，彻底撤下第 3/4 项对应的新惰性接口和延长快照持有，
保留原候选及恢复列表，增加索引的完整成本明确保留。

### 修订复审与采纳范围

对方确认前两项类型／运算顺序、完整盒门和比较器一致性在设计级关闭；
同行单调、两侧合并和全局前八证明足以支持进入后续必要控制。
FULL_LAZY 已移除，因此原列表、关闭和等待行为不变，第 3/4 项关闭。
第 5 项通过如实保留整体 O(1) 缺口关闭，不是算法突然成为整体 O(1)。

对方认为 selector-only 值得有限评估，但稀疏／小 N 可能输给 heap8；
要求计入索引构建、544 B 原始位存储及其它对象、fallback 率和所有不利值。
这项算法比较建议不解释为授权新增三方游戏矩阵或重跑有效基线。

为落实已审 attempt0／空失败集合范围，方案进一步明确：
现有 capture 不知道这些字段，调用点须用请求局部 opt-in 布尔透传，
旧接口保留并默认不建索引，避免恢复窗口无条件新建无用索引。
这是构建适用范围的实现约束，需后续代码审核，不是已执行或验证的改动。

### 类型、浮点与时机补证

只读核对当前 Service、NavigationRequestPath 与本地 mapped_official source jar：

- `mob.blockPosition()` 返回 BlockPos，`getTarget()` 字段／返回值也是 BlockPos。
- Vec3i.distSqr 将坐标转 double，按 `((dx²+dy²)+dz²)` 求和；
  外层 `.05` 是 double，并保持原乘法及加法。
- 原 awaitNative 保存已经选出的 targets，唤醒不重选；方案保持。
- 完整目标 section 盒对 a/t 的每轴绝对差均≤65536 时，
  距离平方和可精确表示，评分误差差额小于 2^-18；
  同一侧非零相邻实数分差至少 1/20，支持旧 double 下的严格单调。
- 两侧及全局同分仍使用原 double 与 XYZ，不换成整数评分。
