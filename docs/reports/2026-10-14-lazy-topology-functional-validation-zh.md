# 懒惰升级实体执行功能补测

日期：2026-10-14。状态：**功能验收未通过；压缩研究暂停；未送审，未接入生产。**

用户要求“先验证功能再考虑压缩”，并询问功能是否验证好了。此前候选图、能力关系和原版查询证据不足以证明实体实际到达，本轮补充隔离执行原型，保留失败，不将证据核对通过登记为功能通过。

## 1. 当前判定

最终 `functional-v4` 执行九个预定场景：五个正向场景实际到达，一个关闭铁门负控制正确返回候选不可用，三个正向场景失败。驱动运行正常结束，`functionalPassed=false`。

| 起点位于基础图未表示的窄通道内 | 局部升级取得候选 | SUCCEEDED | 实体实际到达 |
| 低顶通道 | 局部升级取得候选 | SUCCEEDED | 实体实际到达 |

最终有 29 次真实原版查询。74 条检查记录中，71 条成立、3 条功能预期失败；不能写成“74 项测试全部通过”。独立读取器 520 项证据核对成立，同时明确保持功能未通过。

## 2. 被测范围

证据根：`.tmp/lazy-functional-validation-20261014/`。

使用上一阶段冻结的五份生产构图/采集核心和 `PartitionedLazyProbe`。构图、能力分档和局部升级算法未修改；本轮新增 `FunctionalProbe`，将其候选锚点转为短段目标，交给真实 GroundPathNavigation.createPath 和 moveTo(Path, 1)，实体在真实 Forge 世界中运行。

演员为成年 Husk，具有原版 FloatGoal 和 OpenDoorGoal，加入 ServerLevel 并接受正常 AI、移动控制和碰撞。导航子类仅声明 tick 并调用 super，以隔离自动生产路由。它由本轮同步研究适配器驱动，不是生产 SegmentedNavigationService、异步 Runtime 或 Goal/Brain/POI 接入验收。

阶段目标来自宏观候选，保留转弯并将直线段限制为四格；没有生成伪 Path，没有传送实体，没有人工支撑/方块语义过滤，也没有整条原版执行回退。原版详细搜索返回的真实 Path 直接执行。

阶段查询固定 accuracy=0、visited multiplier=1，range 和节点上限来自演员的原导航默认值。成功要求真实最后段 canReach 和实体实际进入最终目标格。**这是本轮选定的严格精度控制，不等于已验证所有生产调用方的 accuracy 配置。** 后续需要按真实 NavigationIntent 保留阶段与最终目标精度语义，不能为消除失败而偷偷改宽条件。

普通地面 Husk 的浮水行为也不代表所有两栖或水生导航。流体许可是研究输入显式条件，本轮没有完成生产实体能力到该条件的通用映射验收。

两次 section 局部图、真实边界检查及实体跨界可以组成一条简单可执行候选。该结果没有覆盖现有 Super 聚合、跨区发布、卸载重载或并发索引更新。

## 3. 两类未解决的问题

### 3.1 水域与输入失效

测试在房间中放置真实水源，其定时流体更新继续运行。水流扩散后，实体被推回；第一段详细 Path 的 canReach 为 true，实际没有完成该段。

最终版本按原导航 range+8 的区域另建输入观察，复用生产 NativeQueryProof 的区块身份/修订检查。该观察在实体执行期间变为不当前，并记录 `INPUT_VERSION_OBSERVED_STALE`。

这是查询范围的版本观察，不是从生产 Runtime 接收的完整查询证明；它证明观察闭包发生了变化，不能独自证明某个节点必然不可行。不过它明确暴露了当前研究适配器的缺口：**自动方块/流体变化只被观察，没有执行暂停、撤销旧结果和按新输入重搜。**

水域失败保持，不宣称实体不能走水、不将其写成原版无路、不归为单纯升级遗漏，也不通过清掉真实流体行为来将本例登记为通过。

### 3.2 节点耗尽与实际阶段到达

不开门绕行最终停在 `(9.5125,81,11.1533)`，当前段目标为 `(9,81,10)`。输入变化后的替代绕行停在 `(9.5134,81,8.1518)`，当前段目标为 `(9,81,7)`。

两次原版查询均可达，终态记录均为：

- Path 节点已耗尽。
- Navigation 仍持有该 Path，不是 native stop 清空路径。
- 实体尚未进入精度 0 的阶段目标格。

因此，早期对“原版提前停止”的猜测已被收窄：本例是节点耗尽与物理阶段到达之间的衔接问题。追加的最多两次 native-stop 重搜分支没有触发；不能声称该分支已经修好了它。

Forge 的跟随逻辑具有身体宽度相关的节点位置和到点阈值，可能参与这种差异；当前证据不将其归为共享图构图错误或生产导航回归。下一步应复核真实阶段精度、原版节点消费与等待/交接时机，并保留最后段 partial 和 EXHAUSTED 的区分。不能伪造到达或在详细搜索前增加语义资格过滤。

## 4. 已取得的功能证据

五个实际到达场景都保留每 tick 位置、真实节点、最终坐标、宏观锚点和阶段目标。独立读取器重算实际位移，核对最终目标格和最后段 canReach；轨迹中未发现大于一格的单 tick 位置跳变。

窄通道、端点缺图及低顶验证从基础图无连接到局部生成，再到真实实体到达。门捷径验证了目标开门条件独立生成，以及原版 OpenDoorGoal 实际打开木门并通过；不开门路线没有打开门。

跨 section 场景先升级西侧和东侧端点，再通过真实 BoundaryGeometry 桥接，缺 halo 控制拒绝桥接；实体实际从西侧经过窄口到达东侧目标。

输入变化场景在演员接近旧通道时停下导航、修改地形、增加代次，并实际调用交付入口。旧代次被拒绝，没有新增旧输入详细调用；只进行一次宏观刷新，之后详细调用绑定新代次，新候选包含替代通道。但后续物理交接失败，所以这一场景不能整体记为通过。该控制是同步研究代次，不是实际并发 worker 的迟到回调资格。

同输入重复请求不增加局部出边生成的既有控制保持。

## 5. 版本、失败和核对

- `functional-v1`：前三个场景实际到达；水域阶段超时后断言失败并停止。原件保留，不能补记未执行的其他六个场景。
- `functional-v2`：驱动记录全部九个终态，不在首个预期失败后中止。五个到达、一个正确负控制、三个失败。`failed=false` 仅表示驱动没有内部异常，`functionalPassed=false` 表示功能预期未通过。
- `functional-v3`：增加有界 native-stop 恢复分支，结果相同；未触发该恢复资格。
- `functional-v4`：补充实际节点耗尽及输入版本观察，功能判定保持。此版本作为最终报告绑定。

重复版本用于归因和修订适配器，不合并为更多独立场景或额外通过证据。所有版本源码、发行包和原始结果分别冻结，不覆盖旧运行目录。

四个服务器 JVM 均完整停止、正常退出；v1 的宿主脚本因功能断言失败返回错误，这不等于 JVM 异常退出。最终版本 29 次查询中，28 次为真实短段执行查询，1 次为铁门负控制查询，没有完整路线移动回退。

发行审计确认 48 个预算、导航、Mixin 类与此前冻结原始发行包逐字节相同。未改生产代码、动态预算、用户存档或共享构建输出。原有并发工作区变动只记录，不回退。

独立 `verify.mjs` 为 520 项核对，检查冻结身份、实际位置/距离、原版节点终点、宏观锚点和阶段目标、跨界、旧结果拒绝、失败分类及发行隔离。`evidenceChecksPassed=true` 与 `functionalPassed=false` 同时成立。

## 6. 下一步顺序

**功能优先，暂停压缩、存储布局及持久化收益研究。**

先解决两个已复现的执行问题：正确处理真实请求精度及原版节点耗尽后的阶段交接；将自动输入变化接入暂停、失效和原版重搜，覆盖门与流体变化。随后补充 step/drop、partial、取消和替换、能力变化、邻区失效及异步发布控制，再讨论功能资格是否足够。

本轮不批准整体懒惰升级功能，不批准生产 Runtime 接入，不送 DeepSeek。既有持久化 v5 的 future 缺陷仍未处理，也未用于本实验。
