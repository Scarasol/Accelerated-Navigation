日期：2026-10-14。用户授权继续探索，与 DeepSeek 收敛方案后直接实施验证。

本次数据支持保留查询数组复用这一候选优化：查询结果、并发隔离和清理控制通过，窗口 worker 分配除以已接纳请求数减少约 90%～96%；零拒绝的串行和 64 在途负载下，三个场景整体处理速度都有改善。尾延迟仍有反例，不能把这项结果扩成全部负载或真实服务器 tick 的性能保证。

## 实现与范围

证据根：`.tmp/shared-query-scratch-20261014/`。冻结实现 `scratch-v1`，测量 `matrix-v1`。25 份 Java 源码、158 份 class 的 SHA256/大小、编译记录及原始证据均保存。基线 22 源从 `arrival-v1` 克隆，未修改副本保存为 `baseline-sources/`。

仅复用 `SharedRows` BFS 的 `int[4096] parent/queue`。实际 `TopologyTaskExecutor` 每个 worker 惰性持有独立 ThreadLocal 值；只有实际 Task 体内能取得。每次搜索完整重置 parent，head/tail 从零开始，queue 只读取有效前缀。已知搜索失败后，局部搜索顺序复用同一对数组。

owner 拒绝外线程传入；busy 时为同线程嵌套查询分配独占临时 fallback；query 的 finally 释放占用。ThreadLocal 在整个 worker 循环外层 finally 移除，正常关闭和 fatal 逃逸均结算创建/清理数。结果 List、Change/legal 和发布快照不持有查询数组。

原单参 `query(Query)` 保留每阶段分配作为对照；新增二参复用入口和三参测试入口。测试 QueryHook 默认 null，位于已知 BFS 完成、外层 reconstruct 尚未读取 parent 时；另在局部结果重建前提供同一钩子。嵌套由钩子在同一 worker、两锁之外直接调用查询，这是构造性防御测试，不表示当前生产存在嵌套调用。

本轮不复用 LocalKernel/BuildScratch，不改变捕获、构图、算法、MovementKey、准入、路由、恢复或动态预算。共享实现仍在隔离原型中，未接入生产消费者，未测新实体移动、上层图、压缩或落盘。

## 性能协议

新建 `ScratchPerformanceProbe`，不改旧探针协议。只比较固定分块＋Slot复用中的 allocate/reuse，各 12 个独立 JVM，共 24；同 JVM 不混模式。先后 AB/BA 交替，三个场景与六个条件按重复编号轮转。12 次是探索重复数，不宣称统计功效普遍充分，不按编号制造配对退化结论。

每场景 8192 个唯一完整查询键，起点 x=1..7/z=1..14、终点 x=9..15/z=1..14，固定枚举前 8192 对；混合五种 body 按 ID 循环，MovementKey=(1,0,3)，limit=4096。两模式与全部 JVM 的查询及生产参考图预期完全一致。每场景预热 16384 请求、最多 64 在途，正式条件间 drain；诊断关闭。

每场景六条件：真正串行 8192；FIFO 限制 64 在途 8192；2000/s、8000/s 各 8192；无节奏突发 512、2048。串行确等前一结果观察完成，64 在途确等相应旧槽位；固定速率不等前一结果、不丢迟到、不重设计划钟。

总计 432 个正式窗口、2,543,616 请求：2,532,252 正常结果、11,364 明确 flight-cap 拒绝、零意外终态。正常结果包含正确的负候选，不等于全部寻路成功。预热共 1,179,648 请求，排除在正式计数和分配差值之外。

worker 分配为两个实际存活 worker 的累计计数在窗口前后、终态/drain 后的差值。除以已接纳完成数；若有拒绝，仅称窗口总分配比，不能称每个成功请求的精确归因。整体分位从全部相应原始请求合并计算；吞吐为全部已完成数/全部窗口时间，拒绝不算已完成工作。

24 次启动前与 475 次运行中抽查未观察到其他 Java，不证明没有其他系统负载。全部窗口保存 GC 与编译增量、CPU、caller/worker分配及原始时间；正式窗仍有 GC/编译，未宣称稳定 JIT、JMH 或真实服务器 tick。
