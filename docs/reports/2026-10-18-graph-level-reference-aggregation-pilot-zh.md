# 图级引用聚合：隔离原型与有界验证

日期：2026-10-18。用户授权继续研究，并明确小于10%的真实净改善也有研究价值。
前置：[历史成本分析](2026-10-18-runtime-history-cost-analysis-zh.md)。
证据根：`.tmp/runtime-graph-ownership-20261018-v1/`。

## 一、本轮结论

**图级引用聚合值得继续研究。原型未接入生产，但已取得实际操作减量、
有限正确性和完整热API两个场景均改善的证据。**

同一张图的缓存或其他消费者已经持有事实时，新增、释放一个消费者，
不再重复遍历整组事实；消费者自己的计数仍逐次加减。
200次就绪图获取与关闭，实际标量事实更新从6000次降到0次。
两对固定比较中，空气重复场景进程CPU分别降低43.49%、45.27%，
不重复场景降低47.49%、40.07%；分配均约少48B/操作。

这些结果属于保留anchor的就绪Base图获取与关闭，不是整次寻路或游戏提速。
没有用历史69.80%的遍历机会推算CPU，没有将两对数据称为稳定性能证明。
本轮结束同壳扩样，下一性能问题应转向另行预注册的真实冷/暖路线侦察。
生产接入、首Path、实际到达、tick和步骤8完成均未获批准。

## 二、对旧结果的表述修正

旧“连续空气事实合并”第二版在空气场景有改善，在不重复场景测得较高成本。
后者应表述为控制场景的观测，不能简称为整个方案或整体负载“回退”。
同样，缺少真实负载权重，不能直接确定旧方案整体净收益大小。
旧候选未全过原门的记录保持，不事后删除数据或改变原判定。

本轮是独立的新候选，只有图级聚合，不叠加空气段合并。
协议在测量前固定，不将原来的10%门套作一切后续研究价值的必要条件；
方向一致的小改善也可支持进一步调查，但不能自动授予生产资格。

## 三、实现为什么可以更小

没有新增租约表、图字段或常驻元数据，复用现有两项状态：
当前缓存图的对象指针，以及按具体图身份保存的消费者计数表。

候选只改`TopologyWorkerRuntime`的三个方法，共10行增加、4行删除：

| 方法 | 新增判断 | 目的 |
| --- | --- | --- |
| 固定图 | 首个消费者且该图不是当前缓存图时，才增加图事实贡献 | 当前活动缓存或其他消费者已持有时省掉遍历 |
| 释放图 | 最后一个消费者且该图不是当前缓存图时，才撤销图事实贡献 | 旧图保留到最后一个消费者释放 |
| 退役缓存图 | 没有消费者持有该具体图时，才撤销事实贡献 | 退役时仍有读者则保留一份活动贡献 |

发布新图仍增加缓存贡献；原`touchBase/removeIdleBase`负责活动/空闲转换。
直接事实持有、消费者原始数字、全局活动引用、原标量更新方法、
事实序列槽位重数及当前性检查均保留。
`pinBase`仍先退出idle，因此固定当前空闲缓存图会先恢复活动贡献。

源码审计将这三个方法还原后，整个候选runtime与基线一致。
六处缓存图写点为一次赋新图、五次清空；
全部五处退役都立即清空指针，之间没有外部回调。
没有清空消费者表的捷径；实际替换验证新旧对象不同。
候选仅编译在新`.tmp`目录，生产源码和默认Jar不变。

底层事实整数的含义改变：从“缓存加每消费者的逐槽贡献”，变为“每图类别的逐槽贡献”。
不能比较新旧内部整数逐项相同；必须比较事实身份、活动/空闲类别、
字节桶、删除时机，以及独立维护的真实消费者数量。

## 四、正确性与机制

| 检查 | 结果 |
| --- | --- |
| 实际private方法受控场景 | B与候选各6600场、210800次断言 |
| 未拥有或错view释放 | 各1236次预期错误，保留原失败行为 |
| 可观察层摘要 | 两者完全相同 |
| 外部真实pin | 按动作清单另行核对；消费者表值始终为正 |
| 公开API生命周期 | 14个观察点，旧图、多geometry、idle、卸载重载与关闭账目通过 |
| 复审后外部持有补核 | B与候选各114检查，5个新旧图视图、6个关闭后观察点通过 |
| 并发 | 四线程各60次请求与12次事实事件发布交错，结清后账目通过 |
| 就绪API操作减量 | 200次获取/关闭：标量更新6000→0 |
| 受影响契约 | Core9、Boundary recovery9、门集成、Worker7组通过 |
| 共享契约 | Shared stage99951检查/41路线/643组件；Shared runtime1296检查通过 |

受控状态包括当前/旧图pin 0～3、直接事实pin 0～2、缓存活动/空闲/无图、
共享空气身份、重复槽位、内容相同但身份不同的事实，以及idle、退役和淘汰。
oracle先从缓存与消费者所有者清单构建数值联合，再按实际槽位展开；
B检查原始账目，候选检查图类别联合账目，二者比较可观察层。
它没有用候选的三个条件作为预期结果计算器。

淘汰检查注入临时128MiB合成缓存字节压力，执行原`evictBaseCache`，
扣除注入偏移后核对剩余真实所有者。没有修改容量上限；
这不等同于真实128MiB地形或驻留负载。
计数器只用于正确性，未进入性能JVM。

关闭时保留一个外部视图，section表清空后仍核对其旧图持有，
随后视图关闭、重复关闭，最终事实记录、活动引用及字节均归零。
既有公开视图的关闭本来幂等，也允许在runtime停止后释放已拥有的pin，
没有为了通过验证把它改成报错。

这些是有限语料、真实方法及现有并发契约，不是所有交错的形式证明。
人工整数溢出、损坏账目和OOM重放不在承诺范围。
构建中取消、持久化直接所有者和真实长期压力仍需后继应用验证，
不能仅因静态表与有限测试通过就称生命周期风险全部消失。

## 五、完整热API测量

原封不动复用旧`MaintenanceApiBench`及进程CPU profiler字节码，
JMH1.37、Temurin Java17.0.18+8、单线程、512MiB。
参数与旧壳相同，保留重复的`-Xmx512m`参数，没有调整优先级或亲和性。
Trial setup构图并保留anchor；计量是
`requestBaseGraph().join -> componentCount -> close`，不含每次冷构图。

测前协议固定两对`B,G / G,B`，每次驱动的air与distinct分别独立fork：
4次驱动、8个测量fork、32个迭代，预热3×1秒、测量4×1秒。
2026-10-18 08:05:04至08:06:32 UTC完成；
107,957,203次测量操作，32项CPU总量/实际操作数归一化核对通过。
没有删除、追加或重跑有效样本，没有JFR、编译XML或诊断代理。
各驱动前未见其他Java；本任务的方案复审在测量前结束，结果复审在测量后启动。
后台常驻应用没有暂停。

分配各fork均约768.02→720.01B/操作，下降约6.25%。
测量期编译2～4ms；单fork内CPU迭代变异系数最大8.65%，wall最大0.71%。
GC原始次数、时间、每迭代CPU/操作数及wall均保留。
候选固定时间内完成更多操作，不能把更高的GC总次数直接称为每操作回退。
没有将主线程CPU替代进程CPU，也没有扣除旧A/A波动。

anchor保证图存活，恰好代表可省较多重复固定/释放的路径；

## 六、技术失败与审查

首次编译的runtime成功，但harness缺少单独编译的
`MaintenanceLifecycle`支持目录，补工具classpath后新目录编译成功。
随后增加类来源断言，以最终`compiled-v4`执行。
第一次验证在B的“停止但外部视图未释放”观察点失败：
oracle只枚举section表，漏掉关闭后由外部视图持有的原owner。
补入实际pre-close owner根并独立核对活视图数量后，
新名`validation-v2`的B与候选均通过。
候选源码没有因这两个工具问题修改，性能尚未开始；原失败输出全部保留。

方案复审使用既有WSL `deepseek-review.mjs`和固定
`deepseek/deepseek-v4.1-flash`，6058B、258.649秒返回
`ACCEPT_SCOPED`、必须修改项无。其清单用于补充错view、退役写点、
外部pin、类来源、关闭及并发检查；没有采纳与既有幂等关闭语义冲突的泛化要求。
结果复审6796B、134.349秒返回`ACCEPT_SCOPED`、必须修改项无；
认可保留原型、结束同协议扩样，下一问题转真实路线。
两次均退出0、未超时、settings哈希前后一致，已完整阅读回答。
它只收到自足摘要，不构成独立源码访问或复现。

采纳其对外部根独立性的提醒，又做一次窄正确性补核：
从测试保存的5个真实导出视图，直接检查release闭包捕获的具体view/图身份，
不枚举section表重建预期；旧图3个视图、新图2个视图，在runtime停止后逐个释放。
六个观察点直接以尚存外部句柄数预测事实身份、贡献、字节和真实pin，
B与候选各114检查通过。它补强前一版“从关闭前runtime表保存owner根”的检查，
没有修改候选或追加性能样本。

没有照搬复审中的“四对B/G”计数表述：
实际是两组运行顺序对×两个fixture，共四行比较、八个测量fork。
本轮共识限于原型保留和下一研究方向，不是整游戏、步骤8或生产批准。

## 七、后继问题与封存

本轮支持保留图级引用聚合原型，结束当前热API扩样。

应另立最小侦察协议，保留真实30秒等待、实际到达、首Path、全进程CPU、

事件失效和旧图生命周期也须独立保留验证。
