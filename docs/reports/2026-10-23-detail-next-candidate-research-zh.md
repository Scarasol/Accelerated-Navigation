## 1. 决策

下一候选选定 **NT-L4：在已修正节点计时的NT上，隔离重试普通分段最多四连接**。
具体边界及后续验证安排见[候选方案](../designs/2026-10-23-detail-nt-long4-candidate-plan-zh.md)。

选择理由是已知的重复完整查询可以减少，旧304格平地已观察到实质接续收益，
而旧长段的一部分执行失败后来取得了具体机制证据并形成独立修复。
这是有根据的有限隔离候选，不是已经证明总成本明显下降，
也不是新算法使单次A*大幅变便宜。
若要求现在就拿出证据闭合、预期显著的单查询内核新方案，本轮没有找到。
不把小常数精简凑成主候选，也不把研究不足说成优化空间耗尽。

继续尊重用户暂停宏观平局/通道质量方向的决定；
上一轮输入批次导致同代价通道变化的结论保留，不据此改宏观算法。

## 3. 未选择的单查询方向

| 方向 | 本轮确认的可删工作或障碍 | 决策 |
| --- | --- | --- |
| visible holder缓存 | hasChunk不使用原4项chunk缓存；只缓存发布map身份+坐标→holder可省一次fastutil查找，但仍须读实时ticket | 份额与净收益不足，不作主候选 |
| hasChunk布尔缓存 | holder.ticketLevel可在visible map身份未变时变化，Load/Unload事件不覆盖全部变化 | 不采用 |
| scope/区块定位合并、直接section读取 | 重复定位存在；直接HEAD返回会改变其它Mixin可见调用链，保留live检查后的可省量未知 | 没有取得足够大的兼容闭合方案 |
| proof按用途采集 | 逐region槽创建Entry/WeakReference等在search窗外；公共decisionCurrent、adopt、POI与延迟消费者仍需闭合 | 不能看到移动分支只比身份就删除，仍属附带研究 |
| raw状态复用/floor缓存 | raw诊断约81%为空气早返，静态collision shape已有缓存，保留真实读取后的可省量有限 | 暂不升主项 |
| 精确平方距离与条件sqrt | 或可减少最多8目标的开方；不减展开，分支和记账可能抵销，还未核对Node/Target精确运算及hook等价 | 仅小研究假设，不实施、不宣称无损提速 |
| 端点预筛 | 1017独立提出再否决：每请求增加最多8次检查，而旧64次长查询已全部可达，原生已有锚点/AABB缓存 | 没有足够收益依据 |

ChunkMap的visible map由modified时clone后发布，但holder不是不可变状态，
因此不将“map身份稳定”等同“已加载布尔永久稳定”。
可缓存holder的资格与值得做主候选是两件事。

原生PathFinder已使用加权1.5启发式和最多8目标；
单纯减少sqrt不是改变搜索阶数或利用宏观资产得到精确最优解。
本轮未提取Node/Target/Mth进一步成案，没有把该假设写成已闭合实现。
原生重建路径的头插可改为尾加reverse，但当前11至33节点为主，
仍只能附带，不能独立撑起候选。

## 4. NT-L4的依据与保留风险

| 证据 | 已确认 | 不能外推 |
| --- | --- | --- |
| 旧L复杂压力 | 64/896请求扩段；64次返回可达，14次之后执行恢复；部分晚5.8至10.9秒 | 不能认为canReach保证行走成功 |
| 旧L304格平地 | 冷暖各20→11次搜索，18长段无恢复，到达分别早451.86/450.05ms | 单实体观察，不是304格一次全程A*或复杂并发保证 |
| 停止诊断 | 4次新节点等待0tick却携带旧89/92tick立即超时，其中2次旧L长段 | 未定位旧L全部14次失败 |
| NT独立修复 | 原2/1跨度，896/896到达；真实石墙仍能按原阈值终止；项目新节点清timer | 不是NT+L4测试，移除的14条台阶恢复不是旧L同一集合 |
| 查询成本 | 旧L无长段恢复的50请求合计少50次搜索；304每场少9次 | 分组非随机，不把次数差换算为当前候选CPU收益 |
| 分配负项 | 旧L搜索分配+56.57%，约88.20%增量在832条未扩段请求；NT对NS+10.96% | 原因未唯一定位，不能默认由timer修复消失或归纯波动 |

旧压力总搜索1704→1666、wall178.8867→182.8239ms；
旧L并没有通过总体净收益评价。
50次无恢复分组的搜索减少约为1704次的2.9%，
说明原压力场总体直接收益预期应保守，不能包装为大幅整场CPU候选。
较长路线的接续收益是另一个需正确母版验证的问题。

NT自身search wall123.4408ms比NS178.8867ms低，
新增代码却在执行计时而非A*内核，输入/路径亦有差异，
不能据此声称详细算法又提速31%或余量已足够任意扩长。

源码复核还明确：旧方案“range保持”应准确理解为公式及上限保持，
并非每次实际数值保持。Service普通段按最远备选目标距离+8、16至96限制计算，
目标远移可能放大region矩形、展开量与proof工作。
本报告澄清这一表述，旧观测原件与数据不改。

额外预算、防御扫描或宏观改动。
