# T/QG回退与尖峰：1017讨论及下一步方案

日期：2026-10-22。本轮按用户要求，只读复核现有实现和数据，
与官方1017所用的flash别名进行两轮max方法讨论，形成下一步方案。
没有新游戏运行、构建、候选修改、生产接入或提交推送。

结论：**不能将本轮负结果整体归为波动。新增热包装确实存在，QG还出现了
有明确阶段分布的额外partial；两个具体候选继续停止。
347ms尖峰则已有“墙钟远大于CPU”的新增证据，仍不能唯一归因。**
下一项建议是一个保留旧脚手架的原生语义空后端S对照，
不自动重做两个clean候选，也不立即换成JPS、Theta或门户图。

T/QG分别从U建立，不相互叠加。

T/QG各只跑了**35ms背景占用的一次六场**：
64/128/256实体分别进行8/28格测试。

本轮复用原件，未重跑有效U/P/N。

## 2. 实现确有冗余，但不是已证的全额根因

已对照U/生产Mixin、候选源码及T编译字节码：

- T不修改启发函数，却新增了覆盖全部`getBestH`调用的包装。
  helper固定返回NaN，随后经`original.call`执行原函数。
  QG作用域外同样经此回退。
- 字节码可见三项`Object[]`、`Operation.call`和`Float`拆箱。
  这是新增调用结构；JIT是否消除运行时分配尚未测量，
  不能将字节码分配直接当成实际分配量。
- U已有邻点包装和失败节点过滤；本轮新增的是每次邻点调用的
  `ThreadLocal`读取、判空和计数。不能把U原有成本全算给候选。
- 外层每次搜索也增加上下文读取及包装；算法不适用不等于这些脚手架不执行。
- 没有发现“每节点完整身份、版本、取消、预算检查链”。
  业务资格在Service入口一次判断，Context进出各一次。
  T堆按PathFinder复用，QG目标/q数组每次适用搜索准备一次，
  不是每节点重建。

因此，更准确的判断是**实验实现把无关适配带入了热循环，
其性能份额尚未分清**，不能已经认定为大量防御策略导致全部回退。

## 3. 方法本身也有负面行为信号

T新增2次partial均在256×8拐角首次正常中间段；
QG新增46次分布为墙14、门14、拐角18，全部在首次正常中间段，
每次随后多一次恢复搜索。这些不是计时波动。

QG的28格64/128/256分别增加6/12/24次partial，
是更多实体复现对应地形，不能据此声称单请求开销随并发或range增长。
现有DEBUG能对齐路线、阶段和日志range，
但缺完整目标集合、expanded及终止原因，不能唯一分清
几何偏置、节点限额、range或其它状态约定的份额。

QG把“距最终目标的几何方向”引入本段有限Weighted A*，
不保证真实地形代价更小或partial更少，当前适配结果不佳。
T只改变同f次序，也没有取得值得继续调整的净收益。
两者均恢复后896/896到达，不等于路径质量或性能通过。

讨论中明确纠正：`Target.updateBest`保持真实距离，
服务原partial/bestNode回溯，本身不能判为代码不一致。
原循环在g改善判断前写`walkedDistance`、closed不重开等是继承的约定，
本轮没有证据将其认定为新增partial的唯一根因，不顺带修改。

## 5. 与1017最终收敛的执行顺序

以下是后续方案，**本轮尚未实施或启动测试**。

### 5.1 保持两个负候选冻结

不继续调T排序或QG系数，不改节点上限/range去掩盖partial，
不自动制作T_clean/QG_clean，不恢复预算、增加队列或扩大测试矩阵。
这只停止两个具体实现，不否定所有A*或详细寻路优化。

### 5.2 先用一个空后端回答实现成本问题

S从同一U和旧候选适配建立，算法保持原生，精确约定：

| 部位 | S保留/删除 |
| --- | --- |
| worker、Service原流程、选点、分段、派发 | 保持U，保留候选的入口资格/Context进出 |
| 全部getBestH包装 | 保留旧包装，helper固定NaN，再执行原h |
| 邻点调用 | 保留U原过滤，以及旧候选ThreadLocal/判空/计数 |
| 外层逐搜索包装 | 保留旧调用适配 |
| openSet、h、Target.updateBest、终止/partial | 使用原生语义 |
| T方向堆、同f方向排序、QG/q数组 | 不启用 |
| 新每节点资格/版本/预算检查、诊断计数 | 不增加 |

S用于检验**旧共同适配能否造成同量级成本**。
不能把钩子全删成U再测，也不能把S-U直接线性相减，
声称得到了精确算法成本；JIT、缓存及实时路径变化仍可能混合。

开跑前必须审定精确diff、历史身份和固定输入控制。
优先复用既有原生循环图fixture，核对h、堆、updateBest、路径和partial。
到达时间本来就是测量对象，不要求实时运行时间相同；
少量实时搜索/partial差异触发核查，不立即证明S改变算法语义。
若S和U实际无差别，或必须新增热插桩才可解释实验，停止，不开跑。

此后若获准验证，只新增**S一个35ms JVM、原六场一次**，
原顺序、场景、工具、参数和计量保持，复用有效U/T/QG/P/N历史；
不补15/25ms、不重跑U、不做四版本矩阵。

判读与停止门：

- S与U同路线输入/搜索行为可比，成本增加达到旧候选增量的量级：
  优先清理实验包装；未来方案在搜索入口决定后端，
  不给无关搜索增加无效热调用和计数。
- S新增成本很小：记录“共同脚手架不足以解释”，
  排序/启发改变更值得怀疑，但不据一次观察唯一细分q、堆或JIT。
- 若差异含混或路线输入不一致而无法解释：保留未分清并停止，
  不扩矩阵凑结论。
- 无论S结果如何，都不自动恢复两个已经无净收益的候选。

### 5.3 尖峰单独定位，不污染S

S主测只沿用原计量，不同时塞入新任务账本、逐节点日志或栈采样。
现有数据缺少的正是任务类别、任务CPU/wall及停顿时调用栈。

如原日志或S仍出现同类尖峰，先做有界内存账本，
在drain/任务边界记录类别、wall和线程CPU，关服后输出；
若仍为大wall小CPU，再考虑只补256×8的阻塞/主线程状态栈诊断。
诊断解释原净数，不替代原净数；未重现则保留未知，不扩大矩阵追峰。
新增诊断必须记录具体缺失原因与扰动，不据CPU差额虚构锁等待。

### 5.4 后续方向：先核实询点热点，不盲加缓存或更换算法

已核原WalkNodeEvaluator存在路径类型和AABB碰撞缓存，
均`computeIfAbsent`、`done`清除，底层还有节点表。
因此下一步先静态核对cache miss内部的世界读取和临时对象，
以及是否有未被原缓存覆盖的重复纯查询；这不是第二个运行时实验。

只有确认热点和重复以后，才考虑一次同步搜索寿命内的局部复用。
保留实体尺寸/能力、开门、水、台阶、碰撞、type/malus、
节点状态和邻点输出顺序；不缓存可变Node数组，不跨tick共享实体结果。
宏观资产仅在字段语义和版本匹配得到证明时复用，否则仍走原生求值。
若没有热点或原缓存已覆盖，停止这个切口，不为“使用宏观资产”强加缓存。
JPS/Theta/门户图或整套后端重写不因此自动成为优先项，也不承诺200ms。
