# 构图中间产物分层复用验证

开始于北京时间 2026-10-15，跨日运行至 2026-10-16。独立原型：`.tmp/intermediate-reuse-20261015/`。方案：`docs/designs/2026-10-15-intermediate-reuse-validation-plan-zh.md`。

本版原型的局部验证已完成：正确性通过，原始事实行复用确实减少工作，四体型组存在完整 Base 成本收益；普通单体型却回退 10.6%，两体型近乎持平。**当前通用首用即建缓存未过推广成本门，不接入生产，不启动本候选的 Minecraft 冷首次请求矩阵。** 这不是整个分层复用方向被证伪；缺少真实跨 GeometryKey 重复消费比例，不能将有条件的收益推广到实服。DeepSeek 已达成该范围的研究收尾共识，结论为 ACCEPT_WITH_GATES、必须修改项无，不是生产批准。

## 本轮实际验证的实现

第一层按不可变 PackedFacts 对象身份，惰性缓存四个原始事实标志位平面，每行 16 格打包成 long；第二层按当前 GeometryKey 拼装 volume/ground 行，精确形状仍调用原 volumeOpen；第三层保留原侵蚀、组件、边、能力与完整 stamps 规则。缓存为 worker 私有、64 源对象 FIFO 上限，清空释放源引用；遇门退回原行生成。

本次验证对象是 Base 跨不同 GeometryKey 的原始事实行复用。没有验证新的 LocalKernel 消费接口、完整 legal/prism 缓存或 Boundary 结果共享。现有 facts/SectionGeometry、SharedRows、LocalKernel 惰性合法性不计作本轮新成果。生产源码、调度预算、生产 JVM 参数、TTL 与持久化均未改动。

## 正确性

- 50 组输入、21 种几何条件，1,050 对 Base 构建；完整图快照以及 legal/prism/volume/ground/haloUsed 一致。
- 覆盖 GROUND/VOLUME、精确薄形状、UNKNOWN、门与门支撑、流体、偶数对齐、最大宽高 16、完整或稀疏 halo、缺失 halo。
- 补充事实替换、相同内容但不同对象、原图不受后续构建影响、同一中心事实的下方 halo 加载/代次变化/卸载、FIFO 淘汰、清空，共 6,315 个断言通过。
- 在独立 JVM 中编译未改动的冻结原始四个生产类，另与候选的 1,050 份图逐项摘要对照通过。跨 JVM 仅排除 `signatureHex`：原算法签名包含 GeometryKey.hashCode，后者含 Channel 枚举的进程局部身份。原始全部字段的同 JVM 比较仍包含签名。
- 这些是局部快照和缓存生命周期检查，不能冒充真实 runtime 的 stale flight、卸载重载发布或完整实体移动验收。

## 行生成内核

JMH 1.37，双方每种条件各 3 个独立 fork，3×1s warmup、5×1s measurement，单线程。一次操作包括缓存建立、查询、消费和清空；1/2/4 为不同 GeometryKey 数量，并非同键 Base 重建命中。共 36 个有效 benchmark fork。下表是每组操作的平均微秒，负数表示候选减少耗时。

| 输入 | 体型数 | 基线 us/组 | 候选 us/组 | 变化 |
| --- | ---: | ---: | ---: | ---: |
| 普通平地，无 halo | 1 | 11.24 | 15.90 | +41.5% |
| 普通平地，无 halo | 2 | 23.33 | 19.13 | -18.0% |
| 普通平地，无 halo | 4 | 128.49 | 32.00 | -75.1% |
| 合成精确形状/halo | 1 | 83.61 | 22.41 | -73.2% |
| 合成精确形状/halo | 2 | 167.44 | 41.09 | -75.5% |
| 合成精确形状/halo | 4 | 385.03 | 101.82 | -73.6% |

合成输入的 26 个 halo 引用同一个不可变 facts，是复用压力上界，不是实服独立 section 对象分布。4 体型组还包含更宽、更高的视图，不能将其组耗时除以 4 就当成同一体型单次成本。行派生改成批量操作也会改变单次构建成本，全部减少不能归给跨体型共享；完整 Base 的每体型清空控制用于区分这两者。

## 完整 Base 与归因控制

同样的 3 fork、3×1s warmup、5×1s measurement，每组 1/2/4 个不同 GeometryKey，包含建立、查询、完整构图与清空。完整 Base 为 36 个 fork，归因控制另 6 个 fork；连同行阶段共 78 个有效 benchmark fork。重复 iteration 不计作独立 JVM。

| 输入 | 体型数 | 基线 us/组 | 候选 us/组 | 变化 |
| --- | ---: | ---: | ---: | ---: |
| 普通平地，无 halo | 1 | 43.35 | 47.96 | +10.6% |
| 普通平地，无 halo | 2 | 84.81 | 84.31 | -0.6%，接近持平 |
| 普通平地，无 halo | 4 | 265.52 | 195.32 | -26.4% |
| 合成精确形状/halo | 1 | 140.93 | 93.82 | -33.4% |
| 合成精确形状/halo | 2 | 253.19 | 143.81 | -43.2% |
| 合成精确形状/halo | 4 | 521.52 | 297.96 | -42.9% |

普通单体型三 fork 均值：基线 42.93/43.94/43.20us，候选 49.33/44.98/49.57us；两体型的 0.6% 差异小于本次 fork 波动，不算实质收益。普通四体型基线 269.11/265.09/262.37us，候选 190.03/199.03/196.89us。全部 fork 和 JMH 自带误差值均在 `local-results-v1.json`，表中比率是描述性平均，不是额外的显著性检验。

保持候选算法与位平面格式相同，只在每一种体型前清空缓存：

| 四体型输入 | 每体型重建行层 us/组 | 跨体型共享行层 us/组 | 留存复用相对变化 |
| --- | ---: | ---: | ---: |
| 普通平地 | 233.77 | 195.32 | -16.4% |
| 合成精确形状/halo | 349.46 | 297.96 | -14.7% |

这证明跨体型复用本身具有可测价值；不能把相对原基线的全部 26.4%/42.9% 记作共享层的收益。四种体型为 `.6×1.8`、`.9×1.4`、`1.2×2.2`、`2×2`，最后一种接受流体；不是测出任意四种实体都会得到同样收益，更没有测出一个普遍的“第几个消费者回本”阈值。

性能基线和候选都使用同一份冻结算法的共同测量壳，关闭工作计数、JFR 阶段和深度 profiler。原行循环抽取为可单独调用的真实内核，未另写简化算法；独立未改动生产类对照验证的是正确性。上述微秒不是原生产 jar 的服务器时延，不是 Minecraft 冷首次请求。

## JFR 与工作量

双方各 1 个诊断 JVM、8,000 次构建、48,000 个阶段事件；无 DataLoss、缺失 workId 或失败阶段。阶段覆盖 build、rows、erosion、components、edges、output，保存实际 ActiveSetting 和线程覆盖。原生计数只用于诊断，无深度插桩 JMH 不启用它。

每种输入为 1,000 组、每组 4 体型；以下是完整构图期间的计数，不是采样百分比：

| 输入 | 基线原始事实读取 | 候选原始事实读取 | 基线精确 occupied | 候选精确 occupied |
| --- | ---: | ---: | ---: | ---: |
| 普通平地 | 32,768,000 | 4,096,000 | 0 | 0 |
| 合成精确形状/halo | 41,919,000 | 6,379,000 | 2,167,000 | 2,167,000 |

普通输入每组原始解码从 32,768 格次降到 4,096 格次；精确碰撞没有被错误合并。两种输入各建立 256,000 行；普通输入累计命中 768,000 行，合成输入命中 2,378,000 行。命中包含同一构建内的行重复消费，尤其合成 halo，不能当作跨 GeometryKey 命中率。

JFR 诊断中 rows 阶段累计时长为基线 1,153.88ms、候选 313.48ms，侵蚀为 159.56/159.85ms。该轮带计数与追踪且没有独占整台主机，仅用于定位和机制解释，不作为净性能收益。build 是 inclusive 父阶段，不能与子阶段相加。主线程运行本离线内核，因此不存在 Minecraft worker/Server thread 覆盖声明。

GC 根暂停区间并集为 0/3.3296ms；2ms 门槛下没有记录到锁、park 或 IO 长事件，不代表这些成本绝对为零。分配直接用线程累计 allocated bytes 补证：两种输入各 1,000 组，基线/候选分别为普通 12,854,648/15,015,456B、合成 36,649,488/38,047,520B；属于诊断模式，不是对象留存或 JMH gc profiler 结果。

本机线程 CPU 时间最小正步进实测为 15,625,000ns，只报告批量 CPU，不认证微秒阶段 CPU。JFR 栈采样周期 10ms，短函数归因以阶段事件与工作计数补充。

## 留存

Instrumentation 按对象身份去重，填满 64 个条目：

| 口径 | 字节 |
| --- | ---: |
| 缓存容器与行数组，排除源 facts 闭包 | 138,216 |
| 加上缓存引用可达的源 facts/geometry 闭包 | 801,904 |
| clear 后仍保留的空容器 | 1,512 |

135KiB 左右只表示本候选容器与数组；缓存还会延长整个源事实的生命周期。801,904B 是本次平地源对象填满案例，不是复杂形状的通用上限，也不能与已有 graph 记账直接相加估算进程峰值。

## 执行记录与边界

历史清理已删原 city 路径，使用另一份存活的同源 fixture 并登记 SHA256；初始源转换定位串被守卫拒绝，修正后仍来自同一冻结源码。独立进程 v1 比较保留了签名与 JSON 顺序不稳定导致的失败输出，v2 的排除项和通过结果明确登记，没有将失败替换删除。

完整 Base 的前两次 JMH 启动被其他会话占用的全局锁拒绝，均未开始 fork/measurement，不进入性能分母。没有绕过锁或停止其他进程；后续等待其完整既定矩阵和安静间隔后运行，原条件保持不变。

Minecraft 冷首次请求、首 Path、自然到达、完整 tick 与实服复用率的本候选数据均为 0；普通单消费者成本门未通过，因此本轮止于局部验证，没有用大矩阵继续推进。开始时的冻结生产基线也不能自动代表另一会话后续优化完成后的代码。

## 研究决定

1. 保留“原始事实行可跨体型共享”的正确性和条件性收益证据，本轮没有验证完整合法性缓存或局部搜索消费者。
2. 停止推进当前通用首用即建缓存，不生产接入；不能将其称为普遍提速，也不能将整个技术方向称为无效。
3. 未来若重新考虑，只应先取得真实同源 facts 跨 GeometryKey 的重复消费、间隔、淘汰与留存数据，再决定是否为明确的多体型热点另立更窄方案。不要先扩大端到端矩阵，也不在本任务自动实施下一技术方向。
4. 本轮工具栈实际提供了“工作减少在哪里、精确判定是否保持、行阶段收益如何被完整构图稀释、共享自身贡献多少、额外留存多少”的证据；spark/WPR 没有被强行重复使用，JMH gc profiler 未在本轮执行，分配由 ThreadMXBean 诊断补证。

综合数据：`.tmp/intermediate-reuse-20261015/local-results-v1.json`；源码、类、JFR、输入与结果哈希：`evidence-manifest-v1.json`；逐次错误与锁等待：`setup-failures.json`、`jmh-lock-wait-v3.json`。
