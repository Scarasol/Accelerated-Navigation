# 节点支撑高度共享优化结果

日期：2026年10月9日（北京时间）  
范围：新工程隔离原型 `D:\Workspace\AcceleratedNavigation-forge-1.20.1`

## 结论

上一阶段的“单高度直接配对”已从当前方案回滚。它的历史文件和失败/回退结果仍保留，但不再作为下一阶段基线。当前基线只保留共享投影事件排序。

本阶段把每列每个水平片区重复扫描支撑 Box、创建 `TreeSet<Double>` 和高度流，改为每列建立一次支撑高度索引。修正排序索引错误后，所有受影响图关系和顺序对照通过，性能出现明显改善：

- 请求起点完整构图中位数下降 **10.5%**；
- 常规最重完整构图中位数下降 **26.0%**；
- 较大体型完整构图中位数下降 **32.7%**；
- 节点阶段分别下降 **55.2%、65.9%、76.6%**；
- 累计线程分配中位数分别下降 **20.9%、31.8%、43.5%**。

这仍然是隔离原型诊断，不是生产接入或正式验收。

## 优化内容

当前原型每个水平片区都重新扫描相关 Box、收集支撑高度、用 `TreeSet<Double>` 排序去重、创建高度 Axis，再用原 Mask 做精确碰撞判断。

候选实现每列只做一次：

- 用 `TreeMap<Double,Integer>` 按 `Double.compare` 建立唯一支撑高度；
- 为每个高度保存支撑 Box 位图；
- 每个水平片区仍用原 `horizontal` 谓词确认支撑；
- 用原 Mask 产生横向 Box 位图；
- 只遍历高度位图与横向位图相交的支撑高度；
- 继续调用原 `freeAt`、流体判断、节点发布、步行连接和跳跃连接。

没有改变 X/Z 分层、碰撞边界、流体、能力、方向、节点顺序、见证、组件或恢复树。VOLUME 路径保持原实现。

## 性能口径

每次数据都是**一个16×16×16格区段的完整构图**，包括索引、Mask编译、节点、步行/邻接、聚合和跳跃。阶段计时是 `build` 内部阶段值；完整构图总时间是从 `build` 进入到返回的墙钟时间。阶段中位数之和可能与总时间有少量差异，因为阶段计时有嵌套边界和计时开销。

Java 17.0.18、G1、初始堆128MiB、最大堆1GiB。两个变体同一 JVM 轮换执行：每个变体首次1次、预热8次、测量9次，三个代表共108次构图。没有 JFR、没有显式 GC、没有扣除 GC、没有挑选后段样本。

## 资格反馈和失败修复

新阶段完成7个代表图对照，覆盖无支撑列、同高多 Box、多高度薄墙、流体、三份既有代表和较大体型。节点、边/见证顺序、组件、出边、恢复树及非时间统计字段逐项一致。

第一次反馈发现了真实实现错误：`TreeMap` 的插入序被误用为高度序，导致真实输入的节点顺序改变。该失败保留；修正后重新编号为排序序，再次编译、反馈和性能运行均退出0。这个失败证明资格控制能够发现顺序错误。

报告读取器拒绝四类错误输入：缺阶段字段、缺轮次、错误变体身份和 `complete=false`。

- 还没有多 JVM 稳定性复测；
