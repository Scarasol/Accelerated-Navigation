# 目标组质量后继研究：条件式首段代表点

日期：2026-10-21，北京时间。
用户授权：继续研究方案，不急着验证。
本轮仅阅读有效历史、源码与互联网一手资料，形成方案并做方法审查；
不修改候选或生产源码，不构建、不跑fixture/回放/微基准/游戏。
方法审查中的建议和最终状态在文末记录，不把研究判断当性能结论。

## 一、继续探索什么，停止什么

目标仍是相对原生的实际到达增量尽量压到200ms以内。
生产S9L、调度基线B、工作计划起点B0和原生N0是不同参照。
本轮不新算一次性能比较，不把相对L8改善当作相对原生达标。

保留L8为研究起点，停止L8E和普遍best+1硬带。
不是继续调同一阈值，也不复活Q完整距离场/后缀传播/32格缩段。
优先解决“原生实际采用的点让后续多走”，不继续只优化排序速度。

已有证据：

| 历史发现 | 本轮约束 |
| --- | --- |
| 生产和L8都在自己的评分下完整选前八 | 再做同评分的精确top8不会改变目标组成 |
| 原生在八个备选中到达任一个，不遵从排序 | 留下差点只改顺序、给好点重复权重均不能解决问题 |
| 斜线采用第4/6名后，末段3→4节点，到达约晚239ms | 有必要研究减少同一简单通道内的冗余目标 |
| 墙体采用第8名，少partial却需继续走回最终目标 | “容易到达”和“后继好”存在真实冲突 |
| L8E在同range下仍恢复原六partial | 不能再假设缩目标、保宽range就足以保住原可达结果 |
| 台阶宏观等结构代价换边发生在选点之前 | 不把所有台阶差额当选点算法直接因果 |
| Q完整准备明显更重，模型也不同于原生 | 不把成员位图改造成另一套默认全图寻路 |

上述只复用已封存报告及坐标记录。原六条partial组与原六条到达不利组不同；
本轮没有新增样本、统计稳定性或对照矩阵。

## 二、核心判断

普遍性的“每个通道选一个好点”目前依据不足。
墙体的完整C是一条连续的16点边界，若按连通性把它归为一个通道，
再只保留评分最好的(-60,81,-128)，就会再次丢掉L8实际能到的(-64,81,-128)。
C/F只保存成员和已接受源端投影，不保存完整原生可达代价；
连通、距离近或局部邻居多都不足以证明两点能在本次原生预算内互换。

因此当前首选是**只在很窄的几何条件下减少冗余目标**：
其它请求完整沿用L8，而不是为所有地形强制设计一个新的通道划分器。
这是有边界的研究候选，只期望改善一部分简单斜线接续；
墙体、门口、复杂台阶及后来各段的问题暂由L8承接。

## 三、拟定方法A2：仅首段、同高无孔矩形

A2是本轮方法草案编号，不是历史生产版本或已构建候选。

### 1. 候选身份与执行边界

从原L8源码建立后继研究，不能以停止的L8E作为默认接入版。
复用“目标与范围必须分别说明”的认识，不继承L8E普遍过滤行为。

它仍属于**减少实际备选终点**的研究，不是假装已经消除了旧方法的全部风险：
L8E按评分带普遍删点；A2仅在下述窄条件下取既有首项，
否则完整保留L8。矩形/接口检查不提供缺失的原生信息，
因此即使方案逻辑闭合，仍可能在未来验证中失败。
这也不是把旧ray过滤、Q距离场或空间分散策略换名重新使用。

只有满足以下条件时，才考虑本请求首个double bank：

- L8原选择成功，模式为local；只有两条组件连接E=2。
- 仅正常cursor0、attempt0、failedTargets为空；不作用于恢复/final/shared/S回退。
- 原double bank超过一个目标；最多八点是上限，不要求凑足八个。
- 使用请求冻结起点r和冻结最终目标g；二者不冒充将来执行时的实际位置。
- channel为GROUND、`ceil(width)==1`、`ceil(height)==2`、
  `acceptsFluid=false`、`canOpenDoors=false`、`maxJump==0`；
  maxStep/maxDrop仍用原profile及连接规则，不按测试路线名开关。
  这不代表场景一定没有门或原生惩罚。
- 两条边均只有一个boundary band，为同高、单位水平距离、沿face法向的相邻变换；
  对Local、变高、跨跳、多变换等不确定情况直接保留L8。

E、cursor和profile限制用于避免后来预测入口及复杂移动的额外不确定性，
不是统一改成一连接，也不更改已有stride或四section规则。

### 2. 代表点与条件检查

先完整执行原L8，保留原全部banks及其比较顺序。
q直接取原首个double bank的第一项，不另做新的全C评分或二次选择。
q必须仍属于原接受C，且r、q、g同高、分别在对应冻结组件中。
明确要求`q∈originalFull8∩C1`，且q与范围参考来自同一份冻结首double bank，
不允许从另一种跨度或另一份选择记录拿首项来配范围。
本请求E=2，g明确是冻结最终目标，不是下一出口代表。
固定V0=edge0.from、V1=edge0.to=edge1.from、V2=edge1.to=finalDestination，
中间组件快照必须为同一份身份；不能泛指“本段里碰巧有的所有组件”。
编号明确为T0:V0→V1、T1:V1→V2；C0、C1分别为这两条连接原接受的目标端集合，
C0⊂V1、C1⊂V2；C1不是第四个组件。F0、F1为对应原接受源端投影。

在高度h建立包含r、q、g的闭合x/z轴对齐矩形R。
先以long计算边界，要求x/z两个方向的包含端点宽度均至少2格；
单行或单列直接保留L8，不将退化矩形当作二维空旷条件。
两个维度均不超过64格，矩形涉及section不超过原四section上界；
并且这些section必须全部属于V0/V1/V2所在section；若涉及第四个其它section，
在扫描前直接保留L8，不能向其它快照借行。
不满足先拒绝此优化，不为额外检查扩大原导航范围。
只用上面精确V0、V1、V2的冻结成员，不取全世界或其它走廊成员填洞。
覆盖条件只定义成一个可执行成员谓词：
对R的每一个整数z，该行完整[xmin,xmax]都属于V0∪V1∪V2在h层的成员。
任何缺失行、其它组件填入的格子或未覆盖bit都不满足条件。
不额外声称该检查证明“通道连通”，也不暗含BFS或floodfill。
检查使用16位行掩码覆盖/包含关系，不扫描实体、方块状态或主线程世界。

**仅检查两侧站位存在还不够。**
矩形跨越的两个section接口还须与原接受boundary变换、原C掩码一致，
保证检查没有凭成员并集补出本次连接未接受的跨界边。
在唯一单位水平变换下，从目标端反推唯一源端；
每个被R触及的跨界位置必须同时存在于该边原C和对应源端F。

精确定义每个接口的几何平面P_i和有向单位法向d_i：
X_i包含R内所有`s,t=s+d_i`、且s/t均在R内并跨越P_i的格对。
这里先按**整个平面与R**定义，不预先删掉位于有限16格共享面之外的格对。
切向跨度可以达到64，先算完整`|X_i|`；
若为0或超过16，直接保留L8，不截断检查。只有1–16对时才检查全部格对，
两个接口合计至多32对。
每对都核对s/t所在section/组件、s∈F_i、t∈C_i和唯一band变换；
面外或缺失任一格对即保留L8，不能静默略过后称覆盖完整。
此外`(q-d_1,q)`必须明确属于X_1并通过检查；
其源端在R外、未枚举或映射不唯一时保留L8。
不为支持更复杂变换新增全量(from,to)配对。
缺必要输入或无法以小成本完成接口核对，保留完整L8。

另在每个共享面h层完整16位置上，核对源端F行按唯一单位变换平移后
与目标端C行完全一致且一一对应；错层、面外、多义或不等均保留L8。
这项另计最多32位置的工作，不与R内最多32格对混为一次计费。
原prepareConnection在同一接受分支同时记录F和C，是该关系的数据来源；
不把没有配对的任意投影集合普遍当成边集合。

这只是**结构上的无孔矩形条件**，不是原生碰撞、惩罚、门、节点上限、
可达性或最短路证明。位图不提供完整原生移动边或costMalus，
不能把这些缺失信息通过“认证”两个字补出来。
冻结起点与实际执行起点可能有偏移，世界也可能变化；
原生命周期及原生实际搜索仍是最终裁决。

### 3. 发布什么

条件通过：worker准备单个q的可选正常首试目标集合。
条件不通过、未知或超成本界：直接发布完整原L8前八，内容/顺序保持。
不输出UNAVAILABLE，不给原生增加一次试探，不先搜一个再另搜八个。

**新增且明确计费的一项主线程条件**：真正开始native搜索时，
比较实体当前方块坐标是否等于冻结r；不相等则消费已经冻结的完整L8集合。
这是一次O(1)坐标相等检查和预制结果分支，不计算新点、不排序、
不重新跑矩形检查、不提交worker或另行排队，也不做泛化前驱匹配。
它是相对旧候选新增的控制成本，不能声称主线程完全没有新工作。
这里的保留边界是“无主线程重新选举目标”；不是拿该检查重新启动完整选点。
相等仅指方块坐标；实体在格内的连续位置和原生evaluator实际起点仍可能不同，
不把这项O(1)检查扩大解释为原生搜索输入完全相同。

保留完整L8首double bank作为独立range参考，仍在实际执行位置计算：

```text
range = clamp(max_distance(actualStart, originalL8Bank) + 8, 16, 96)
```

因此减少目标不缩小首试range；也不扩大原L8正常范围。
冻结的是完整range参考集合和原公式，**不在worker按r冻结一个数值range**。
await暂停续行必须保存同一份选择记录；恢复到真正搜索时再次做上述坐标相等检查，
不重新做几何准备。`work.segmentTargets`等记录须与实际采用的集合一致，
不能残留暂停前的单点身份。
原失败恢复仍用原恢复目标及原范围规则，没有第二套策略。

坐标不等或几何不适用时回到L8，只适用于请求及其资源仍有效的情况。
取消、stale、owner/profile/version无效必须走原失效/重规划/清理流程，
**不得用同一份已经失效的数据回退L8**。
原发布、live检查和原生能力校验保持；不新增逐行完整身份检查链。

q本来就是L8首项，因此已有预测入口引导不变；
E=2且只改首double bank，也不需要让后续bank沿一个新入口重新生成。
其它所有bank与原L8相同，不为未消费的bank增加成对元数据。
最多只在适用请求持有一个可选不可变单点Set；其余直接复用原Set。

### 4. 数据结构与成本

现有`ComponentSnapshot`只公开`contains(BlockPos)`，没有免费可用的行接口。
若未来实施，需要新增包内只读primitive行访问，例如按本地y/z取16位x行；
不暴露可变64long数组，不复制256/4096格平面，不追加共享缓存。
GroundRouteData内已有profile，可在其内部计算准入条件，不向主线程读取世界。
旧C的rows/occupied仍按原含义使用，不能把其存储轴误当固定x轴。

成本上界应覆盖：

- E!=2等快速拒绝，以及原L8完整选举本身；不能只计通过的请求。
- 最多64个全局z行、最多四section切片，共至多256次矩形成员行核对。
- 两个接口各最多16个横向位置对应的掩码核对，另计至多32次行/掩码工作。
  每个位置都要核对目标C和源端F，不把它算成一次免费查询。
  这一上界来自明确的`|X_i|>16`拒绝规则，不从64格矩形宽度凭空推出。
  坐标转换、profile/边描述读取、最多三个组件的查找及取消检查另外计入；
  上述数量是数据检查上界，不是总CPU指令数，也不是O(1)完整选举。
- 两个共享面完整行映射另计至多32位置的C/F核对，
  不把它隐藏在上述R内格对成本之外。
- 至多一个额外单点Set和一个可选字段；不为每bank分配一套目标/范围记录。
- native实际派发及await后的一次坐标相等检查，和消费预存完整集合的分支成本。
- 坐标界限计算用long，超界/缺失保留L8；64/四section只是额外检查上界，
  不改变原导航业务允许的请求距离。
- 每行取消检查及原发布校验；取消按原异常传播，不转L8/S回退，
  不再逐点反复走完整身份/预算检查链。

旧L8选举O(N)成本仍然存在，本方案不是更快的top8实现。
矩形检查、额外捕获及失败回到L8的全部成本都属于前置准备和直接影响范围。
E=39等长走廊额外条件应立即不适用，不复制Q的全程传播成本。

### 5. 未来改动位置与兼容

拟需的范围是GroundRouteData中的条件检查、ComponentSnapshot只读行接口、
PreparedGroundRoute的可选首段覆盖结果及Service的双用途参数传递。
原LocalTargetSelector评分/完整前八可以保持，避免另造一个评分体系。
这些只是实施定位，本轮源码修改为0。

不另做F的全局连通区间聚类：单一变换下，本矩形所需的原C/F跨界覆盖
已经明确检查，F其它地方存在另一个区间并不等于本矩形不能使用。
强求整个F只有一个区间可能增加假阴性，且不能补出原生approach代价。
这与按C连续段直接删点是不同的准入条件；也不将F投影称为native通道证明。

Service不能重复L8E的同名重载探针兼容问题：
保留旧工具实际识别的搜索方法名称，给三参数转发使用独立名称；
实际native调用次数、原探针计数/范围/目标记录保持。
是否采用该组织在未来代码审查中核对，不为候选先改测试工具。

## 四、文献与互联网项目的取舍

本轮查阅一手论文页面、作者文章和项目官方文档。
只借鉴适用原则，不引用其它项目加速比推定本项目收益。

| 来源 | 本轮可借鉴 | 不直接采用的原因 |
| --- | --- | --- |
| Portal-Based True-Distance Heuristics，SOCS2010 | 门户后续成本确实应纳入目标质量 | 其真距离与A*配套；本项目没有免费真距离，不重建Q |
| Harabor作者的HAA*/true-clearance说明 | 代表点与通行能力应结合，不能只看中心位置 | 完备性依赖其图与clearance模型，不能移植成成员位图的原生证明 |
| Recast官方dtPathCorridor / dtNavMeshQuery | 几何捷径应建立在可查询的通行走廊及过滤条件上 | 本项目不是凸导航网格，位图直线检查不能直接替代navmesh raycast |
| Polyanya，IJCAI2017 | 区间/门户整体处理可避免过早固定任意点 | 其凸多边形网格前提不成立，本轮不改原生搜索 |
| String Pulling，SOCS2020 | 空旷区域的额外转向确有独立处理思路 | 路径后处理不等于首次终点选举，不纳入本轮 |

比较结论：

1. 通道连通分组/中心/端点分散：保留研究记录，目前不作为首选。
   连续C不等于原生同样容易到达；墙体反例不能靠换分组名称解决。
2. Pareto、改变权重、直接更换欧氏/八方向距离：几何代价并不是真实前后缀，
   不能据此安全剪除原生可达备选；保留八点时又可能完全不改变实际终点。
3. 条件式首段代表点：当前最窄可讨论方案；有明确不适用路径和额外成本，
   无普遍收益、原生可达或200ms保证。
4. 带终端代价的虚拟终点搜索：能在目标函数层面表达后继代价，
   但须修改原生A*目标终止和启发/预算语义，超出现有保留边界。
   不把这项偷偷塞进选点器，不以本轮研究作为其实施授权。
