## 1. 目标与方法选择

同时处理两个问题：

1. 降低一次详细搜索的邻接查询、重复方块判断和队列操作成本。
2. 避免搜索为了尽快碰到一个交接点，把过多行走代价留给下一段。

推荐内核是多目标 Weighted A*，起始权重沿用 1.5；
在满足精确条件的平地增加可以展开为原生普通步子的长边。
复杂位置仍采用原生 WalkNodeEvaluator 的实际邻接规则。
终点附带后续代价，作为独立的第二阶段变化。

这是一套待验证的组合方案，不是一个已被论文证明适用于 Minecraft 的现成算法。
原生本身已经有 1.5 倍启发式权重，收益假设来自降低询点和展开成本、
复用同一派发内重复访问的静态事实，以及改变目标决策，而不是加权这个名称。

不直接使用全局 JPS 剪枝。JPS 原论文针对均匀代价栅格；
本项目含有向跳落、台阶、地形惩罚、门及 Forge 路径类型钩子。
本候选只借鉴“用长边压缩连续普通步子”的思想，保留普通邻接，
不借用 JPS 的完整性、最优性或性能倍数结论。

## 2. 当前代码给予的边界

- ComponentSnapshot 是组件成员快照，不是原生完整移动图。
- BoundaryTransition 有方向、位移和空间掩码，可以提示入口、出口和结构变化位置。
- 原生 WalkNodeEvaluator 已有每次搜索的路径类型缓存和碰撞缓存。
  不能把再加一层相同的查询内缓存描述成新收益。
- 原生 getNeighbors 返回值已经受本请求 Node.closed 影响；
  部分碰撞与铁路判断还依赖实际 Mob 的起点和身体。
  不能把整个 Node[] 当作跨实体可共享的邻接缓存。
- NavigationCapabilities 包含实际尺寸、步高、落差、门/流体等能力及 malus；
  宏观 TraversalProfile 不足以单独识别详细规则等价。
- 完成宏观结果的成员快照可能早于当前世界。其版本不能认证新的详细移动边。
- 新后端必须显式承接 avoided-node 过滤、prepare/done、profiler、未知区块和
  NativeQueryProof 等原有责任，不能因跳过旧搜索循环而绕掉现有 Mixin 钩子。

## 3. 搜索实际接收什么

每段一次性接收：

- 实际请求、真实起点、原最多八个交接目标、accuracy、range、visited multiplier。
- 已有宏观走廊、组件成员快照和边界转换，均只作为结构提示。
- 原有能力快照、失败节点回避和生命周期身份。
- 第二阶段增加最多八个 float 后续代价，与该段现有 worker 准备同次计算、同次交付。
  不为这些值新建任务，不新加 worker 往返，也不预先构建全走廊距离场。

目标数、默认分段跨度和搜索范围不随本方案增加。
同步查询、POI/AI 决策及未支持的导航继续现有真实原生查询；
第一候选只研究地面分段移动后端。
这是对旧“分段移动也必须使用原生搜索循环”契约的明确研究提案，
不是冒称旧契约已经允许替换所有消费者。

## 4. 如何询点

### 4.1 起点和普通邻点

起点仍由实际实体的原生 getStart 生成，不把成员位图中的任意一位当起点。

没有可复用记录时，调用原生 getNeighbors，保留它的：

- 水平四向及对角移动条件。
- 上台阶、下落、门、流体、危险类型、碰撞及地形惩罚。
- 本请求的 closed 状态、失败节点回避和范围条件。

不先按宏观位图裁掉原生邻居。宏观成员缺失只意味着不能采用该提示或快速方法，
不能据此宣布真实详细节点不可走。

### 4.2 同次派发共享的普通平地记录

仅对已经通过精确条件的普通平地，缓存无搜索状态的只读记录：

- 哪些同高方向已经确认可以移动。
- 直移代价 1、对角代价 sqrt(2)，并且相关原生 malus 为 0。
- 所依赖的当前详细世界输入身份。

首次搜索仍支付真实原生判断。记录从这次判断中产生；
未知格不为准备长边而额外扫描。后续搜索命中时，把只读记录映射成本请求自己的 Node，
再应用本请求 closed、g、parent、avoided 及范围条件。
不共享 Node、堆、parent、Path，也不共享实体相关碰撞结果。

记录位置必须在原生 findAcceptedNode 产生几何候选之后、
isNeighborValid/isDiagonalValid 应用本请求 closed 之前。
先捕获四个正交和四个对角的候选坐标、类型及代价，再对下面支持的平地子集
计算不含搜索状态的方向位。不能从最终返回数组中把“因 closed 被省略”
误记成几何阻塞，也不能临时清空原 Node.closed 再调用一次原生。
复杂分支没有足够信息时整条记录不进入快速方法。

进入该快速方法要求：

- 原生地面 evaluator 与支持的能力组合。
- 同高完整支撑、足够身体空间及已确认的对角规则。
- 相关方块和邻近危险检查属于已支持、无动态上下文的规则。
- 不涉及门、铁路、流体、特殊碰撞、危险惩罚或未知的第三方规则改写。

“WALKABLE”、同一组件、两侧站位存在均不是充分条件。
实施前须把原生相关分支逐项对应成明确条件；无法证明等价的分支保持原生询点，
不以缓存命中率目标放宽条件。

缓存初版只活在一次 drain 内，不跨 tick 保活，不新增常驻共享详细图。
按当前维度、详细能力身份、实际读取域/依赖及位置识别；
不能仅按坐标或宏观 profile 复用。
读取域含缺失/区域外区块的差异，不能从另一份更大原生 region 借出本次区域外事实。

实际详细输入发生变化时，失效的是这份临时查询记录，
不是已经交付执行的宏观走廊。
块状态、区块身份或其它相关输入变化时清理受影响记录；
依赖没有完整跟踪、包含动态钩子或依赖实体上下文的判断不入共享记录。
直接 section 写入和原有 chunk 写入的变更覆盖需要核对，不能仅假设宏观修订号足够。

缓存按整个 drain 合计限制为最多 16 个“section 与能力”项，
达到容量后直接调用原生，不拒绝请求、不驱逐后重新全量构建。
基础已知位图和八方向字节约每项 5 KiB，另计依赖/映射/对象开销；
实施中若还需额外字段，必须列出实际字节，不能沿用这个基础估值冒充总量。

### 4.3 精确长边

一个方向上连续多步都是当前已知、同高、零惩罚的普通移动时，
增加一条从头到尾的长边，代价等于这些原生单步代价的和。

每个扩展点保留原普通邻接，另外最多生成八个方向各一条长边。
遇到未知记录、复杂移动、离开可复用读取域、range/累计行程边界时停止延伸。
长度不足两步不生成长边。
可在目标、目标精度边界或宏观边界提示附近提前结束长边；
这些是候选端点，不能凭提示直接批准中间步骤。
同一方向存在多个提示时只选一个端点，不枚举整条射线的所有位置入堆。

对角移动必须逐步满足原生的两侧正交约束，不能穿墙角。
路径经过 avoided 格时长边在其前停止，不能只检查长边末端。

水平连续段可按 16 位行掩码寻找首个不满足位置；
跨 word/section 的成本按读取字数计。
对角段初版逐行做位判断，成本为 O(长度)，不声称 O(1) 找出整条路径。
所有方向总探测长度受本次原 range 和单段累计行程约束，不另给更大范围。
未知方向立即停止，不为一条潜在长边调用若干次原生询点来“预热”。

父边记录方向和长度，最终恢复 Path 时展开成真实逐格节点；
不要求原版导航执行一条未经适配的大跨度跳跃。
恢复节点、类型填充和 Node 分配的成本仍计入搜索，不能只报告压缩堆的成本。

这可能减少出入堆和原生询点，不保证每张地图都少展开节点。
原普通邻接保留时，一部分中间节点仍可能展开；没有取得 JPS 的整段剪枝收益保证。
在无限制静态图上，只添加与原步子等价的边不会删除原来的路线；
在实际有限节点数、浮点计算及改变搜索顺序后，不能据此承诺原成功率完全不变。

## 5. 主算法和目标质量

第一阶段后续代价全部为 0，使用多目标 Weighted A*：

```text
h(n) = min distance(n, target_i)
f(n) = g(n) + 1.5 * h(n)
```

普通边沿用原生距离加 costMalus。长边使用已确认的逐步代价之和。
首先让新循环在不改变目标质量意图时接受核验。
所有 q_i=0 时保留到达任一原目标即结束，不额外创建虚拟终点堆项。
这不是承诺返回和原生逐节点完全相同的 Path；
同分次序、长边和浮点累加本身都可能改变实际选择。

第二阶段给每个目标一个非负终端代价：

```text
r_i = EuclideanDistance(target_i, finalGoal)
q_i = r_i - min(r_j)
```

这些值只对当前原目标组计算；最多八点，不扫全图。
这是最轻量的几何后续估计，不是真实绕行、上下楼路程。
减去共同最小值不改变当前组的目标比较，只去掉公共常量。
最后段或没有完整代价输入时统一 q_i=0。

构造一个概念上的虚拟终点，每个真实目标以 q_i 为边代价连接它：

```text
real-node heuristic: h(n) = min(distance(n, target_i) + q_i)
real-node priority:  f(n) = g(n) + 1.5 * h(n)
virtual goal cost:   C = g(reachedTarget_i) + q_i
```

虚拟终点不进入实体 Path，不需要实际世界节点。
到达真实目标时更新最好的完整候选及其真实父链，
将这个 C 作为虚拟终点的队列项；虚拟终点按本算法的队列规则取出时结束，
不做“搜到第一个就停”，也不在首条结果后另开一场寻路。
在候选质量模式中允许从真实目标继续扩展，以比较另一个目标。

第二阶段初版仅作用于 accuracy=0 的中间交接段；
accuracy>0 的目标集合继续 q_i=0，沿用原生 Manhattan 精度判定。
不能把某个目标中心的代价随意套到整个精度球，破坏停止规则。

达到既有工作上限后，有已经到达的候选就返回其中最好的；
没有则保留原生 partial 的区别和原失败恢复，不伪造 canReach。
不会为了补一个更低代价目标增加一次重新入队或自动扩额度。

初版沿用原 Node 的请求内状态和现有二叉堆风格，
不同时引入多堆 MHA*、新堆结构及新的通用内存池。
原 evaluator 会过滤 closed 节点，新循环必须明确沿用或完整改造这项约定，
不能声称写了一句 reopen 就能重新得到全部原生邻接。

1.5 是起始实验参数，不声称本实现有全局 1.5 最优性保证：
实际有节点/range 上限、原生状态约定、partial 和后续估计误差。
几何后续估计错误或继续搜索成本过高，都可能使第二阶段不值得保留。

## 6. 主线程、worker 和实现位置

worker 继续现有宏观和段准备职责，只随既有结果交付目标/代价及已有掩码引用。
不读取真实 Mob/世界来替主线程生成所谓精确原生邻接。
宏观掩码可提示快方法的机会，不能免掉当前详细语义条件。
未来若加入新预计算字段，其采集、worker、分配成本必须单列；
本方案初版不要求扫描四个 section 来创建新完整图。

详细搜索仍在主线程一次执行。初版不引入跨 tick 保存 live evaluator 的新问题，
不新增“窗口准备好后再排一次只为选点”的阶段。
初版也不通过对每个节点重跑完整请求身份/版本/预算链来控制自己。
生命周期在原入口、发布和必要失效点维持原保护；内部只做实际需要的轻量条件。

建议保持 PathFinder 外层 findPath 调用边界，在有明确候选 Scope 的地面分段请求中
替换内部搜索循环。保留原 region、prepare、getStart、getGoal、done 和外层计量。
新循环直接调用的邻接适配器必须显式应用原 failed-node 过滤，
并处理旧内部 profiler 钩子因循环替换不再执行的差异。
未选择该后端的调用仍运行原生循环。

这样有机会沿用原搜索计量入口，但必须核实原探针的实际匹配方法；
不能仅因为仍调用 PathFinder 就假定计数自动对齐。
新后端还需明确自己的 generated/expanded、原生询点和长边探测计数，
不能把原生询点调用下降冒称详细搜索调用下降。

不修改 U 的提交/唤醒语义、不恢复预算、不改原 8/28 场景或分段跨度。
生产 P、原脏改和默认 JAR 保持。

## 7. 成本账与停止条件

新增成本全部包括：

- 临时记录的资格判断、能力/读取域识别、查表、失效及清理。
- 长边探测、额外入堆和实际 Path 展开。
- worker 侧最多八个后续估计及其交付。
- 每次节点启发式的最多八项比较，以及首个目标后继续搜索。
- 替换后端后仍需进行的原生 prepare/done、proof 和发布。

当前原生每个展开节点本来就要与目标组比较；
新的终端代价只增加其中少量标量工作，但“首个目标后继续展开”可能是明显新增成本。
不能据最多八个 float 就把整个质量变化称为 O(1) 无成本。

现有 U 的 77–117ms drain 不是单次 A* 计时。
本方案要减少其中的详细工作，但必须分清详细循环、外层准备/校验/发布等成本，
不能承诺通过替换内核消除全部派发峰值，也不据旧 I/I2 profile 归因 U。

第一阶段若冷启动认证/查表比节省的询点更贵，或者记录命中率低、
长边新增队列操作导致总主线程成本上升，就停止相应快速方法。
不能用提高命中率为由扩大静态规则白名单而没有等价证明。

第二阶段若额外展开增加主线程成本，却没有有意义的同路线到达改善，
则保留第一阶段可接受部分，停止终端代价。
不强求把两项捆成一个必须成功的大候选。

## 8. 未来核验顺序

本轮不执行下列检查。以后实施时分层组织，不自动扩游戏矩阵：

1. 询点适配与原生规则对齐：方向、高度、malus、对角、closed/avoided、
   精度、range/累计行程、未知块和清理。
2. 必要新增检查：长边逐步展开等价、缓存能力/读取域隔离、变更失效、
   内存上限、普通路线保留及终端代价停止规则。
3. 先验证第一阶段 q_i=0 的成本，再独立开启第二阶段质量变化。
4. 沿用有效历史的原接口、场景、参数、工具与计量。
   U 为同调度母版对照，P/N 为生产和原生背景，不重跑有效历史。
   只有原探针对新后端确实漏计时才做必需观测适配，并记录原历史仍可比的字段。
5. 按用户既定分工，方法审查与代码/数据审查分别使用对应 provider；
   本方案没有新的 DeepSeek 判词，不沿用旧 A2 审查作为通过凭据。

冷启动与共享后的成本分别保留。不能只报告命中时，也不能为了显示收益
改变多实体路线复用、预热时长或请求顺序。
若需要新阶段的干净游戏数据，必须说明缺失或失效的具体字段，
不能仅为了新配对而补跑整套基线。
