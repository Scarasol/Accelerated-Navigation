## 问题和目标

当前普通宏观路线的首段：

```text
宏观交付 -> queue(nextSegment)
  -> final: queue(findSegment)
  -> 中间窗口: worker 准备 -> 主线程交付 -> queue(findSegment)
```

成功中间段：

```text
真实 Path 耗尽 -> 原稳定观察 -> queue(settle)
  -> 原物理交接通过 -> queue(nextSegment) -> 上述准备/搜索
```

这些任务可能同 tick 连续完成；减少一次入队不等于节省一个 tick。
历史 47 个后继窗口本已同 tick 接搜，准备到搜索最大约 1.8371 ms；
不能由此承诺省掉约 300 ms。8 格平地还存在只有一次真实搜索的路线，
段间优化无法解释其全部到达差额。

目标仍是相对原生的**实际到达增量不超过 200 ms**。
首 Path、首次移动和请求终态是辅助指标，不替代实际到达。
原生长提交 tick 后的追赶节拍可能混杂结果，作为待验证解释保留；
失败路线分母和两种计时起点均保留。

## 选定的方法

将正常交接、当前段准备和一次真实搜索合为一个正式调度的 `StageTask`。
正常中间窗口不再提交 worker，而在主线程从已提交 corridor 的快照可续行生成。
“同步”指执行线程，不表示必须整段不可中断完成。

合并采用两次审查提出的：

1. 每小批检查准入、可暂停继续的准备。
2. 保留完整、有序、去重后的正常候选基。
3. 真正搜索时，从全量候选精确选择 top8。
4. 正常成功路径不提前展开恢复邻域。

比较后未选：

- 整段原子枚举：实现简单，但准备可能独占主线程，取消和预算响应差。
- 只保留 top8、等待后重枚举：位置变化后旧 top8 之外的点可能变优；
  精确性要求重新全量枚举，增加重复工作。
- 全量排序：作为等价性 oracle，候选使用容量 8 最大堆降低选择成本。
- 提前完整恢复表：正常成功路径仍支付邻域展开和集合分配。
- 预登记占号、队首插入、预测起点完整 Path、下一段预搜和窗口模板预取：
  不属于本轮，不用它们填补尚未证明的收益。

## 适用范围

仅已 adopted、静态目标、普通 corridor、attempt 0 的正常执行：

- INITIAL：无历史已发布段、真实搜索、恢复或重规划。
- HANDOFF：当前非 final、reachable 的真实 Path 正常耗尽，
  保留原稳定、physical 和 intermediateArrival 判断。

动态目标、shared、preview、未 adopted 决策、partial、原生停止、
恢复和重规划走原入口；不适用不能变成导航拒绝。
任务执行时允许自身 `running`，其他 pending/preparing/followup 仍需排除。

不删真实末节点，不提前跳段，不增加固定等待。
`stable >= 3`、onGround、加载、身体碰撞和支撑沿用原逻辑；
目的组件经过记录仍绑定原 request/publication/window/component/proof 身份。
不对 adopted 路线新增 `proof.current()`。

## 准备、选择和提交

每个 Work 至多一个活动阶段。冻结 request/control/stage 代次、
corridor 对象、旧 cursor/stageEnd/publication/window/proof 和起始 tick。
HANDOFF 准备期间只保存拟执行的新 cursor，不提前修改全局状态。

窗口仅枚举当前段最后一条 edge：

- Boundary 保持 band、256 bit 和原坐标映射顺序。
- 其他保持 4096 source cell、四向和 drop/step 顺序。
- 仍用原 `LinkedHashSet` 去重顺序及最多四 section 上限。
- 每批最多八个 bit 或 source cell；profile 的既有规范构造限制
  maxStep 为 0–1、maxDrop 为 0–4，因此单 cell 至多 24 次邻居检查。
- 有机会就同次派发继续，不每八项强制重新排队。
- 机会用完保存游标；未完成窗口不得发布。
- final 段不建窗口；原最终组件查找也每八 endpoint 设检查点。

只在枚举完整后冻结正常候选列表。成员和 transition 都来自同一 corridor；
不按旧 componentId 查询当前图，不读取新地形重新构图或增加通行资格过滤。

目标选择保留原表达式：

```java
p.distSqr(actual) + .05 * p.distSqr(finalTarget)
```

再按 X、Y、Z 比较，容量八的最大堆扫描全量候选，
最后排序最多八项；结果必须与旧全量 sort/take8 完全相同。
每八候选检查准入；跨派发实际 BlockPos 变化时清堆，
从保留的全量候选重选，不重新枚举窗口，也不只重排旧 top8。
选择器一阶段一实例，冻结失败集合；
HANDOFF 使用原 settle 清理后的空失败集合语义。

完成准备后、原生启动前、发布前复查阶段身份、能力、停止、取消、
TTL 和 server/level 生命周期。HANDOFF 在提交前重放原物理交接。
canUpdatePath 为假沿原等待；恢复可更新时重新排队、复查和选择。

获准后同一有限主线程启动序列：
成功交接计数和 cursor 只推进一次，关旧窗，显式 `takeResult` 移交新窗，
设置本段状态，调用一次原生搜索并按原规则发布。
未获准保留准备结果，完成后普通新排；不借用旧派发机会。

## 调度与预算

沿用 `(dimension, queryId)`、priority、老化和维度轮转。
依赖就绪才提交，不提前占号、不插队。
同步原生搜索只在正式调度任务内，不能在宏观回调、observe 或 worker 调用。

调度器在 `search.step` 周围保存当前 request、外层 schedulerDeadline、
haveTime、常规/idle 模式和本次是否已认领真实搜索机会。
不能误用 1 ms cooperative slice deadline。

- 常规 END：准备批前检查正余额、实际截止、实时 haveTime；
  原生启动保持原 500 μs 余额门槛。
- idle：只原 43 ms 绝对启动截止、实时 haveTime、生命周期，
  不因余额为零或负数阻止，不加 500 μs 墙钟提前量。
- 每次派发最多一次真实搜索，claim 后不继续准备。
- 预算、截止不足时不启动新批或新搜索；已启动有限批或原生搜索
  可以截止后返回，完整记账并停止后续，不宣称硬实时零越过。
- 原 `account` 的 activeElapsed 即时反映当前开销，不重复计费。
- running 期间只设唯一 followup，旧任务移出 pending、future 完成后才新 submit；
  不能直接 submit 同 key 误取消当前任务。

首审曾要求任何 chunk 越过截止都判失败，复审已明确撤回该硬实时要求，
接受“启动门 + 全额记账 + 停止后续”的现行软预算口径。

## 恢复、关闭和异常

新窗保留原始有序正常候选为恢复基。
首次结构上需要时才按原曼哈顿不超过二的 XZ 邻域、
同一成员快照和 `LinkedHashSet` 顺序可续行生成；完整才缓存。
关闭、取消或失效后不得启动新生成；已缓存不可变列表关闭后仍可读取，
保留旧契约。

实际原恢复代码会增加 attempt/调整 stride，然后关闭旧窗并重新建窗。
本轮实际恢复仍走该旧异步入口；
新惰性生成器的结构验证不能冒充实际游戏恢复分支命中。
真实失败后下一次搜索重新排队，原重选、缩段和一次刷新上限不变。

取消、替换、重规划、TTL、能力失效、停止或关闭服务时失效阶段代次，
释放未移交的新窗、checkpoint、选择堆和候选，清唯一 pending/followup/waiting。
续行回调必须先核对 `work.stage == this` 和阶段代次，再处理 live 或 TTL；
已失效旧阶段的过期回调不得结束同一 Work 的新规划。
这条组合边界由生命周期代码审查发现，V4已修复并完成实际重规划后的迟到回归。
已经移交 Work 的窗口不能由准备对象再次关闭。
旧异步迟到窗口继续按原身份核验和关闭。
异常使任务失败并由原完成链 finish 清理，不捕获后续用缺口进度。

改块或后图 revision 不撤销已提交 corridor。
每次真实 PathFinder 仍使用当时实体、当前世界和原参数；
真实搜索或已发布 Path 执行失败才走原有限恢复。

## 验证门与数据复用

先核对历史数据版本、工具、场景、参数、接口和计量；
有效 S9L、2026-10-19历史调度基线 B、原生 N0 直接复用，不重跑基线凑配对。
候选净测仍只一个 JVM、原 burst warmup8/warmup28 各 64 实体，
原 2 GiB/G1、速度 II、30 秒就绪、NoTrace 和相同工具字节。
8 与 28 分别并发，不是 128 同时并发。

先做代码审核、等价性和机制控制，再准入候选净测：

- 旧 26 fixture 全序列；新同步路径对应的 20 个普通 fixture
  全候选、恢复候选和关闭契约逐项等价；
  另外六个 reach fixture 继续旧接口。
- top8 与旧 full-sort oracle 等价，含过滤、并列、负坐标、
  0/1/7/8/9/大于八、暂停和位置变化。
- 准备/恢复 checkpoint 暂停取消，显式窗口所有权转移。
- 原生命周期、改块、预算耗尽、等待恢复/取消控制；
  新派发门的真实 scheduler 假钟控制、负余额 idle、精确截止、
  即时计费、同 key 完成后续行和单派发最多一搜。
- 先证明 INITIAL、有窗口和 HANDOFF 实际命中；
  必要时复用原 304 格单实体场景作机制诊断，不增加性能矩阵。

直接影响窗从宏观交付/原 observe 决定提交阶段起，
到下个真实 Path 发布、失败或取消结束，
含准备、续行、枚举、选择、排队、搜索、清理和实际触及的恢复。
窗外不展开间接归因。报告所有不利值、成功分母、
CPU/分配、首 Path、首移动、实际到达和终态两种起点。

方案通过不代表代码审核通过；功能通过也不代表新分支命中，
更不代表 200 ms 或生产条件达标。
若直接影响窗无有意义收益，停止扩大，不靠改计时起点、
放宽物理条件、抢队、加预算或预测搜索取得更好数字。
