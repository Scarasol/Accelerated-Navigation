# 宏观寻路内准备与选点的完整修订方案

日期：2026-10-21，北京时间。版本：V5，首审后完整范围修订。
状态：官方 max 复审 ACCEPT_WITH_GATES、无必改项；隔离实现 v5 的四包代码复审均通过。
构建、选择器、有限运行时/主线程控制与本轮原场景游戏核验已完成；
数据复审 ACCEPT_SCOPED，性能尚不支持接入，候选保留隔离。
最新证据与未通过的门见[隔离核验报告](../reports/2026-10-21-macro-prepared-segment-isolated-verification-zh.md)。
本文替代 V3 selector-only，作为当前方案入口。
旧 V3 及其 ACCEPT_SCOPED 原文保留为历史证据，批准范围不能转移到本文。

## 一、目标和此前遗漏

主目标始终是相对原生的实际到达增量尽量全部压到 200 ms 以内。
首 Path、详细寻路完成和请求终态分别报告，不能替换实际到达目标。
本案同时消除正常执行中的重复准备往返和降低选点成本，
不能再以“仅替换选择器”代替完整方案。

此前 V3 有两项范围错误：

1. 保留了“宏观返回主线程，再提交 worker 准备，返回后再排详细寻路”，
   没有解决用户要求的排队合并。
2. 把用户允许的“合法、质量足够，可以不是最优”升级成
   “每次按实时位置保持原最优八点”，因此又引出主线程重新选点。
   新方案取消这项自行增加的要求。

正常路径由宏观 worker 一次完成候选准备和本次规划使用的选点；
主线程使用已经选定的最多八点，不因实体正常移动再选一次。
只有实际寻路失败、原有重规划条件成立或请求被替换等情况下重新处理。
读取已经选好的点是 O(1) 读取，绝不能把它称为 O(1) 选举。

## 二、会话要求逐项对照

| 累计要求 | 本方案落实位置与边界 |
| --- | --- |
| 相对原生实际到达增量尽量全部不超过 200 ms | 第十节保留逐路线、分位和最大值；未达成前不宣布完成 |
| 重点看基线，优先复用历史数据 | 第十节区分 S9L、历史 B、计划前基线和原生 N0；不重跑有效参照 |
| 新旧接口、场景、参数、工具和计量必须对齐 | 第十节；只修改新调用链必须适配的观测，不重定义公共指标 |
| 选取本身低成本，不能只说读取 O(1) | 第六节完整列构建和选举成本，严格整连接 O(1) 仍是未解决项 |
| 点须合法且质量足够，可以不是最优 | 第五、六节；由同一 corridor 合法集合选，不要求实时最优，不二次正常选点 |
| 在宏观寻路时一并准备、选点，省重复排队 | 第三、四节；不先交付裸 corridor 再提交正常准备任务 |
| 后续段也要解决，不只优化首段 | 第四、七节；同次宏观完成阶段准备整条已选路线的连接数据和目标 |
| 预登记后仍重新取号没有意义 | 不引入预登记或占号；正常交接只有详细寻路所需的一次调度准入 |
| 不把尚未到达的位置当成实际位置预搜 Path | 第五节只提前选择终点，详细 Path 从执行时真实位置在主线程计算 |
| 地形变化不能靠无条件提前重做处理 | 第八节保留提交前版本校验与提交后 corridor 语义，实际失败走原有限恢复 |
| 不再把准备搬到主线程挤占 tick | 第四、七节；主线程只安装数据、做原物理判断并启动已准入的一次寻路 |
| 不每八项执行完整业务检查链 | 第七、八节；不引入 S1 的细批检查、暂停状态机和每批重新入队 |
| 常规预算保留，idle 按墙钟空闲补发 | 第七节保留 20 ms 常规策略、43 ms 实际截止与 haveTime；idle 零/负余额仍可补发并记账 |
| 不恢复额外 0.5 ms 墙钟提前量 | 第七节明确保留已取消状态 |
| 准备、索引、排队、搜索、恢复、清理全部计入直接影响窗 | 第九节；前移工作不能留在计量窗外 |
| CPU、分配、完成和到达的负收益全部披露 | 第九、十节；不以局部选点下降代替整场改善 |
| 不把旧候选的组合失败当成独立方法无效 | 第十一节分开 S1、A2、预取和本案，不直接复活或一概否定 |
| 预热是否启用要核对，不凭空增减预热 | 第九节核对实际 prewarm 准入、消耗与测试预热身份，不改原策略来改善数字 |
| 方案审查用 1017/max，代码数据用原 provider | 第十二节；自包含且控制大小，要求独立替代方案，不为通过擅自缩减范围 |

以上是同一任务的累计约束，不是各自独立、可以互相替代的子任务。
本次不恢复已经停止的候选，也不自动接入生产、提交或推送。

## 三、要删除的入队与保留的准入

生产普通首段现状：

```text
宏观 worker 完成
  -> 主线程交付
  -> 排 nextSegment
  -> 再排窗口准备 worker
  -> 再次主线程交付
  -> 排选点/详细寻路
```

修订后的普通首段：

```text
宏观 worker：宏观路线 + 本路线候选准备 + 选点
  -> 一次主线程交付及原最终版本校验
  -> 一次详细寻路调度准入
  -> 使用已选终点计算并发布 Path
```

正常后续段：

```text
原稳定观察、目的区域与物理交接条件满足
  -> 一次详细寻路调度准入
  -> 同一任务内推进游标、安装已准备数据、寻路和发布
```

删除以下正常路径：

- 只负责转调 `nextSegment` 的独立调度任务。
- 宏观交付之后再提交 `prepareGroundWindow` 的 worker 往返。
- 正常后续段的窗口准备 worker 及其主线程交付。
- 已获调度准入后，final 分支只为调用 `findSegment` 再次入队。
- 收到预选八点后，为追求实时最优而重新扫描、排序、选择。

必要的跨线程交付和一次详细寻路调度准入仍需保留。
删除它们会改变线程所有权或绕过公平/实际截止条件。
减少一次入队不等于必然少等一个 tick，更不等于已经省出 300 ms。

宏观搜索原有的依赖等待、计算切片和取消不改成无界连续执行；
这里删除的是额外的业务阶段往返，不是所有底层执行器队列。

## 四、宏观 worker 同次完成什么

### 4.1 以最终 corridor 为单位准备

只处理实际形成的最终路线，不为搜索中每一条展开边生成数据。
在宏观 worker 已捕获完整组件快照、尚未交付结果的完成阶段：

1. 提取与生产相同的 ComponentEndpoint 到 ComponentEndpoint 连接序列。
2. 对每条连接，按原 `GroundSegmentWindow.enumerate` 的来源/目标成员、
   Boundary band 或 LocalTransition 规则生成合法去重候选。
3. 完整确定原候选顺序和原恢复候选顺序，分别编码成 destination section 内的
   short cell 序列；只压缩存储，不推迟候选或恢复邻域计算。
   对外为不可变 List，get 仅按索引解码一个 BlockPos，无枚举、缓存物化或地形读取。
4. 对适用连接构建行位图，并在 worker 中完成最多八点选取。
   不适用位选时在这同一次 worker 执行内用完整旧比较器选择，
   不能返回主线程后再排一次准备。
5. 同时保存 final 目的组件引用/身份，避免 final 调用只为扫描端点再排一次。
6. 将 corridor、准备数据和已选目标一并作为宏观结果交付。

候选准备依赖连接的最后一条边，与目前窗口枚举规则一致。
覆盖所有路线连接，使正常 stride2、既有 stride1 以及恢复缩段需要的末边
都有对应数据；不通过忽略某种连接类型隐藏旧往返。
空集合只记录为空，不为了选择八点填入组件中的任意位置。
只在实际使用该连接时按原规则处理无候选，不能因未使用连接为空提前拒绝整条路线。

### 4.2 共享数据与请求数据分开

准备数据分两层：

- `GroundConnectionData`：同一 corridor 的连接、完整正常/恢复候选编码序列、
  目的组件快照和可选行索引，全部不可变，可由同一物理查询的请求共享。
- `PreparedGroundRoute`：本请求的规划起点/目标、路线位置和各连接的已选八点，
  不可与起终点不同的其它请求混用。

`GroundSegmentWindow` 增加从已有连接数据安装窗口的工厂，
只形成真实起点对应的 sections 和当前窗口关闭状态。
候选和恢复集合不重算；按需解码坐标不创建或缓存完整对象列表，
其解码及日志读取分配计入成本。关一个窗口不得关闭其它窗口或缓存共享的内容。
原 capture 接口保留，用于原契约和其它明确调用者，不把它伪装成零成本新路径。

预计涉及 `TopologyWorkerRuntime` 的完成/缓存重放、
`TopologyService` 的结果交付、纯准备数据 helper、
`GroundSegmentWindow` 的数据/生命周期拆分和 `SegmentedNavigationService` 接续入口。
不能再写成“不改 Runtime、只换 selector”。
宏观图结构、通行能力、组件身份及原生搜索核心不改。

### 4.3 普通、共享飞行与缓存命中必须全部覆盖

普通和分层宏观路线都在最终组件快照齐备后准备，昂贵计算不放在 runtimeLock 内。
共享必须以同一 corridor/stamps/profile 内的组件连接身份为依据，
不能只按“同一个物理查询”或裸 componentId 认定等价。
当前 `rematerializeCorridor` 仅替换 Exact 首末端点及其连接，
组件到组件连接和 components 保持；新入口仍核对完整连接身份后才共享。
若未来重物化改变某条组件连接，须在交付前同 worker 为该连接重建，
不能误用其它请求的连接数据。各请求只做自己的选点。
不能为 64 个等待者重复枚举同一条 corridor。
每个请求选好后即可交付，不要求第一位请求等其余请求全部选好才收到结果。

缓存中保存可复用连接数据，并将其完整保留成本计入现有 corridor 缓存上限，
继续遵守现有 1024 项/16 MiB 策略；活动请求持有的成本另外记录。
缓存重放仍按请求实际起终点重物化，不复用其它请求的八点答案。
当前缓存命中路径可能从控制线程进入，不能把昂贵准备塞进控制线程或主线程。
必要时将重放和本请求选点作为宏观结果产生前的一个 worker 工作完成；
该次 worker 排队必须实报，不得称缓存命中“零排队”。
禁止先完成/交付 corridor，再创建正常窗口准备任务。

首版保留完整正常/恢复顺序，但以预生成 short 序列表示，
避免提前保留全路线 BlockPos 对象集合。
序列完整生成后才发布，关闭后读取只需序列和坐标原点，不额外保留成员快照。
这与旧 FULL_LAZY 的延迟枚举/缓存物化不同。若前置成本不合格，应修改表示或构建算法，
不能自行删掉宏观合并目标，退回 selector-only。

## 五、一次选定八点，如何兼顾后续段

正常中间段保持最多八个不同候选，少于八个全部使用。
八点交给一次详细寻路，不是八次寻路；实际失败后的选择保持生产原规则：
`attempt>0` 从 recovery 按原实时评分取一个；失败缩段使 `attempt` 清零后，
若仍有 `failedTargets`，从 normal 删除失败目标并按原实时评分取最多八个。
正常 `attempt==0 && failedTargets.isEmpty()` 只消费 worker 已选八点。
最终目标和 shared anchors 沿用各自原有单目标语义，不强行变成八点。

对于尚未发生的后续段，不存在已知的“届时真实位置”。
本案使用明确的路线参考点，而不是选完后在主线程补做实时最优：

1. 本请求第一个组件连接，以宏观请求冻结的真实起点为参考点。
2. 后一连接，以前一连接已经选好的最多八点作为参考集合 A，
   每个候选采用对 A 中各点的评分最小值；
   不生成从这些点出发的详细 Path，不把实体传送到参考点。
3. 前一连接无候选时，使用当前连接源组件原有 anchor 作为单一评分参考；
   不用该 anchor 代替当前连接的合法终点。
4. 每条连接按此参考点和本次宏观目标，在原合法候选中选最多八点。
   stride2 使用其末连接已经选好的八点，不再以实际起点重新选。

参考评分仍为：

```java
min(a in A, p.distSqr(a) + .05 * p.distSqr(plannedTarget))
```

表达式按每个 a 执行原 double 运算后再取 min，不先变换算术求值次序。
再按 X/Y/Z 排序破同分。参考集合和各连接结果的顺序必须稳定，
不能依赖 HashMap 迭代顺序或完成回调顺序。
这只减轻“只参考八点中某一点”的偏置，不提供最坏路径质量保证。
参考点读取不是新的最优答案表，更不能称为 O(1) 选举。

**这明确改变了后续段相对“实时实际位置”的评分输入。**
不再宣称与旧算法在所有请求上的 top8 完全相同。
仍须证明它与同一参考点下的旧 full-sort/take8 相同；
而相对旧实时选点的路线质量，必须由搜索开销、失败/恢复、
路径与实际到达观测检验，不能用几何距离近证明实际路径一定短。

主线程不因实体普通移动、落地位置与参考点不同或小幅目标漂移重新选点。
原有目标变化/重规划判断保留，满足原重规划条件时产生新规划；
final 目标仍按原业务时机更新。
`awaitNative` 遇到原 canUpdate 条件暂不满足时保留同一组终点，
就绪后使用，不借唤醒再选一遍。

## 六、合法性、质量和选举成本分别判断

合法性指点属于该条连接在同一 corridor 快照中的原合法候选集合。
继续保留来源/目标成员和原 transition 映射检查；
不能把“整个目标组件都可选”当成“都能从这条连接进入”。
正确性要求是集合不越界、不同目标不重复占名额，目标身份不串用。
它不等于地形动态变化后 100% 能找到详细路径或最终到达。

质量允许不是实时最优，不允许以“任取最低置位”代替有依据的选择。
此版保留八备选和参考评分来避免随意选点，
同时承认参考点选择可能增加绕路或搜索，必须保留全部不利观测。
没有足够数据之前不能承诺这些参考点已经达到用户所说的“优质”。

位选复用 V3 中的整数 BlockPos、完整目标盒数值门和旧 double 比较器证明：

```text
q = (20a+t)/21
```

对每个 a 分别查询：每个非空行以中心左右最近置位作两头合并，
每行至多输出八点，跨行得出该 a 的全局八点。
合并至多 8×8 个结果，按完整 min 评分与 XYZ 去重并保留最终八点。
这里不对 min 后的非凸函数套用单个 pivot。
a 是上述 worker 参考集合中的整数点，不是未来真实位置。
数值门覆盖完整目标 section 与 a/t 的三轴两端点，
绝对差均不超过 65536；不适用时在同一 worker 内执行旧完整排序。
不以整数评分替换原浮点评分，不在共享索引上原地清位。
若一个目标是 min 评分下的全局前八，则它必在至少一个取得 min 的 a 的前八中：
否则该 a 已有八个在完整比较器下更优的不同目标，
它们的 min 评分不会更差，形成矛盾。因此查询各 a 的前八并合并不会漏点。
同 a 行内单调性及完整盒误差门沿用 V3 的证明，实施前必须差分验证。
左右区间明确为 `u<=pivot` 和 `u>pivot`，无遗漏且不重叠；
q 为整数时对应点包含在左区间，不能把右区间写成排除所有 q 整数点的实现。
法向轴 N/S=Z、E/W=X、U/D=Y；行内变化轴刻意选择
N/S/U/D=X、E/W=Z，两者不是同一个概念。
ComponentSnapshot.contains 首先校验目标 SectionPos 相同，
因此越过 destination section 的 Local offset 会被原成员检查拒绝，
正常及恢复集合均完整处于一个目标 16³ section，不靠索引截断目标域。

完整成本必须如实列出：

- 候选枚举及去重，按 band 置位/LocalTransition 原扫描实际计量。
- 正常和恢复列表生成、共享数据持有及未消费数据。
- 两条顺序序列各最多 4096 个 short，最多 16 KiB 原始存储；
  索引构建 O(N)，约 544 B 原始位存储/适用连接，另计头、元数据和恢复生成临时空间。
- 单个 a 的单行一次位选 O(1)，完整八点选举 O(8KR)，K≤8、R≤256，
  另计至多 64 项的去重合并及各项 min 评分；不能隐藏增加的 K 因子。
- 各请求的参考点、选举及目标对象成本，以及 fallback 和取消后的无用工作。

**严格整连接 O(1) 选举仍未解决。**
不能用“移到 worker”“只执行一次”或“随后读取 O(1)”把这个缺口改成已完成。
方案重审必须主动寻找合法且质量足够的更好方法；
若无法给出，应明确保留缺口，不能私自把用户目标改写为“只需某一行 O(1)”。

## 七、主线程接续与调度边界

正常主线程交付内只做原版本/请求身份校验、安装准备结果和一次搜索任务提交，
不进行全量候选枚举、恢复展开、重新排序或重新选点。
真正的 `NativeNavigationSearch.find` 始终从当时实体真实位置出发，
仍在主线程的一次正式调度任务中运行。

原 `settle` 已在调度任务内时，正常交接通过后在同一任务内推进一次游标，
装上对应连接数据，调用一次详细寻路，不再设置仅为转调的 followup。
从 observe 发现就绪时提交一次这样的搜索任务，不在 observe 直接跑详细寻路。
final 段也在已经获得的这次准入内直接完成原准备并搜索。

不循环执行多个实际寻路：
本次搜索若实际失败，需要另一次恢复搜索，则结束本次任务，
沿原完成后 followup 机制为新尝试准入一次；不在同一调用栈里递归多搜。
这是实际新搜索的调度，不是“准备好后又排一次准备”。
只在阶段入口和发布边界执行必要业务校验，不增加每八项完整检查链、
主线程枚举 checkpoint、准备准入接口或“认领一次搜索”的新状态机。

真实起点 sections 加当前实际 edges 仍须满足原四 section 上限；
超限按原规则缩为 stride1 并记原恢复额度，使用对应已准备连接数据。
生产正常 stride 是 2，成功交接后也重置为 2；1 是原超限/恢复缩段值，
不能把审查中的“正常只 stride1”误读当成新增要求而修改。
原 range/accuracy、搜索次数/恢复次数上限、partial 处理、末节点、
目的组件进入记录、stable>=3、onGround、碰撞和支撑规则不删。

调度保持原 priority、FIFO/老化和维度轮转；
不预登记占号、不插队，也不在宏观回调直接跑详细寻路。
常规 END 保留已有预算准入；tick 主体后的 idle 按 43 ms 实际截止和
实时 haveTime 补发，余额只记账，零/负余额不阻断。
不恢复 0.5 ms 墙钟提前量。所有实际成本继续计费。
同步详细寻路不能中途抢占，不声称绝不会越过启动截止。

## 八、地形、恢复、取消与所有权

| 情况 | 处理 |
| --- | --- |
| 宏观结果尚未提交，地形/装载身份已变 | 保留原 worker 及主线程最终版本验证和有限 stale 重试；准备数据与被拒 corridor 一并丢弃 |
| corridor 已提交后发生改块 | 不按新图 componentId 重解释或撤销旧 corridor；详细寻路读当时真实世界，实际失败走原有限恢复 |
| 实体正常移动、交接位置不同 | 使用该连接已经选好的八点，不重新派 worker，不二次正常选点 |
| 原 canUpdate 暂不允许 | 保存同一组 targets，原观察就绪后只为详细寻路准入，不创建准备窗口等待 |
| 本段无可用路径、走完未进入目的区域、原落地等待超限 | 沿原 recover 的 attempt、failedTargets、缩段和刷新上限处理；attempt>0 从已准备 recovery 按原实时评分取一个，缩段清零后从 normal 删除失败目标再取最多八个 |
| 需要恢复重选 | 属于实际失败后的新尝试；完整恢复集合已在 worker 准备，当前线程不临时展开邻域；若必须更新宏观输入则走原重规划 |
| 请求被取消、替换、能力失配、实体移除或停服 | 原请求身份和终态规则处理；迟到结果不可挂回新请求，未安装窗口须释放 |
| 窗口关闭 | 原 current/contains 失效，原不可变候选和恢复列表关闭后仍可读；不关闭其它窗口或缓存共享的数据 |

不为降低平均时延吞掉失败、延长 TTL、提高恢复额度或放宽原物理交接。
stale 清理指丢弃未获提交的旧准备数据；仍执行原提交前有限 stale 重试，
不是因出现 stale 就取消请求或删除自动重试。
“主线程不正常重选”不禁止实际失败后原有的恢复评分：
`attempt>0` 可扫描已经完整生成的恢复序列，按失败时真实位置、原内邻点数和失败集合选一个；
原缩段清零后的 normal 例外同样保留，不把“存在失败目标”擅改成单点恢复。
这不等于主线程重新枚举几何或展开邻域，不声称恢复评分为 O(1)。
不能用冻结恢复排序的桶替换依赖真实位置的旧评分。
共享的不可变内容不持 Work、实体、服务器、future 或 callback；
本请求的待交付结果与已安装窗口有唯一所有者，旧回调不能清理新规划。
沿用已有请求/宏观 future 身份与代次，只补新资源确实需要的所有权约束。
取消检查在连接边界用已有取消信号，不逐候选读取配置、策略和整套业务链。

## 九、成本前移不能冒充消除

全路线紧凑准备移到宏观完成前，仍会提前支付后续段的枚举、恢复与选点。
这可能拖慢首 Path，增加未走到连接的无用准备，并让其它宏观请求等待。
这不是免费操作，也不保证会被消除的队列等待抵消。
活动路线数据和缓存数据分别计量，不能用 16 MiB 缓存限制冒充全进程内存上限。
现有查询节点数和活动请求上限只给出有限规模，不证明该规模内成本可接受。

因此首版保留旧列表契约、压缩坐标序列并共享身份一致的准备数据，
将前置成本列为明确风险；若不利，优先在同一合并架构内减少准备表示或重复扫描。
没有证据时不另增线程、扩大缓存、增加预热或重启已否决的抢队/预算方案。
不能用退回“宏观交付后再准备”隐藏前置成本。
活动请求及节点上限仅是原有有限规模，隔离测试不授最坏规模的生产容量保证。

直接影响范围从新增准备开始前，到实际受影响的 Path 发布、
失败/恢复处理和新增数据释放为止；跨异步间隔与缓存持有成本不能漏记。
首段宏观、后续接续、恢复三类窗分别列边界，不把 CPU 和墙钟混为一项。
同时保留原场景总 CPU、主线程/worker 可用的成本、分配/GC、首 Path、
详细寻路完成、首次移动、实际到达、请求终态和 tick 启动间隔。
没有逐线程数据时不把“进程减主线程”命名为 JIT 或 worker 成本。

核对拓扑 prewarm 的实际准入和任务消耗；
它与测试的 warmup8/warmup28 不是同一个概念。
本案不调整既有预热政策，不通过改预热、日志或场景收尾时间取得更好的数字。
新增无用准备、fallback、取消丢弃、缓存保留和恢复成本全部披露。

## 十、验证、比较和完成判定

用户随后授权“送审然后开始核验”。方案与代码审查、隔离构建和必要正确性控制已通过；
最终 v5 两个原场景性能 JVM 已结束，130/130 到达，数据复审只批准有限结论。
最新状态以核验报告为准；有效历史 S9L/B 直接复用，未重跑基线。

复用现有 GroundWindowContracts、完整旧候选/恢复序列、
full-sort oracle 和取消/替换/改块/等待/预算/关闭控制。
仅补本改动必须覆盖的内容：宏观同次准备实际命中、缓存与共享飞行、
不同请求不串用八点、负坐标和位图映射、数值门、后续参考点确定性、
正常主线程没有重选/枚举、compact List 的顺序/不可变/关闭后解码、
原窗口关闭契约与新共享数据所有权。
不能把“与同一参考点 oracle 一致”写成“与旧实时选点行为完全等价”。

先核对历史版本身份、测试接口、场景、参数、工具和计量：

- S9L 是本次改动的直接参照；有效历史性能直接使用。
- 历史 B 与工作计划前生产基线分别注明具体版本和日期，不能统称 B 混用。
- 原生 N0 用于原生目标比较；旧完整工具不同等限制继续保留，
  不冒充与当前受控同接口的因果比较，也不因局限自动重跑原生。
- 候选变化不使以上参照自动失效，不为形成新配对重跑有效历史版本。
- 新调用链必需的诊断适配只增加新方法覆盖，公共提交/Path/到达/终态计时不改。
  历史缺失的新增直接窗不能凭空重建；真需补测只补失效/缺失部分并记录原因。

原 8 格/28 格是混合地形距离档位，各 64 实体并发，
不是单实体测试，也不全是平地，不把 64 实体当作 64 次独立复跑。
304 格冷暖是原长路线单实体场景；按实际影响和历史缺失决定是否需要补测，
不默认重跑全部矩阵、不自行新增极端地图。
原有先下后上等原生失败路线保留失败分母，不能伪造到达差值。

指标同时保留单个实体提交起点和整批提交起点。
每条路线使用其原有 tile/slot 身份，不挑一个实体代表全体；
配对差的分位与各版分位相减分开报告，绝对毫秒和百分比同时保留。
所有窗内不利值列出；窗外按用户既定口径视为波动，间接影响不展开归因。
窗内未定位原因的回退不能自动称波动，已测证据也不支持把整项增量都归新代码。

判定分开进行：

1. 正常首段/后续段没有额外准备往返、没有二次选点，是机制要求。
2. 合法集合、恢复、生命周期和原调度条件保持，是正确性要求。
3. 参考点八选的搜索/到达质量与完整 CPU/分配是否值得，是性能要求。
4. 相对原生实际到达增量≤200 ms 是否覆盖原场景/路线，是端到端目标。

不将中位改善等同“全部压到 200 ms”，不以首 Path 绝对值小于 200 ms 代替增量。
稳定观察、真实搜索耗时和原生长 tick 后追赶节拍必须分开，
不能把它们都计为准备队列等待，也不为达标更改计时原点或模拟节拍。
如果直接影响窗没有足够可回收时间，不能承诺该方案单独省出约 300 ms。
若剩余主因是原有稳定/物理接续或路径质量，应据证据修订整个方案，
不把未解决部分直接丢到“下个阶段”并宣布本阶段完成。

## 十一、历史方法的使用边界

S1 将准备搬到主线程、细批完整检查和暂停续行的组合已经停止，
本案不恢复该执行方式；其 CPU 增量根因未定量闭合，
不能一口咬定全部由检查、主线程迁移或波动造成。

A2 的纯准备交接合并有机制依据，但净收益未被确认，
不把它当作已证明能省数十毫秒的生产优化。
旧后继模板预取诊断有 47 个窗口同 tick 接搜、最大约 1.8371 ms 的记录，
本案不能把同类机会重新包装成必能省一个 tick；
全路线准备的前置代价也必须另行评估。

行位选、无索引容量八选择器和全排序是独立算法选择。
不因 S1 组合失败否定独立方法，也不因 V3 文本审查通过认定新架构有收益。
可以在方案审查中选择成本更低的算法，但不得因此删除宏观合并、
一次正常选点、质量和完整计量要求。

## 十二、重新送审要求与当前未闭合项

后续方案重审沿用用户划定的分工：方案用官方 1017 对应当前可核验接口、max，
代码和数据等用原 provider。调用前核验模型实际接口，
不能把旧别名记录当作新调用的不可变模型版本证明。
无头审查材料必须自包含、控制大小；必要时按架构/算法成本分包，
两包都携带共同约束，不能通过分包把关键交互遗漏掉。

必须要求审查者检查并主动提出更好方案：

- 宏观完成阶段、缓存重放、共享飞行是否真正避免正常重复准备往返。
- worker 一次选定八点的参考点策略是否足够优质，有无更好的一次性方案。
- 是否存在严格整连接 O(1) 选取、且合法/质量/构建成本兼顾的方法。
- 全路线前置准备及完整恢复列表的额外 CPU/首 Path/保留成本是否合理。
- 同次准入接续是否仍遵守原公平、idle、截止、真实起点和失败恢复规则。
- 哪些情况下方案无法接近 200 ms，不能为了取得通过缩成 selector-only。

首审提出的恢复“禁止主线程任何扫描”不作为新增要求：
原规则禁止正常二次选点和主线程几何准备，允许实际失败后的原恢复评分。
首审关于 q 的疑问须用单个 a 的单调性证明、数值门和差分控制回答，
不能仅因文本判词声称平方评分不适用；min 集合则按上述并集证明处理。

当前明确未闭合：严格整连接 O(1)、多参考点八选的实际质量、
全路线前置准备的净成本、200 ms 覆盖和生产资格。
四包代码复审只允许隔离核验，不以旧 V3 的 ACCEPT_SCOPED 代批。
审查原件中的“所有恢复取一”已按生产实际 attempt/缩段规则澄清，见代码导航复审及报告；
不为迎合审查措辞改变原业务。
