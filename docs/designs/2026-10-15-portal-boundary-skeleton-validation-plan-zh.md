## 增量与边界

从完整 Base 的六个面及现有跳跃、下落边界带提取不可变稀疏锚点表，保留局部位置和当前 Base 内的组件绑定。预计算每个组件对十四个相邻 section 槽的能力候选掩码，以实际锚点可产生的跨界位移筛除不可能的依赖；不以组件包围盒命中代替真实锚点。表用于现有 BoundaryLinks 的源锚点枚举，碰撞、目标组件、descriptor、能力判定和最终真实 PathFinder 仍走原逻辑。

骨架只表示候选，不表示 canReach。缺少目标 Base、邻区事实或 BoundaryLinks 继续使用现有 UNKNOWN/等待。不会在源 Base 之前可用，也不节省源 Base 首次扫描。完整父图延后复用上一轮闭包策略，不能把它再次算作骨架新增收益。

不新增独立异步缓存。骨架由唯一不可变 Base 持有，随 Base 生灭；组件号只在该对象内有效。查询的完整身份仍由 dimension/section、GeometryKey、ViewEntry validity、中心及 halo 的 loadIdentity/revision stamps、Base 对象身份、面/锚点、能力掩码及骨架算法版本共同约束。原有获取、发布、消费检查保持；旧对象不能接到新代次。骨架记账加入 Base retainedBytes，但不宣称进程内存。

## 正确性和准入

先逐项比较旧枚举与稀疏枚举的 BoundaryLinks：所有边、descriptor、mask、能力和下界一致；覆盖六面、水平带上下邻层、GROUND/VOLUME、台阶/跳跃/下落、多组件、窄/偶数宽度、低顶、门、支撑和 halo。对所有三十个 MovementKey，任何真实旧边的源组件均不得被骨架剪掉。另要求存在包围盒假阳性被拒绝的确定性例子，否则不能声称新增依赖筛选效果。

复用并重新执行实际 worker 的共享取消、UNKNOWN 恢复、失代重试、卸载重载、能力隔离、关闭清理及默认搜索上限控制。自然移动覆盖原功能场景及 512 实体正确性门，核真实节点、原终态、到达、无整条原生回退。读取器必须拒绝缺失行、早发、错包、错误终态及未测补零等损坏；失败保留并停止其后性能资格。

旧自动基线派发前失败不等于骨架失败。本轮探针补逐请求终态，诊断副本区分传入 haveTime 与实时 supplier 的拒绝点，不改变谓词求值次数或短路语义，不调预算、TTL、JVM 参数。若再次发生派发前失败，保留原件、停止性能比较，只给本轮可证明的结构/正确性结论。

## 有界性能比较

采用独立顺序 JVM、场景就绪真实 30 秒后提交、固定当前 tick 20ms、原 500us 门槛与实时截止。比较 auto、closure、portal：auto 为现有自动 Base/Super；closure 为上一轮候选、关闭骨架；portal 为相同候选、开启骨架。另保留强制 Base 诊断。所有组同包、同输入、同调度，源码和发行在性能前冻结。

plain 覆盖平地 1/128/256 各三模式一轮，平地及八走廊 512 各三模式两轮；detail 覆盖两个 512 场景各三模式一轮，共 27 个性能 JVM。模式按场景轮转，第二重复反转顺序；诊断组交错，不先跑完详细组。低负载只有一轮，只作回归观察；两轮高负载也不支持稳定性能或生产资格。必要的接线/功能轮不混入性能分母。

主要看每 JVM 首条真实 Path 观察延迟和自然到达；同时保留首段节点/终点、真实原生调用、全 tick、Base/Super 数量、骨架提取成本/字节、边界扫描槽数和实际剪枝。将 portal 与 closure 的差异作为新增骨架效果，auto 对照作为端到端参考。若边界输出等价而没有可重复端到端改善，或只是搬动等待，记录本候选无已证明收益并停止扩展；不新增方案外优化挽救结果。
