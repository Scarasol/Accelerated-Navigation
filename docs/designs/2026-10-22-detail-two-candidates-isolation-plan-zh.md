# 两项详细寻路候选的隔离方案

日期：2026-10-22。用户要求与1017继续讨论，确定两项方法并隔离验证。
这是前轮三算法研究后的具体筛测，不是直接实现平地长边、Lazy Theta*或门户图。
本轮最终方法为T与QG；二者从U分别建立，不叠加、不接入生产。

## 1. 会话约束

详细询点仍由主线程真实Mob的原生NodeEvaluator负责。
门、水、碰撞、体型、台阶、下落方向、malus和Forge钩子不改。
已有宏观worker、走廊、选点、分段跨度和最多八个备选终点保持。
不新增worker往返、重复选点、长边、共享语义缓存或预算。

U是此前“取消预算、保留原END/排队ready派发”的隔离候选；
生产P仍是生产区，N是同运行时原生。旧I/I2需求不符，不能混入。
已知连通并不提供原生精确距离；本轮两法也不称全局最优。
200ms仍是整体项目目标，不作为单分支必须承诺的收益。

## 2. T：仅同f时使用最终目标方向

原生主键f严格优先，完全相等时依次比较：
节点到最终真实目标的平方距离，以及x/y/z。
不用epsilon，不跨不同f重排。启发式、1.5权重和首目标命中停止保持。

实际BinaryHeap的private sift直接比较Node.f，没有可覆写比较器。
因此DirectionHeap只继承其接口类型，自持数组/size并完整覆写九个公有操作，
自己的sift维护heapIdx；不调用父类堆操作。
父类构造的额外数组及新增堆自身分配都计入成本。
每个PathFinder复用自身DirectionHeap；只在一次适用搜索中临时替换openSet，
finally恢复原堆，不复制原搜索循环。

T可能改变展开、路径与partial，收益没有保证。

## 3. QG：几何方向偏置的单次多目标搜索

保留全部实际目标。对每个目标ti计算：

```text
di = Euclidean(ti, 最终真实目标G)
qi = max(0, di - min(dj))
getBestH(n) = min(Euclidean(n, ti) + qi)
```

仍用未加qi的原距离更新Target.bestNode，保留原partial选择。
原生后续节点的1.5倍、起点未乘1.5的例外、堆同分顺序、
首真实目标命中停止及原回溯均保持。
全部qi=0时委托原生getBestH，固定输入应得到相同目标和路径。

不建立虚拟终点，不维护额外已达候选，不在命中后继续搜索。
原因是该几何q满足三角关系，目标处启发式为qi；
若终端候选按1.5qi处理，首个出堆目标已经满足相应停止规则。
此前多候选设计在此特例下没有必要，已在与1017的复审中撤掉。
这不是一般虚拟终点算法的最优性证明。

qi不是实际后续路程，QG只是方向偏置；
原partial按几何最近点选择，可能与偏置目标不一致，作为风险保留。

## 4. 适用范围与实现边界

只用于已adopt、普通GroundPathNavigation的正常中间分段移动：
无preview、非最终段、attempt=0、recoveryCount=0、非shared、
accuracy=0、实际目标2–8个且最终目标存在。
查询、whole、最终、单目标、恢复、其它导航类型均走原生。

Service仅在真实find调用周围打开ThreadLocal上下文，finally清除。
原Service和NativeNavigationSearch方法签名保持。
Mixin只临时替换堆或包装getBestH调用，保留原循环和探针指令、
prepare/done、profiler、失败节点过滤、range、visited、closed与未知块处理。
共同上下文、适配和观测开销都计入，不当作算法收益。

## 5. 验证范围

先做真实Minecraft BinaryHeap/Node和原PathFinder循环的图控制：
堆同分/非同分、相邻float、减键/删除/扩容/索引；
q0路径一致、q>0方向、父链、八目标、range、限额partial；
作用域排除、原失败节点过滤和异常清理。
离线图控制仅对原getBestH加等效测试钩子，游戏使用真实Mixin，
不把图控制冒充全地形或发行接线覆盖。

每候选仅一个35ms压力JVM，原顺序：
64×8、64×28、128×8、128×28、256×8、256×28。
沿用八类人工地形、sigma5/seed20261021、Java17/2GiB/G1、
速度II、真实30秒就绪、90秒观察和10tick尾窗，NoTrace、无JFR。
U35/P35/N35历史有效，直接复用；不重跑基线，不增加15/25/304。

每格一次，只作机制与明显回归筛测，不作稳定性能或生产批准。
