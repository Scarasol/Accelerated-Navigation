## 推荐框架

沿用原设计的职责划分：**宏观层找组件走廊，详细层生成真正可执行的路径，原版导航负责实体移动。**
宏观层继续使用现有两个 worker；详细层读取 Minecraft 世界和实体状态的工作仍留在服务器主线程，
复用现有 `NavigationScheduler`。不新增详细寻路 worker，不把宏观构图搬回主线程。

```mermaid
flowchart LR
    A["命令或明确接入的实体移动请求"] --> B["请求身份与移动能力"]
    B --> C["现有宏观服务：组件走廊"]
    C --> D["主线程详细搜索：真实逐格路径"]
    D --> E["当前性与目标校验"]
    E --> F["命令显示，或原版导航执行"]
```

“组件”是区段内的一组连通位置；“走廊”是宏观层选出的组件及连接序列；“详细后端”是把请求和走廊
转成 Minecraft `Path` 的搜索实现。“可恢复搜索”指保留搜索进度、下次继续，不是重新从头寻路。
这里没有把代表点之间的粒子直线当成实际路线。

首轮建议限定**地面导航、完整详细路径生成和调试展示**。先接通 `/navigation … true`，
验证真实碰撞与开门能力，再接明确的实体移动入口。飞行、游泳、第三方导航、提前发布部分路径和全局
AI 接管分别后续设计，不在第一次接入时一起扩张。

## 接口与数据交接

推荐每个请求保存最少的业务输入：

- 请求者、维度、请求代次、真实起点、目标集合、目标容差。
- 实际宽高、上下台阶／落差能力、介质能力、门通行及开门能力、路径类型偏好。
- 宏观走廊及其依赖身份；详细搜索自身实际读取区域的身份。
- 最终结果、取消／失败原因以及少量计时字段。

能力从同一个请求输入派生给宏观和详细层，避免两层用不同体型或开门设置。
宏观能力是结构筛选，不自动证明详细后端会执行跨空隙跳跃。首轮只支持地面后端已经验证的移动集合；
超出既有宏观表示上限的实体能力不能静默截断后宣称完整支持。

建议的业务入口是 `requestPath(导航上下文, 目标, 选项)`，返回请求句柄和异步最终结果；
需要移动的调用者在成功交付后再使用 `requestMove` 或同等明确的适配入口。名字只是说明职责，
不是要求新增两个转发模块。同步 `createPath()` 不返回请求句柄、不返回占位路径。

返回结果至少分清：到达目标、允许情况下的最终部分路径、候选区域未找到路径、工作上限、输入变化、
区块不可用、取消和异常。`Path != null` 不是完整成功条件。原版最终部分路径与“搜索尚未结束的前沿”
也不能混同。

### 走廊怎样参与详细搜索

第一候选是在走廊所经区段的联合区域内进行**一次面向真实终点的详细搜索**。同一区段多次经过时不强制
挑选代表点；局部和边界候选由真实邻接规则筛选。必须保留身体碰撞、邻格危险检查所需的读取邻域，
而且把“节点允许搜索的范围”和“碰撞允许读取的范围”分别表达。

走廊提供候选区域与连接提示，不作为唯一详细可达性证明。首次不建立全世界组件标签副本，不把全部派生图
固定到主线程，不为详细层重新扫描生成一份宏观图。现有边界 mask 可供候选验证，但不能在没有坐标映射
与完整性证明时直接作为唯一通口。

此候选比逐 anchor 分段更容易保留跨边界选择，也避免一次搜索失败就把真实有路的场景判成无路。
但它仍可能因为走廊过窄或宏观与详细能力差异漏掉合法绕行。因此**候选区域耗尽只说明本次细化未找到**，
不能宣称整个世界不可达。扩大区域或重新选择宏观走廊的策略在后端小原型对照后决定，不先增加重复搜索器。
没有证据保证本轮找到全局最短路径。

长路线的滚动窗口与部分路径执行可以后续加入，但首次不靠贪心拼接多段路径快速宣称完整可达。
这不是把整个城市包围成矩形后无约束跑原版全图寻路。

### 后端和线程的取舍

| 候选 | 正确性与线程 | 时间、内存与成本 | 初步结论 |
| --- | --- | --- | --- |
| 直接原子调用原版详细搜索 | 主线程内读真实 Mob；单次可用现有 evaluator；要处理未知区块与完整结果语义 | 最容易建立对照；调用开始后不可抢占，长路线有主线程尖峰风险 | 作为短范围对照与原型基线，不直接认定适合作为通用默认后端 |
| 保留原版地面邻接规则，改造成可恢复搜索 | 主线程续跑；请求独占搜索状态；必须固定实体计算上下文并处理跨 tick 世界变化 | 可控制每片工作；较原子调用多状态与输入一致性工作，但复用现有调度器 | 推荐的正式接入方向，先验证固定上下文与分片机制，不能仅把原版循环拆开 |
| 新建离线世界快照并放到后台线程 | 完整复现 BlockState、碰撞上下文和 Forge 钩子才能成立 | 采集、快照、缓存、失效和第三方兼容明显增加规模 | 首轮不采用；现有导出基础图不足以复现全部详细规则 |

原版 `WalkNodeEvaluator` 的缓存随 `prepare/done` 管理，内部还直接访问 Mob 的当前位置、AABB、
malus、步高、落差及方块查询。保存这个对象直到下一 tick，期间让实体继续走旧路径，会改变同一次搜索
的计算输入。请求独占 evaluator 只解决共享问题，并没有解决这个移动问题。

可恢复后端需要一个真正固定的地面计算上下文，以及与之对应的节点规则适配；不能用在每片开始时把真实
Mob 瞬移回起点的办法模拟。世界变化则采用实际读取范围的变更身份，或经证明等价的读取校验。
现有宏观版本不覆盖全部 BlockState 路径类型；例如几何相同的方块替换仍可能改变危险类型和偏好。
如果采用新的运行期方块变化序号，它只服务详细输入失效，不扩张宏观图的重建依赖，也不加入持久化格式。
具体选型仍需最小原型证据，当前不是已闭合实现契约。

## 三项生产职责的初步契约

下表按列给出三项职责的六块内容；现有 scheduler 仍拥有预算和排队，宏观 Runtime 仍拥有图，
不另增两套调度器、缓存或镜像状态。

| 契约块 | 完整请求生命周期 | 地面详细搜索 | 路径交付与消费 |
| --- | --- | --- | --- |
| 目的与边界 | 接受明确的异步业务请求，串接宏观和详细阶段，负责取消及终态；不拥有图或节点规则 | 用真实地面规则把候选区域转为 Path；不发区块票据、不控制实体移动 | 复核并交付可执行结果；调试显示与实际移动消费者分开 |
| 入口与身份 | 首轮命令，其后明确接入的实体移动入口；服务器线程；维度＋请求者＋代次 | scheduler 调用 step；输入为同一请求能力、真实起终点及走廊上下文 | 同一请求代次的终局；真实目标／容差以及实体当前位置均参与复核 |
| 状态、线程与资源 | 一个请求者一个活动请求；拥有阶段和子请求句柄，不复制子模块队列；数量有上限 | 每请求独占 open set、节点缓存及读取身份；按节点数／读取区段计资源，初始化和恢复路径也计预算 | Path 是可变消费对象，不跨实体共享、不进入全局完成路径缓存；消费后转交原版 |
| 生命周期与失败 | 接收→宏观等待→详细排队→执行→待交付→终态；替代、离线、换维度、取消、关闭均取消子工作 | 初始化→扩展→恢复最终路径→清理；输入变化、上限、未知区域及异常分别终结；prepare/done 成对，迟到唤醒不可复活 | 发布前核对目标、加载及读取身份、取消代次；成功才替换旧路径；新路径失败不自动清空旧路径 |
| 依赖与删旧 | 复用 MacroRequest、scheduler 及策略；现有命令 Session 迁移为此请求的消费者，避免维持两个活动请求所有者 | 扩充既有详细输入；保留通用 ResumableSearch；删除被新接入替代的空分支，不复制原版整套导航执行 | 复用原版 moveTo(Path)/tick/MoveControl；true 的“尚未实现”分支在接入时替换；false 的宏观展示仍有消费者 |
| 验证、规模及批准 | 验证替代／旧回调／关闭与资源归零；范围和失败策略仍为候选 | 验证相同输入的分片／非分片最终结果、地形变化和预算；固定上下文机制尚缺原型证据 | 验证目标、接续、门执行与粒子；本轮未获模块实现批准 |

旧路径继续执行仅适用于尚可安全继续的路径，不能绕过原版碰撞、卡住检测及既有重新寻路行为。
实体移动后，新路径要能从当前实体状态接续才可采用；不能每个 tick 因位置变化就从头重算，也不能直接
采用脱离实体位置的旧起点路径。具体接续验证、重算条件与总工作上限需在实体移动阶段冻结。

停止服务器时先停止新业务请求并取消等待／执行，再完成必要清理；不能只等 `ServerStopped` 才让
已被业务放弃的请求留在宏观或详细队列里。细化失败不污染现有宏观完成缓存。

## 首次接入与后续扩展

建议先完成一个真实可用、范围清楚的命令入口：

- `false` 保持现有宏观查询及直线粒子。
- `true` 使用统一的地面调试能力，从指定起点到终点生成完整详细 Path；输出结果与分阶段耗时，
  粒子沿详细节点显示一分钟。
- Player 不能直接传给需要 Mob 的原版 evaluator。命令使用明确声明的地面调试上下文；原子对照可采用
  不加入世界、不 tick 的调试 Mob，但它不代表所有真实实体，也不能据此认证跨 tick live evaluator。
- 后续真实 Mob 请求从它自身读取能力；成功后使用其原版导航执行，不让命令玩家本身自动移动。
- 有能力规划通过木门不等于实体实际会开门。先验证具备已有开门执行逻辑的地面实体；向其他实体添加
  开门行为属于额外能力选择。

原版地面路径本身不是完整的自由跨隙跳跃控制器。宏观短跳跃边、原版上台阶以及实体真实跳跃动作不能只用
一个 `canJump` 就混为一谈。首轮不为大跨度跳跃生成无法执行的节点链。

## 最小验证与计时边界

现有几何、宏观查询和采样资料复用，不恢复旧 test/gameTest 架构，不为了本轮框架重新启动世界。
进入原型后按新增机制选择最少控制：直路／楼梯；薄玻璃与门的阻断／许可；同一区段不同通路或多出口；
区块缺失与方块类型变化；取消、替代和关闭。多个业务参数共用控制机制时不做笛卡尔积扩张。

可在捕获的局部 BlockState／碰撞输入上离线核对新算法；现有基础图只支持宏观结构部分，不能替代
所有详细方块规则。实际门操作与实体接续留给最小真实地形验证。

| 验收对象 | 要证明的关系 | 当前证据状态 |
| --- | --- | --- |
| 请求交接 | 宏观完成不等于详细成功；同请求代次交付，旧结果拒绝且资源释放 | 初步契约已列，新增行为尚未实现 |
| 路径真实可走 | 原始起终点、实际宽高、逐格节点规则及目标容差一致；薄墙拒绝且合法绕行保留 | 已有宏观几何证据复用；详细链路需要新增证据 |
| 分片一致 | 同一固定输入下分片与非分片的最终目标、节点有效性和失败原因一致；不是 restart | 上游状态关系已核对，固定上下文原型待验证 |
| 当前性 | 几何不变但路径类型改变、卸载重载、实体能力／位置变化不能采用旧结果 | 已发现宏观版本不能覆盖全部输入；详细机制待定 |
| 门与执行 | 规划能力正确；已接入实体能实际开门并沿路径移动 | 首轮命令只验证路径；真实执行另行验证 |
| 性能及清理 | 主线程最大单片、累计实际执行时间、请求延迟及终态引用释放分别记录 | 详细后端没有实测性能，不能从宏观火焰图推导 |

建议每请求只保存入口、宏观交付、详细首片、详细终局、最终可用时刻，以及执行片累计时间和最大片时间：

- 宏观延迟：宏观提交前到其最终校验后的走廊交付。
- 详细延迟：走廊交付到详细结果校验可用，包含排队、让出 tick 与必要发布。
- 详细实际执行开销：详细初始化、节点扩展、路径恢复及校验的真实调用区间求和；不计暂停等待，
  不把粒子、聊天、JSON 归档加进去。它是调用墙钟累计，不冒称精确 CPU 时间。
- 总请求延迟：整体业务请求接受到最终详细结果可用；还包含阶段交接与校验，直接取端到端边界，
  不用零散阶段求和替代。
- 实体实际走到目标的时间另计，不能混入寻路计算时间。

计时使用单调时钟，展示以毫秒为主。排队与等待是真实延迟但不是计算开销，两者都报告；
不通过减一个“监控开销指标”或减火焰图比例制造净性能。普通日志每请求一条终局摘要，异常附有界原因，
不输出完整节点、世界或每个扩展事件。

## 成本、尚待验证的选择与返回动作

| 实现范围 | 初步成本估计与依据 | 边界 |
| --- | --- | --- |
| 走廊身份交接＋命令完整请求生命周期＋路径展示 | 约新增／替换 250–450 行生产 Java，借用现有 Session、调度和图服务 | 不是最终 diff；不含详细算法和全面实体接入 |
| 地面可恢复详细后端及固定输入适配 | 约新增／替换 450–850 行；原版搜索循环约百行，但节点规则与一致性处理明显更大 | 输入机制若需全面复制 evaluator 或快照世界，估计失效，应先缩小支持范围而不是继续堆实现 |
| 首轮新增定向验证 | 约 150–300 行临时驱动／必要控制 | 不计复用上游及历史源副本，不承诺建设新测试框架 |

这三行不能当作精确净增量；删除量及原子切换位置尚未完成逐符号枚举。首轮不更改持久化格式，
不增加图缓存、全局详细路径缓存和后台线程。请求数量与时间预算先复用现有约束，节点、局部读取区域
与输入状态的额度须通过原型确定，不能按起终点直线距离武断下调搜索限额。

需要下一步证据的选择已一次列出：

- 详细固定上下文怎样实现：保留哪些原版地面规则，如何避免 live Mob 跨 tick 输入漂移，
  是否需要最小运行期 BlockState 变化序号。
- 走廊候选区域与通口提示的用法：多出口、走廊过窄及宏观／详细规则差异时怎样避免误报不可达，
  是否需要取得少量组件信息。当前不预先引入组件标签副本。
- 首轮详细性能预算、节点上限及输入资源上限：真实执行片与总延迟分别定门槛。
- 实体执行阶段的具体调用者、路径接续、移动目标更新及自动重新寻路边界。

建议下一步先用一个很小的地面后端原型，核对“候选区域一次搜索”和“固定输入分片”这两项，
以原版原子调用为规则对照。原型证明后再冻结完整实施契约。现在无需先做全局导航 Mixin 或重建测试包。
