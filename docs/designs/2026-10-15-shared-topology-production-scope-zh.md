# 共享拓扑首版接入范围

日期：2026-10-15。依据用户本次“先接入已经验证的部分，首版审核通过后再验证补充”的授权。本文限定共享首版对现行详细寻路契约的接入增量；未涉及的详细搜索、原生结果、生命周期与预算职责继续按现行契约执行。

## 首版路由

只有已选择地面分段、同 section、accuracy=0、GROUND、精确宽度<=1、heightCells>=2 的请求使用共享锚点候选。其他请求沿既有 Base/Super 宏观候选链路；不修改飞行、水生、同步查询或多目标原生决策语义。

共享表示采用允许开门的 1.0x2.0 基础条件，不开门条件在门依赖范围以精确行替换，空行也替换。连接不足按请求条件局部生成，已发布记录保持不可变。门格含流体、门上空碰撞流体支撑来源无法区分的输入显式标为共享表示未支持，继续原有宏观流程，不伪造原版无路，也不转整条详细移动。

共享结果只给候选锚点。每个阶段最多四个候选连接，从实体实际位置调用真实原版 PathFinder；最后段保持原最终目标和 accuracy。真实节点、partial、malus、能力快照及实际详细参数保留。不能在真实搜索前增加方块/身体邻域/组件通行资格过滤。

补充容量控制已复现 64 Slot 占满及卸载后不自动回收的行为。已将 Slot/行载荷/capture/flight/发布订阅的共享准入不足用专用类型标记，转现有宏观候选流程；关闭、通用 worker 拒绝和其他错误保持原处理。共享准入不足不记作区域无路，不扩大原有额度，也不转整条详细移动。15场景/143控制、四条原参数路线和 DeepSeek 补充综合共识已结清，资格限 [实际补充验证记录](../reports/2026-10-15-shared-topology-supplement-validation-zh.md)，不是所有五处逐一自然饱和或完整内存上界批准。

同 section 首次共享新任务使用现有最小搜索上限 12、恢复上限 8，宏观刷新最多一次；已有非零额度任务继承原值，不因锚点数量放大上限。原预算策略仍使用接入前动态预算候选，不改额度、公平队列或原子搜索计费。

## 执行与当前性

正常可达中间段的真实节点耗尽后，从实际实体位置生成下一段；不能把中间段当整项完成。最终成功仍要求真实最后段 canReach 及实体实际最终目标 accuracy 成立。

共享分支的原生物理停滞/超时停止直接 EXHAUSTED，清除当前任务和待办，不自动进行两次物理重搜。后续由正常调用方按当前输入发起新请求。原有 Base/Super 组件末节点保护保持原语义。

输入、能力、请求和目标代次、取消、TTL 与关闭属于当前性管理。worker 锁外结算后排回 server 线程，再检查兴趣、输入与 TTL；消费真实节点前复核宏观及真实读取区块证明。旧结果失效时按原有有限重搜/刷新处理，不人工重新批准旧 Path。

基础 Slot、在途请求、捕获与估计行载荷沿用已验证的有界准入；估计行字节不等于完整 JVM 内存上限。每任务独占 BuildScratch；每 worker 独占 BFS parent/queue，重入使用临时独占数组，线程退出清理 ThreadLocal。关闭从开始就撤销结果当前性，并结算未交付 future、释放输入 pin。
