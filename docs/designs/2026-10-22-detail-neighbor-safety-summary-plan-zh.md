# 详细寻路主候选：跳过已证明无影响的邻域扫描

日期：2026-10-22。

状态：源码研究及1017三轮方法讨论完成，认可主方向进入实现审查；
尚未实现、构建或运行游戏，不等于代码、性能或生产通过。

用户已明确：临时 `previous` 还原数据精简只能随下一主候选附带，
不再单独建立候选或运行一轮。第六十五节的独立精简计划据此调整；
旧研究、讨论与封存原件保留，当前执行入口以本方案和最新索引为准。

## 1. 主改动和预期工作量

主改动是给原生 `WalkNodeEvaluator.checkNeighbourBlocks` 增加
“这片邻域不会改变输入类型”的快速证明。

原生 `getBlockPathTypeStatic` 在得到 `WALKABLE` 后调用该函数。
它按XYZ顺序检查3×3×3中除中心垂直列以外的24格。
每格依次取得世界方块、调用方块和流体的相邻路径类型钩子，
再判断仙人掌/浆果、燃烧、水边界及凋零玫瑰/滴水石；
命中即提前返回。无命中才返回原输入类型。

候选证明所有相关格子均不可能产生上述影响时，直接跳过整个循环。
原生已有完整实体锚点类型缓存和AABB缓存；本方案不再缓存同一层最终类型。
它作用于那些仍然真正进入邻域扫描的调用。

这是每次相关询点都可能省一段工作的主候选，规模大于每次查询精简临时对象。
但目前没有该循环CPU份额或摘要命中率，不能将“最多24格”直接换算成整体提速。
它减少节点求值工作，不减少A*展开节点数，也不承诺单独完成项目200ms目标。

## 2. 数据来源：活调色板，不再造图

使用当前详细搜索 `PathNavigationRegion` 内实际chunk/section的方块调色板。
它包含该section当前可能使用的所有状态，也可能保留已经不用的状态。

判断方式：

```text
potential(state) = 未知，或可能影响原生邻域检查
paletteSafe = !states.maybeHas(potential)
```

只在所有相关section的整个调色板都安全时快返。
调色板残留危险状态会降低命中率，但不会把危险邻域误判为安全。
同一摘要可以服务不同实体和查询，因为证明的只是邻域钩子和危险分支无影响，
没有共享实体节点、路径、malus或完整可通行结论。

不扫描4096格，不新增详细位图/距离场，不让worker读世界，
不在逐次改块时维护另一套危险计数。
现有宏观成员位图、量化碰撞快照和连通结论都不作为详细扫描的放行依据。

## 3. 状态分类及Forge边界

每个BlockState延迟取得紧凑分类：
已证明无影响、可能影响、未知；未知与可能影响都走原生慢路。
分类按标签语义代次失效，不按每个实体复制一张表。
首次分类同步完成后在本代次内保持稳定；
“尚未计算”与“已分类为未知”分开，不让未完成分类先发布安全结论。
需要改变分类或provider资格时更换代次。

可认证的是实际方法链，而不是“看起来为空气/普通方块”：

- 方块相邻钩子必须是已核对的默认实现，或明确审计过的等价实现；
  要证明返回null且不修改位置、世界或其它可观察状态。
- 默认 `IForgeBlock.getAdjacentBlockPathType` 只检查浆果与
  `WalkNodeEvaluator.isBurningBlock(state)`；分类覆盖这些及原函数的全部其它危险分支。
- 当前47.3.0的 `BlockStateBase.getFluidState` 直接读取预存字段。
  只接纳已核对默认链的 `Fluids.EMPTY`；非EMPTY先全部保守慢路。
- 已核EMPTY实际链：state委托Fluid，Fluid委托FluidType；
  `EmptyFluid` 继承的 `getFluidType` 经ForgeHooks得到
  `ForgeMod.EMPTY_TYPE`，后者显式设置 `adjacentPathType(null)`，
  匿名类没有覆盖相邻路径类型方法。
- 继承默认相邻钩子的模组方块可以按同一证明分类；
  不为测试地图列方块白名单，不用假世界调用一次钩子就推断其为纯函数。
- 标签更新后换语义代次，状态分类与调色板摘要延迟重建。
  不在标签更新时遍历全部世界section。

返回 `inputType` 的非null钩子仍会使原函数提前退出；
返回null但改动MutablePos的钩子也不等价于无影响，两者都不得认证。
raw路径类型、碰撞、门、台阶、落差、水中动作仍由原生处理。

全局Mixin可在不改变Java方法所属类的情况下改写语义，
不能靠反射自动保证所有整合包兼容。
实际支持的邻域方法、state/provider和region/chunk/section读取链要在实现审查中列清；
未知链关闭快路，不增加每节点字节码审计或复杂资格体系。

## 4. 最小摘要维护

使用原生 `maybeHas` 接口，避免为取私有Data再建立容器/owner索引。
调用采用唯一的内部谓词单例；其它谓词保持原查询。

摘要拟放在已核对的原生 `LinearPalette` 与 `HashMapPalette` 本体：

| 情况 | 处理 |
| --- | --- |
| 第一次访问 | 原 `maybeHas` 遍历p个调色板状态，缓存结果 |
| 热访问 | 比较当前size和标签代次，复用正或负结果 |
| 原对象追加状态 | size变化，重算 |
| 扩容、替换调色板 | 新对象没有已算摘要 |
| 两类palette的 `read` | 入口清摘要，包括读入中途异常 |
| 两类palette的 `copy` | 原实现复制新palette/存储，新增字段默认未初始化 |
| `SingleValuePalette` | 不缓存摘要；原 `maybeHas` 实时读唯一状态并查状态分类 |
| `GlobalPalette` | 原 `maybeHas` 恒true，直接慢路，不遍历全注册表 |
| 未知子类或自定义协议 | 不缓存，不强行适配 |

选择palette本体是因为摘要描述“此palette所有成员”的属性，
本来不依赖具体storage或section owner。
拦截其原地 `read` 可以同时覆盖经容器及直接palette读入，
不需要在container、section及所有copy层重复增加失效钩子。

两个不能遗漏的源码事实：

1. `PalettedContainer.read` 可能复用旧Data和palette，在大小不变时替换内容，
   所以单靠对象身份与size不够。
2. `SingleValuePalette.copy` 返回自身，副本read可能改共享value；
   因此不为它缓存摘要，不能只清某个container的缓存就宣称覆盖别名。

两类palette的普通 `idFor` 是追加或扩容；当前已核协议之外的原地替换不在支持范围。
负结果同样缓存，避免在危险/未知section上每次重扫p项。
残留危险项可能直到调色板替换/重建才消失，不为提高命中擅自增加改块热钩子。

## 5. 搜索接入与慢路

在现有prepare入口一次绑定支持资格到region。
热处读取该region字段，不新增逐邻点ThreadLocal、能力匹配、
完整版本链或预算检查。
每次prepare按实际region重新绑定，退出/异常时撤销，
不把请求资格永久留在可能复用的region上。

只包原 `getBlockPathTypeStatic -> checkNeighbourBlocks` 调用点。
其它消费者仍使用原函数。

快判断步骤：

1. 使用传入region自己的chunk引用，不从Level旁路借已加载chunk。
2. 定位实际3×3×3范围，涉及1至4个chunk列、1至8个section。
   内部常见单节走直接分支，边界使用整数循环，不临时分配集合、数组或位置对象。
3. 保留现有非null、非Empty、实时 `hasChunk` 与合法高度条件。
   实际读取链不受支持、缺失、域外、越界或任一摘要不安全，立即进入慢路。
4. 全部安全时返回原输入类型，并把MutablePos设为
   `(centerX+1, centerY+1, centerZ+1)`，与原完整无命中扫描末态一致。
5. 慢路只调用完整原函数一次，保留XYZ首命中、钩子顺序、位置副作用和unknown行为。
   摘要探测本身不设置unknown，不部分跳过混合邻格。

读取链核对还包括原生两个特殊分支：

- debug世界的 `LevelChunk.getBlockState` 可生成并非section存储的方块，
  因此在prepare直接关闭该世界的快路。
- 正常世界的 `LevelChunk` 在 `section.hasOnlyAir()` 时返回标准AIR/EMPTY，
  不读取palette所指状态。此时认证的是实际返回的标准AIR及EMPTY默认链，
  不是凭空节计数直接认安全；认证失败仍原函数。
  非空section才使用上述调色板摘要。这也覆盖自定义空气状态与标准AIR不相同的情况。

整section证明是邻域超集，包含中心列或范围外一些方块只会更保守。
不读过期宏观快照作授权。
省去原读取时，其它整合注入的读取副作用也属于兼容审查边界。

## 6. 线程与发布

快路仅服务本项目现有主线程详细查询，palette摘要在其世界所属线程访问。
不引入异步真实世界读取，也不以新缓存声称支持原生未支持的并发改写。
未知并发palette协议不启用该摘要。

全局BlockState分类和标签代次可能涉及服务端/客户端共享对象，
不能用普通分离字段发布一半更新的“安全+代次”：
实现审查应采用单个可安全发布的紧凑分类戳和相应的代次发布，
避免新锁、逐节点同步或防御循环。palette.read仍在实际修改前失效，
不能以volatile缓存为由声称底层并发读写本身已变安全。

## 7. 完整成本与附带精简

| 项目 | 新成本或保留成本 |
| --- | --- |
| 冷分类 | O(p)调色板状态分类；p不是4096格，但不保证很小 |
| 热命中 | 相关chunk存活判断、1至8个section摘要及少量分支 |
| 安全命中收益 | 删除原24格方块/流体读取、两类钩子和危险判断循环 |
| 失败探测 | 先付摘要探测，再付原生扫描；负收益必须计入 |
| 常驻内存 | 状态分类字段及两类palette少量摘要字段，不宣称精确对象字节数 |
| 冷/维护工作 | 类加载、read失效、标签更新及延迟重算全部计入 |
| 其它调用者 | 新调用点或 `maybeHas` 注入的作用域外分支/包装成本全部计入 |

实际注入选择最少必要层数，不复制原危险规则扫描，
不在正式计时中堆入逐邻点计数。
源码/字节码出现包装、装箱或数组表达，不等于JIT后必然发生同量分配；
同样也不能先验认定JIT会全部消去。
摘要字段也会落到两类biome palette等非本查询使用的实例上；
没有实测对象数/对齐前，不宣称palette放置一定比container放置节省内存。

同一主候选附带临时 `previous` 精简：
四开关与primitive malus数组替换仅用于finally还原的完整能力record及Map。
边界沿用原方案：保留intent完整能力、公共getter的载具语义、
全部setter和默认键、当前evaluator、原try/finally/RAW/proof及异常清理；
不跳同值、不池化，不改业务能力接口。
仍有O(m)读写及数组分配，setter装箱保留。
它在原PathFinder计量窗外，不能把主搜索窗口改善归给这个附带改动。

## 8. 后续验证范围

本轮没有实现或开始验证。后续获准实施时：

- 以U为隔离母版，只做本主候选与用户指定的附带精简。
  P生产、worker、派发、选点、分段和原生搜索策略保持。
- 最小必要正确性控制覆盖危险首命中/位置末态、未知和边界、
  provider副作用慢路、debug/空节实际返回、palette追加/扩容/read/copy及标签刷新。
  这些控制只针对新失效与跳过语义，不新增无关场景。
- 游戏沿用原35ms六场一次筛测；U/P/N身份、接口、场景和计量有效则直接复用。
  不补15/25ms，不加冷热矩阵，不为新配对重跑基线。
- 先用原search、drain、整场CPU/分配、首Path及同路线到达判断净表现。
  如确需补诊断，先说明历史缺失，不把诊断脚手架混入正式计时。
- 不设凭空3%/5%门，不用全项目200ms目标倒推本分支必须节省的CPU。
  若冷成本、慢路额外探测或污染调色板使净收益不足，暂停或不保留；
  不改目标集或搜索顺序去制造收益。
