## 1. 目标与已有证据

目标是减少不同碰撞箱和通行能力下的重复构图、重复存储：优先复用已有的陆地基础连接，在连接不足时，按当前实体的能力局部补充，补充结果继续供后续请求使用。

用户接受优先复用导致的全局最优路线损失。本轮不研究水陆速度比较，不为寻找水中捷径主动升级；水域通行作为额外连接能力，在需要时扩展。实际实体速度、方块 malus 和详细可行性仍由真实原版搜索处理。宏观保留组织候选搜索所需的距离下界等既有结构信息。

此前 [独立持久化原型](../reports/2026-10-13-derived-topology-persistence-prototype-zh.md) 验证了 Base 成品编码及恢复可行性；[有界异步与服务器对照](../reports/2026-10-13-derived-topology-async-validation-zh.md) 未获得跨并发稳定收益，当前 v5 审核仍为 REQUEST_CHANGES，并复现测试 hook 抛 Error 后 future 不结算的缺陷。上述实现不是本方案的通过依据，本方案也不自动解决其遗留问题。

## 2. 已明确的方向与未成立的假设

| 项目 | 当前决定 |
| --- | --- |
| 搜索与复用顺序 | 地面导航优先使用已有陆地基础连接；连接不足时按实体能力扩展 |
| 能力范围 | 尺寸、台阶、跳跃、落差和流体权限继续研究低档复用；开门采用用户新提出的反向基础选择 |
| 复用方向 | 其他能力从较严格条件复用；基础图允许开门，不开门实体在门影响范围局部替换连接，不能直接并集 |
| 共享形式 | 以同一套共享数据表达基础连接和局部差异；具体节点、索引、组件表达未定 |
| 升级方式 | 按需求局部构图并积累结果，不为每次请求预先完整烘焙一套图 |
| 最优性 | 不以全局最短路径为第一阶段目标；不得因此忽略本来存在的连接 |
| 详细寻路 | 真实原版 PathFinder 继续生成实际 Path、处理能力和执行结果 |
| 执行停滞 | 原导航因停滞停止且未到最终目标时直接中止当前分段任务；需要时由正常调用方发起新寻路，不做固定两次自动重搜 |
| 持久化 | 研究保存共享基础结构与必要的局部差异；缓存可丢弃，容量有界 |
| 最新工作 | 固定到达率与真实队列的有限测量/并发原型复审通过；性能证据不足以判定稳定升降，突发拒绝保留；先完善独立重复及报告口径，生产与持久化未认证 |

以下仍是假设：现有宏观构图在能力比较下保持单调；局部升级可在有限成本内补出必要连接；共享表达比完整体型图更小；完整输入校验与升级开销不会抵消收益。不能把这些写成已验证结论。

## 3. 通行能力的比较

候选能力描述记为 `P`，包含导航类型、精确碰撞箱尺寸、台阶上限、跳跃上限、落差上限、门交互能力和允许通过的流体/地形类别。

这是研究中的概念描述，不是拟立即新增的生产 API。能力内容应来自现有真实实体快照，不靠人工前置扫描决定实体是否可走。

在相同世界输入、相同移动类型及其他规则相容的前提下，若 `B` 满足以下全部条件，则记为 `A <= B`：

- `B` 的碰撞箱在相同脚底锚点和坐标定义下包含于 `A` 的碰撞箱，即宽、高要求均不更大。
- `B` 的台阶、跳跃和可承受落差上限均不低于 `A`。
- `B` 的门交互与流体/地形通行权限覆盖 `A` 的权限。
- 其余实际影响候选构图的条件没有使原有移动方式失效。

例如，其他条件相同时，2×1 的体型与 1×1 的体型可以按尺寸比较；更小、能开门、允许走水、落差上限更高的能力组合在概念上可以比较。更小但不能开门，与更大但能开门的两个组合，通常不能逐项比较。

第 14 节曾采用 `canOpenDoors` 相同才继承的保守分离策略。用户随后提出“其他能力做低档，门先做能开门的”，第 16 节以此作为新的研究方向：允许开门条件生成基础连接，不开门实体在受门影响的范围使用原始事实重新生成并替换行，普通区域继续共享。替换也包括空行，避免把基础图里的门边并回来。这个混合方向不是原有逐项单调性的证明，也不保证门框尺寸相异时取得门捷径。canPassDoors、真实 Goal 和其余规则仍需相容，不能把开门权限当作全部门行为的替代。

“高通过/低通过”是这种逐项关系的简称，不是一个能给全部实体排序的标量。走水能力表示增加可选连接，不表示优先走水；台阶或落差能力更高也不表示优先选择这些移动。

复用的工作假设是较弱能力的已有候选连接可用于较强能力。物理碰撞箱的包含关系不自动证明当前离散锚点、支撑处理、组件构造或实际 NodeEvaluator 具有同样的包含关系。第一阶段必须先检验这些映射。

## 4. 与现有图表达的关系

当前 [BaseClusterTopology](../../src/main/java/com/scarasol/acceleratednavigation/topology/BaseClusterTopology.java) 已有两类表达：

| 当前表达 | 内容 | 本方案的研究重点 |
| --- | --- | --- |
| `GeometryKey` | channel、离散尺寸、精确宽高、流体和开门条件 | 不同条件会影响可用锚点、组件和边；跨条件共享仍需研究 |
| `MovementKey` 与边能力掩码 | 台阶、跳跃类别、落差 | 同一 Base 图已经覆盖多种移动组合，不应重复创建整图 |

当前构图先计算体型相关的可用锚点，再标记组件和生成局部边。小体型打开窄通道后，原来分开的组件可能合并，组件编号、元数据和边索引也会变化。现有偶数尺寸的对齐处理和 1×1 的独立处理分支，也需要纳入单调性验证。

因此，“同一张图”首先指共享底层记录和增量，不能直接解释为所有体型始终使用同一份组件标签和编号。

候选结构包括共享位置/入口、连接的能力适用条件，以及各查询的候选视图。查询视图可以是索引或轻量投影；若实际仍需完整重建每种体型的组件视图，应将这部分时间和空间计入结果。

节点究竟采用格内锚点、区域入口、固定小区域，还是保留现有组件并增加跨组件映射，目前不定。先验证可复用关系，再选择表示。

## 5. 陆地基础图与局部升级

### 5.1 基础图

优先烘焙地面类型的陆地基础连接，额外水域连接暂不主动展开。第 19 节建议第一轮只预热一个主基准：精确宽高 1.0×2.0 格，普通一格上跳、不额外提供水平跨沟跳跃，常规落差 3 格，不接受流体、允许开木门。这是待验证起点，不是已通过生产验证的默认值。最新原型把基础开门条件设为允许打开：可开木门在临时宏观事实视图中替换为空气，按现有通用支撑规则重新计算；真实门、门框和铁门事实保留。不开门请求在门依赖范围使用实际门状态局部替换，不能直接交付基础门边。该方向已有第 16 节限定功能证据，最终组件与差异表示仍未确定。

不预设“碰撞箱越大、能力越弱，越适合当基础图”。过于严格的组合可能使基础图很破碎，导致常见实体大量触发升级。第一轮采用一个主基准加按需目标条件行；是否增加第二基准，待升级成本、候选长度和留存实测后决定。

### 5.2 请求流程

1. 捕获当前请求的真实能力、输入身份和代次，取得当前事实。
2. 选择陆地优先的共享候选视图，复用已有且适用的连接。
3. 已有连接足够时生成宏观候选，交给真实原版详细搜索。
4. 连接不足时，从端点映射、搜索前沿或跨 section 的未知连接定位需要升级的范围。
5. 在有界工作量内，针对实际请求能力构建该局部范围；发布前检查输入仍当前。
6. 记录实际完成的局部构图及其适用条件，更新候选视图并继续搜索。
7. 如果实际详细搜索结果无法推进，只在既有有限恢复、缩段或刷新允许的时机研究追加升级；不增加恢复次数或节点限额。执行中原导航因物理停滞停止时按第 18 节中止当前任务，不以停滞为由自动重搜或追加升级。
8. 达到研究中的升级限额仍没有候选时，明确记录候选未取得及原因；不得把未知图当成原版无路。

候选范围与触发算法尚未实现。这里描述的是工作流程，不承诺这些步骤已经可接入现有 Runtime。

### 5.3 升级必须覆盖的情况

- 大体型基础图在窄门两侧不连通，而实际较小体型有连接。
- 起点或终点在实际体型可用、基础体型没有表示的位置。
- 未生成连接位于 section 边界或需要邻区事实。
- 陆地连接不足，实际能力允许通过水域、门或额外落差形成连接。
- 已经找到的候选交给真实详细搜索后，按原有恢复流程需要重选。

升级不能只针对已经存在的路线。没有基础路线时，也必须有定位未知连接的方式，否则可能遗漏本来存在的路线。

“从断开的部分重新搜索”暂理解为从候选搜索未能继续的前沿追加信息，而不是要求实体先移动到障碍前才开始构图。具体前沿选择方法待定。

## 6. 连接标记与未知状态

候选连接至少要区分下列研究状态；名称只是文档用语：

| 状态 | 含义 |
| --- | --- |
| 已有候选 | 当前输入下已生成局部结构，记录其精确条件及可复用范围 |
| 未知 | 尚未针对请求能力生成必要信息，可能需要升级 |
| 局部未连通 | 在明确能力、输入与构图范围内未生成连接，不代表全局无路 |
| 过期 | 输入变化、邻区状态变化或算法版本变化，旧标记不能继续交付 |

基础图不支持某个连接，对更强能力首先表示“未知”。搜索预算耗尽、恢复次数耗尽或原版一次搜索未找到路径，也不能直接写成永久的局部几何否定。

连接的支持范围需要绑定具体空间端点或区域、能力条件、中心及邻区输入，以及相应图版本。宏观构图得到的是候选，不是实体最终可达性证明。

用户朋友所说的“沿路径更新 Mesh 标记”，应进一步明确更新范围：

- 完成一次局部构图，可以登记其实际覆盖范围与能力条件。
- 找到宏观走廊，不能登记整片区域为实际可通过。
- 原版成功路径若作为辅助见证，也只能描述实际搜索覆盖的连接、输入和能力；原生 partial 不能批准完整目标路线。
- 不将这些标记用作详细搜索之前的人工资格过滤。

尺寸支持也不能简单记录独立最大宽和最大高。例如分别有 2×1 与 1×2 的通路，不自动得到 2×2 的通路。不同门/水条件下的两条见证，同样不能按各维度拼出一条未经生成的连接。候选表达可以保存若干带条件的替代连接或不可比较的支持组合，数量必须计费。

## 7. 共享数据与发布

尺寸等局部升级增加更高能力可见的连接，不应改写其他请求的组件结构。最新门方向包含反向限制，因此门条件局部结果还必须能屏蔽或替换基础边，不能只表达增加边。

候选发布方向是不可变版本：共享位置或入口身份、局部构图结果、连接支持条件和查询视图之间有明确版本绑定。组件合并、边界重连和上层聚合索引的变更需要一致发布。既有请求保持自己的当前性判断，不复用新旧组件编号拼接路线。

地形变更、halo 从缺失到加载、卸载重载、能力变化、请求替换和取消，都要使相应旧结果失效。局部失效范围若尚不能安全确定，可先保守失效整个受影响 section 及必要邻区；更细粒度的修复另行比较。

并发请求可以合并同输入、同升级目标的构图工作。不同能力的任务能否通过逐项关系合并，需在单调性及发布关系成立之后研究，不能先依赖“更强任务包办全部请求”。

飞行等 VOLUME 类型、专用水生导航和未适配的同步消费者不纳入首阶段的地面共享结论，沿用当前兼容执行边界。

## 8. 持久化候选

持久化研究对象是共享基础结构、连接适用条件及已经完成的局部差异。持久化完整实体 Path、NodeEvaluator 或旧进程对象身份不在本方案范围内。

记录身份仍需包括世界 namespace、维度、空间坐标、格式/算法版本、支持条件及相关事实内容。所有影响构图的已加载和缺失邻区依赖都要正确绑定；不将 PENDING 或 RECOVERY_FAILED 写成卸载。

恢复时先取得当前事实，再校验记录并重新绑定当前输入，通过发布当前性门禁后使用。没有完成的升级任务、过期标记和迟到结果不作为可用记录恢复。坏文件、丢失、校验失败或资源不足时允许未命中。

两种布局待比较：

| 布局 | 研究内容 |
| --- | --- |
| 独立基础记录与局部差异记录 | 易隔离写入和淘汰，但可能出现很多小文件与关联索引 |
| 按区域聚合的共享记录 | 可减少独立文件数量，但需要解决更新、索引、回收和崩溃恢复 |

现有按完整 GeometryKey 存整份 Base 的格式不能直接宣称已经支持上述共享表示。前一轮 force 和原子提交的经验可以参考，代码及正确性资格不能自动继承。

缓存继续按可丢弃数据处理；不承诺目录 fsync 或掉电后存在性。世界复制/回滚的 namespace 生命周期、目录所有权和索引有界化仍需单独明确。

## 9. 容量与计算预算

此前原型的 128MiB/缓存目录成品额度、16MiB 软件 I/O reservation、8 个在途请求和 2 个 I/O worker，仅作为比较起点，不是本方案已确定的配置。软件 reservation 不是整个 JVM 的实测堆硬上限。

共享模型需要同时统计基础结构、能力条件、局部差异、查询索引、旧版本和正在构图/编码/解码的输入引用。所有能力与体型共用配置的世界额度，不能每新增一种能力就增加一份同样的免费额度。

需有界的对象包括待升级区域、排队和运行任务、支持条件组合、局部差异、索引、文件和临时文件。请求数有限不等于这些对象的总字节有限。

升级不足或被淘汰后允许重新生成，但必须报告额外等待及候选不足。不能用无界升级补偿连接遗漏，也不能通过提高另一对话的动态预算掩盖构图开销。

共享不保证一定省空间。索引更细、能力组合很多或各体型需要大量局部差异时，可能接近甚至超过逐体型完整图成本。比较时同时统计编码字节、文件实际占用、内存留存、索引及临时峰值。

## 10. 尚未确定的问题

| 问题 | 需要得到的答案 |
| --- | --- |
| 能力关系是否单调 | 精确尺寸、离散锚点、支撑、门/流体处理和实际导航模式中，哪些组合能够复用 |
| 基准怎么选择 | 第 19 节建议单个 1.0×2.0 主基准；与更窄、更宽基准的升级成本和路线损失比较尚待实测 |
| 共享什么 | 位置、入口、局部区域还是组件映射；额外索引是否抵消收益 |
| 能力标记怎么表达 | 精确支持组合、范围或若干替代连接，怎样避免组合膨胀和错误拼接 |
| 端点缺图怎么办 | 起终点不在基础图中时怎样定位局部工作，不做前置语义拒绝 |
| 断口怎么定位 | 搜索前沿、边界入口与必要邻区如何形成有限升级范围 |

1. 实体未实际到达最终目标，且原版 Navigation 因执行停滞或原生超时而停止时，结束当前分段任务，终态记为 EXHAUSTED，并记录原生执行停止原因。
2. 停止后续节点和阶段交付，使当前原生交付代次失效，清理本请求的待办与引用，拒绝迟到结果；不在当前任务内排队固定重试。
3. 后续仍有移动需求时，由正常调用方发起新的寻路请求，重新捕获实体实际位置、目标、能力及当前世界输入，走已有正常导航流程。新请求是否采用分段，按正常资格决定。
4. 当前任务的失败回调不自行反复创建新请求，也不把失败任务静默切成整条原版执行。

停滞归因应与主动取消、正常重算、输入过期暂停和正常节点耗尽分开。中间段正常耗尽后的交接、空中等待原导航可搜索，以及输入或能力变化后的当前性重搜继续按各自规则处理。此决定只针对执行停滞，不将这些正常流程归为失败。

原生 partial 属于详细搜索结果；中间 partial 的有限恢复或重选、最终 partial 未到达时 EXHAUSTED 的规则仍按现行契约处理。本条不同时决定取消全部 partial 恢复。

### 18.2 依据与图缓存边界

已记录原型中，没有观察到因停滞而重试后实际到达的成功案例。两组最终主测试共 26 个实际执行导航的场景，只有水域 1 项发生停滞重试，约 3.8%，两次重试后仍失败；排除用户暂不处理的水域后为 0/25。旧版本不重复累计，专门的水域物理对照另计。这是定向场景统计，不代表游戏中的普遍发生率。

“两次”此前只作为有界上限，没有取得改善成功率的证据。执行层使用的本来就是原版 PathFinder；本方案不增加一套运动修复机制来解决物理停滞。

物理停滞不构成派生连接永久无效或宏观几何不连通的证明。保留当次真实 Path、输入当前性、实际位置和终态证据，不因此给共享连接写永久否定标记。
