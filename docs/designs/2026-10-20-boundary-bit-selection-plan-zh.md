# Boundary 合法终点位图与按行选点方案

当前修订主案见[仅替换行位图选择器的方案](2026-10-20-boundary-row-selector-plan-zh.md)。
本文件保留初稿及被拒的 FULL_LAZY 取舍，不是当前实施依据。

## 目标与边界

用户要求优化的是选取时的计算，不能把提前计算最优点、随后读取结果称作 O(1) 选取。
点必须来自原合法候选集合，质量可以不是最优，但不能为省选点开销明显增加绕路和重试。
本案优先保持原评分及最多八个备选终点，避免先引入质量退化再解释性能。

本案是当前生产 S9L 之上的独立后继，不恢复已停止的 S1 V4。
不把窗口枚举迁入主线程，不合并调度任务，不增加每八项完整准入检查，
不改变预算、公平队列、43 ms 截止、物理交接、原生搜索参数和恢复上限。
不承诺这项局部优化能省掉约 300 ms 或达到实际到达增量 200 ms。

本轮不实现候选、不构建、不启动游戏或性能测试、不接入生产、不提交推送。
方案审查走 `deepseek-official / deepseek-flash`、thinking enabled、max；
代码、数据等后续审核仍走原 provider。

## 已核实的现状

普通中间段的正常入口：

1. `GroundSegmentWindow.capture` 在 worker 枚举当前段最后一条连接。
2. Boundary 每个 band 检查 256 位，将置位解码为源点和目标点，
   保留源／目标组件成员检查，使用 `LinkedHashSet<BlockPos>` 去重。
3. 窗口构造立即展开全部正常点的 XZ 曼哈顿半径二恢复邻域。
4. 主线程复制候选、排除失败目标，按下式及 X/Y/Z 排序，最多取八点：

```java
p.distSqr(actual) + .05 * p.distSqr(finalTarget)
```

一次原生详细寻路接收这些备选点，不是八次寻路。
恢复入口还有内邻点数优先级，不适用普通距离评分的代数简化。

`BoundaryTransition` 的每个 band 保存四个 long、来源面、sourceInset、
水平移动方向／距离及 dy；宏观结果已经按本请求通行能力筛选 band。
置位的来源包含源／目标组件身份及快照碰撞校验。
现有 `LocalTransition` 不携带同样的交接点位图，本案不把整个目标组件成员
冒充为该连接的合法终点集合。

## 方案选择

否决“全体合法位中直接取最低置位”：点的合法性有依据，但位序不代表质量。
不采用先逐点评分构造所谓优质掩码、再宣称整体 O(1)。
不预先为任意实际位置和最终目标建立最优点答案表。

送审主案为：

**合并合法终点位图，行内用位运算直接选择接近评分中心的点，
跨行合并得到原评分下的最多八个不同目标。**

质量意图是与旧 full-sort/take8 完全相同，比用户允许的近似选点更保守。
只有数值单调性和等价性得到证明的输入才进快速路径，其他输入走原方法。
审查须主动比较更好的批量空间掩码／近似方法；不得为了通过而忽略严格 O(1) 目标。

## 一、保存集合，不提前选定答案

适用普通 Boundary、attempt 0、失败目标集合为空的路径。
shared、最终目标、LocalTransition、恢复及不支持的数值范围走原入口，
不能因快速路径不适用而拒绝导航。

worker 仍从同一 corridor 快照和同一条边生成合法候选。
将合法目标映射进 destination section 的 16×16×16 位图：

- 64 个 long，共 512 B 原始位存储。
- 沿连接面的 u 方向作为行内轴：N/S 为 X，E/W 为 Z，U/D 为 X。
- 另外两轴组合为 256 行，每行 16 位；四个 long 保存非空行摘要，32 B。
- 多个 band 到达相同目标时按位 OR，自然去重。
- 索引只保存占用集合，不保存当前位置对应的最优点或 top8。
- 每个窗口保存不可变索引；临时取点仅清请求局部的行掩码，不修改共享快照。

保留原源／目标组件校验及所有坐标边界检查。
首版允许 worker 对原置位逐项做无对象的成员校验和映射，必须承认其 O(M) 成本，
M 为各 band 置位次数之和，含重复；不能把这笔工作藏成免费预处理。
可在后续独立证明后改成平移后的成员行掩码相交，本轮不默认已经实现。

原始位存储增加约 544 B／快速窗口，另计数组／对象头和必要元数据。
只建本窗口索引，不增加组件级或全图缓存，不生成新的 topology/component 身份。
索引生成、窗口分配和关闭均进入直接影响范围。

## 二、选取时的行内常数计算

令 a 为本次真实搜索时的实体 BlockPos，t 为当前最终目标。
原评分在实数运算下可写成：

```text
S(p) = |p-a|² + (1/20)|p-t|²
     = (21/20)|p-q|² + (1/21)|a-t|²
q = (20a+t)/21
```

一行中只有 u 改变，另外两轴不变，故评分关于 u 为凸二次函数。
设该行 u=0 的世界坐标为 o，使用 long 算术得到：

```text
Q = 20*a[u] + t[u] - 21*o[u]
pivot = clamp(floorDiv(Q, 21), -1, 15)
```

不能先转成 int 再夹取，负数必须 floorDiv。
16 位合法行分成 `u <= pivot` 和 `u > pivot` 两部分。
左侧用 highestOneBit／numberOfLeadingZeros 取最靠右的置位；
右侧用 numberOfTrailingZeros 取最靠左的置位。
对至多两个位置使用原 double 评分及 X/Y/Z 比较，输出更优者，
只清本地掩码中的该位；继续比较两侧新头。

这是选取时实际计算最合适的位置，不是读取预先选好的点。
一行取一个点的位操作数量固定；取最多八个点最多重复八次，
不逐个枚举行中所有合法位置，也不生成全体点的距离掩码。
掩码位宽固定为 16；pivot=-1/15、空掩码、移位边界必须显式处理。

## 三、跨行保留原八点质量

用四字非空行摘要枚举 R 个非空行，R≤256，不枚举所有候选点。
每行生成至多 min(8, 行点数) 个按原比较器排序的点，
合入容量八的固定大小选择器，最后最多排序八项。
最终只为获选目标创建传给原生搜索的 BlockPos；原评分的无对象算术
必须与 BlockPos.distSqr 的求值次序逐项核对，不能另换评分公式。

正确性理由：全局前八中的点不可能排在所属行的第九位或之后，
否则该行已有八个不同目标在它之前。规范目标位图已去重，跨 band 不会污染名额。
一行最优头已经劣于满八项选择器最差项时，可停止该行继续输出，
但只能使用完整比较器，不能用未经证明的浮点下界剪枝。

完整选择成本是 O(8R)，不是整条连接的严格 O(1)。
单行位选为 O(1)，查询不随 band 数或候选总数 N 逐点评分；
但 N 稀疏时 R 可能接近 N，不能宣称所有输入都渐近改进。
不以 16 或 256 是固定常数来掩盖实际工作上限。

## 四、浮点等价性门

代数中心只决定两侧枚举方向，最终比较仍执行旧 double 表达式和 X/Y/Z。
必须证明两侧分数沿离开中心方向单调，不能仅以实数凸性代替旧 double 行为。

首版建议保守门：行端点与 a、t 在各轴的坐标差绝对值都不超过 65536，
用 long 计算差和边界上界；超出或无法证明时直接走旧 full-sort。
在此门内各平方／求和为可精确表示的整数，
实数同行相邻评分差非零时至少为 1/20；
浮点误差界需正式推导，确保不足以颠倒同一侧的顺序。
相反两侧的同分／近分仍由旧表达式实际计算再决胜。
不改成仅比较 20*distA²+distT²，以免重定义旧浮点顺序。

这是待审证明项，未证明前不得把“完全等价”当成已完成结论。
若审查给出反例，修正数值门或放弃该快速路径，不放宽旧结果标准。

## 五、窗口接口、恢复与生命周期

保留 worker 准备与主线程交付的位置和旧调度入口。
选择保留原调用时机，使用该调用当时的 a/t，不能沿用 worker 时的位置。
`findSegment -> awaitNative` 若保存已选 targets 等待 canUpdate，
本案同样保存该组 targets；不在唤醒时额外重选或重排，不借机修改旧等待语义。
不新增全量准备／选择 checkpoint 状态机。

数值门失配、发现非空失败集合或其他需要旧方法的情况，应在旧 worker 准备阶段
决定并走原准备路径；若只能在交付后发现，需要将同一不可变候选源的物化放回 worker，
沿原排队链交付，明确计入这次额外等待，不在主线程同步补做全量枚举。

普通成功路径不主动展开 BlockPos 列表或恢复邻域。
现有 `candidates`、`nearbyCandidates()` 的内容、顺序、不可变性和关闭后读取
必须保留；拟用惰性只读视图／缓存兼容原接口，正常生产选点走位图入口。
兼容列表需要时按旧 band/bit 顺序枚举并去重，不能改成规范行顺序。
恢复数据需要时仍按旧种子序及 dx/dz 顺序完整生成，沿用原内邻点数排序和重试逻辑。

调用点中的 `candidates.size()`、日志格式化、List.copyOf 等不得无意强制展开。
若历史工具确实启用相应日志，需要把该展开实际成本计入，不能关日志取得新性能。
候选大小可由目标位图的置位计数得到。

惰性兼容视图在关闭后仍可读，需要保留其必要的不可变成员快照／band 数据，
直至视图和窗口均不可达；明确不是 close 瞬间释放全部快照。
不持整个 runtime、活动 Work 或 callback，不建全局缓存。
关闭后 contains/current 仍按原规则失效；取消／迟到结果沿原 future 身份检查和关闭。
若兼容、线程安全或资源代价无法合理闭合，审查应要求缩减到仅替换 selector，
并如实保留原枚举和恢复成本，不以破坏接口换取收益。

## 六、可靠性与成本判断

可靠性目标是和旧候选集合、top8、恢复及搜索行为等价，
不是宣称任意地形变化后 100% 能到达。
不减少八个备选，不引入新的通行过滤，不按当前图重解释旧 componentId。
合法性检查错误或 oracle 不同是停止条件，不能先发布再依赖失败恢复兜底。

成本必须同时列出：

- worker 成员检查、坐标映射、位图合并、非空摘要和计数；
- 新索引、兼容视图、缓存、原快照延长持有的内存；
- 主线程 R 行选择、数值门、最多八项选择器及 BlockPos；
- 真实使用时的列表／恢复邻域物化、关闭及不适用时的原方法；
- 后续真实搜索和实际交接，不用“少排序”推导整场 CPU 或到达必降。

当每行只有一点、原候选很少或快速门经常失配时，新索引可能得不偿失。
是否引入小输入回旧路径的门槛须有数据，首审不拍脑袋定阈值。
