## 三个代码层问题

### 参考点与实际执行段不一致

`PreparedGroundRoute.select` 当前按单连接递推：

```text
edge0 的八点参考请求起点
edge1 的八点参考 edge0 的八点
edge2 的八点参考 edge1 的八点
```

而正常详细寻路通常一次跨两条连接：

```text
实际第一段 [cursor=0,end=2)：
  从请求真实起点出发，直接以 edge1 的八点为终点
```

因此对 edge1 的评分把“已经到了 edge0”作为几何参考，
实际搜索却尚未走过 edge0。后续 stride2 同样存在这个错位。
它不是候选合法集合错误，但可能导致选择对虚拟中间起点便宜、
对本段真正出发位置较差的点。

源码位置：隔离 v5 的 `PreparedGroundRoute.java:25`、
`SegmentedNavigationService.java:512`、`:533`。
四 section 超限、失败缩段以及尾段还会使用 stride1，
因此不能只把上一连接改成“上两条连接”，漏掉奇偶切换。

### 八点的排序不是详细寻路的偏好顺序

原生 `PathFinder` 用到所有目标的最小距离作启发；
发现任一可达目标即结束这次展开，并不是依次尝试第一名、第二名。
当前准备评分不会作为目标的最终总路线代价传入原生搜索。

所以后续若采用出口前瞻、前缀/后缀代价等算法，
必须让提交的整组点都质量足够，
不能只把优质点排在第一，把明显较差的点仍混进其余七个名额。
本轮不因此自行把目标数从八改成一。

源码依据是已保存的上游 `PathFinder.java:73`、`:81`、`:108`，
不是新增测量。

### 几何近不等于整段路程短

现评分为：

```text
min(a in references) [ squaredDistance(p,a) + 0.05*squaredDistance(p,goal) ]
```

它没有墙体绕行、下一出口的真实距离或已走到参考点的前缀代价。
不同参考点取 min 还可能让一个候选只在某个未实际使用的入口下显得很便宜。
这是评分模型的局限，不是位运算选择器算错了该评分。

此外 `localRange` 用八点中最远点距实际起点的距离加八来确定范围，
远处备选即使最终未被采用，也可能扩大搜索范围。
本轮保留原 range，不用调整范围掩盖目标选择的问题。

## 首审否决的候选 A

候选 A 保持原合法集合、平方评分与位选证明，只修正参考点对应的阶段。

把 `targets(lastEdge)` 改成请求独享的 `targets(cursor,end)`。
worker 对每个 cursor 准备 stride1 和可用的 stride2，最多 `2E−1` 组答案。
主线程按实际使用的 `(cursor,end)` 直接取已准备八点。

按 cursor 递增构建：

```text
cursor=0：参考冻结的请求起点
cursor>0：参考所有已准备、且结束在该 cursor 的前驱段八点的去重并集
          即 [cursor−1,cursor) 和可用的 [cursor−2,cursor)
          最多16个参考点
合法终点集合：原 C[end−1]
评分、同分XYZ、最多八个不同目标：保持不变
```

前驱为空只沿用源 anchor 作评分参考，不把 anchor 填入合法目标。
stride1/2、尾段和四 section 缩段都存在对应答案。
实际失败仍用原恢复选择规则；恢复成功后的正常答案仍是预测参考，
不谎称已经匹配未来实际落脚位置。

该方案也有明显成本与质量风险：

- 答案组数最多约翻倍，参考点上限从八到十六，
  Boundary 原始选择工作量最坏约为当前的四倍，不能只报主线程读取成本。
- 仍取不同前驱中的最好情况，不能保证实体实际使用那个入口。
- 未解决障碍绕行、后续出口或原生多目标的整组质量。
- 不能保证实际到达改善，更不能许诺省出固定毫秒。

首审已因此否决 A，不按该版本进入实现。
保留其构造与成本分析，用于解释为何后续改为单参考候选 S。

仅靠增加前驱参考点也不保证质量。一个不涉及地形的反例：
同一行候选坐标为 0 至 15，两个预测入口分别在 0、15，目标在 15。
并集取 min 时，候选 15 的评分为 0，候选 0 为 11.25，
即使实体实际从入口 0 来，仍会让入口 15 的假设主导选点。
这是评分模型的反例，不是本轮新增测试或实际路线的测量。

## 收敛后的候选 S

采纳首审提出的“单一规划引导、避免多参考分支”的成本方向，
但仍按实际 `(cursor,end)` 准备目标，保留原浮点评分和全部旧恢复语义。
没有采用首审给出的算法原稿，理由见后文。

### worker 一次准备两种跨度

```text
r = 本请求冻结的真实宏观起点
for cursor = 0 .. E−1:
    如果 r 缺失：
        r = 当前连接源组件的 anchor，仅作为评分参考

    one = 从 C[cursor] 按单参考 r 的原评分选最多八点
    bank[cursor,cursor+1] = one

    如果 cursor+1 < E：
        bank[cursor,cursor+2] =
            从 C[cursor+1] 按同一个 r 的原评分选最多八点

    r = one 的第一点；one 为空则标记缺失，下一 cursor 再取源 anchor
```

单参考原评分明确保持：

```java
p.distSqr(r) + .05D * p.distSqr(frozenGoal)
```

同分仍按 X/Y/Z；`one` 的第一点指这个比较器下的首项，
不是从无序 Set 任取一点。
它是规划用引导点，不能当作届时实际位置、强制经过点或已算出的详细路径。
八点数量上限不改成一点；只把下一 cursor 的参考集合压成一个规划点。

首段 `[0,2)` 直接参考冻结的请求起点；
后续 `[cursor,end)` 使用对应 cursor 的规划入口参考，
不再使用本段中间连接的参考集合。
实体在宏观计算/等待期间仍可能移动，未来交接也未必落在引导点；
“参考点对应入口”不等于“已经等于执行时真实位置”。
尤其 stride2 实际使用 `bank[cursor,cursor+2]`，
后续引导却由单步链的 `one.first` 递推：
两者在同一目标连接上也可能选出不同点。
因此此方案覆盖所有合法跨度的答案，但不保证所有实际分支的参考点质量；
不能把“bank 存在”写成“已经覆盖真实未来起点”。

### 主线程与边界

- 原规则确定实际 cursor/end、四 section 缩段后，直接读对应 bank。
  正常一条/两条连接、尾段、奇偶切换均有已准备答案，不在主线程再选。
- `E=0` 不创建 bank，保持原 final 分支。`E≥1` 最多 `2E−1` 组。
- 空 `one` 只导致下一参考点缺失；不能因未使用连接的候选为空拒绝整个宏观结果。
  实际选中的 bank 为空时，保持原 unavailable 处理。
- `attempt>0` 和 failedTargets 的原恢复实时评分完全保留。
  恢复成功后仍可沿原流程使用正常 bank，明确它可能偏离实际落点；
  不新增 recovery-only、源 section 拒绝门或其它业务失败条件。
- 真正的详细 Path 仍从当时实际位置在主线程一次准入中计算；
  正常 worker 合并、共享/缓存重放、取消和现有重规划规则不变。
  final、range、物理交接、目标数、常规预算和 idle 截止全部不改。

### 成本与尚未证明的质量

最多 `2E−1` 次单参考查询，复用 one 的首项作为后继引导，
不额外搜索一个 gateway、不增加一个地形距离场。
Boundary 单 bank 为原 `O(8R)`，`R≤256`，完整为 `O(E·8R)`；
数值门失败和 Local 继续用原单参考 full-sort，单 bank `O(N log N)`。
每个目标连接最多查询两次。

原 v5 每连接有最多八个参考点，新候选始终只有一个；
当原 K 较大时可能减少选举工作，当原 K=1 时会多出另一跨度的查询。
这些是工作量边界，不能当作已测得的倍数收益。
完整选举仍非严格 O(1)，主线程 lookup O(1) 仍只是读取。

目标持有最坏为 `8(2E−1)` 点，约为原 `8E` 的两倍，
另计两个 bank 容器与对象成本；共享候选序列/位图不变。
不能只报 worker 时间改善而漏掉活动请求持有。
bank 依赖本请求起点、目标、能力、corridor 与整个引导前缀，
仅由本请求持有，不按裸 corridor/edge 在不同请求间缓存答案。

这只是一个可检验的质量折中：
不再从多个虚拟入口挑最好情况，首段参考点也对准实际段，
但单引导点仍可能选错门口；几何上靠近的八点也可能隔墙绕行。
没有整组点的地形代价保证，没有最坏实际到达上界，更没有 200 ms 保证。

## 对比的更强方法与前提

| 方法 | 可取之处 | 本项目中的限制 |
| --- | --- | --- |
| 实际段的参考点/目标 bank | 对准已有代码错位，可保持正常无往返 | 分支 bank 和参考点成本可能膨胀；未来实际入口未知 |
| 带下一出口的引导、有限宽度门户链 | 能考虑局部跨过边界后往哪里走 | 需要具体定义评分、整组点质量和选举成本；平方距离不能冒充可加行走距离 |
| 组件入口到出口的真实距离表 | 能区分隔墙绕行与直线近 | 需要移动边/门/能力语义，现有成员位图并非完整移动图；额外构建和失效成本不能漏掉 |
| 二维 funnel / Polyanya | 在相应导航网格模型中有成熟依据 | 本项目组件不是凸多边形网格，不能直接套用其几何保证 |
| 平方欧氏距离变换 | 可批量计算带权几何最近参考点 | 不识别墙与通行方向，不自动成为地形路程；须计完整网格构建而非只计查询 |
