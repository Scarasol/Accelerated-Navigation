# 跨隙跳跃导航的实现方式与研究依据

日期：2026-10-26。

状态：源码与一手资料研究完成，形成下一候选的实现方案；尚未实现、送审或进行跳跃性能验证。
本轮只增加研究记录，不改生产业务、不构建、不启动测试、不提交或推送。
现有生产仍为第八十六节完成接入的版本，不能将本文描述写成已经支持的能力。

## 1. 实现选择

采用：**现有宏观组件图提供稀疏有向跳跃候选，位图批量恢复起落位置，
当前详细搜索按需验证并松弛跳跃边，路径携带动作信息，实体通过专门的短跳执行过程跨越。**

借鉴 NavMesh 的 off-mesh connection 表达与机器人运动原语思想。
保留当前原生详细搜索、邻点优化、单次缓存、worker、无时间预算调度和末段合并。
新增工作集中在确有跳跃候选的请求及位置；不把全部普通节点变成弹道模拟节点。
不引入全世界跳跃点对表、全局速度状态搜索、完成路径共享缓存或新的排队阶段。

这里先接通**现有宏观表示范围内的跨隙动作**：
当前结构上限为水平起落单元位移3、上升1、下降4，主要沿四个水平方向。
水平位移3不能表述为跨越3格宽空沟；起落单元之间的空格数量还取决于支撑与体型。
更高台阶、更远跨度、对角跑酷、特殊实体跳跃控制属于能力扩展，不能靠修改一个maxJump宣称支持。
运动模型与动作描述为这些扩展预留参数；不先扩大全部宏观能力编码与测试矩阵。

## 2. 现有源码的事实与接入缺口

| 位置 | 本轮核对事实 | 对实现的要求 |

| `BaseClusterTopology.buildGroundEdges` | 已枚举水平1至3、dy为-4至1，按有向组件对合并能力mask及下界；同组件内跳跃不作为单独宏观边保存 | 复用既有建边成本；不能声称这已覆盖同组件内所有跳跃捷径 |

| `MacroSearch.BoundaryTransition` | 保留方向、水平距离、dy、源侧mask等 | 利用原描述，保持方向、跨section映射及支持能力 |
| `MacroSearch.ComponentSnapshot` | 每组件已有4096位成员信息，但对外仅contains，数组私有 | 在所有者内增加按word消费或派生操作，避免为了跳跃复制全部组件图 |
| `TopologyWorkerRuntime.prepareWorkerResult` | worker完成前汇总组件快照，随后释放图持有关系 | 在同次宏观完成工作内派生跳跃描述；不用先回主线程再排worker选点 |
| `GroundSegmentWindow.enumerate` | 局部连接只查水平相邻一格；仅边界描述能表达较长位移 | 跳跃数据直接挂走廊；该窗口不再充当跳跃数据的唯一入口 |
| `SegmentedNavigationService.finalSegment` | 已可直接搜最终目标，跳过端口window | 合并末段同样必须拿到所有相关跳跃描述，不能让新能力在末段失效 |
| `SharedRows`/`LocalKernel`与`SharedSectionCandidate` | 共享行已经包含具体单元起落点与能力mask；查询按能力筛选并恢复单元路径，但交给详细层的主要是anchors，没有动作 | 直接复用查询所用体型层的细边，输出稀疏跳跃描述；保留同section共享入口，不因实体有跳跃能力就全部改走普通宏观查询 |
| `NativeNavigationSearchMixin.neighbors` | 已有原生邻点扩展钩子，当前只负责失败点过滤等 | 复用钩子追加已验证动作，不复制现有全部邻接规则 |
| 原生`PathFinder` | 32个邻居槽；代价为距离加落点malus；cameFrom仅含节点；权重为1.5 | 处理容量、边代价和前驱动作，不把动作信息或边惩罚错误写成落点固有属性 |
| `NativeWalkedDistanceMixin` | 已接管前驱接受与累计距离同步 | 动作前驱记录与既有钩子合并，避免第二个Redirect争抢同一写入 |
| `NavigationRequestPath.publish` | 只复制原生节点并清零索引 | 同次发布保存节点与对应动作；替换、清空、取消时一起释放 |

## 3. 数学模型：图搜索与局部动力学分别负责什么

对一个请求q，详细候选图可以写为：

```text
G(q) = (V, E_walk union E_jump(q))
```

`E_walk`沿用现有原生规则；`E_jump(q)`仅表示该请求能力、选中宏观连接及当前读取范围内的动作。
每条跳跃边不是一条没有执行含义的直线，而是：

```text
a = (source, landing, launchGate, controller, sweptRegion, cost, dependencies)
```

其中launchGate包括实际脚底位置范围、水平速度范围、朝向及着地条件；
controller包含进入该状态、起跳、空中引导、落地接回步行的控制过程。
同一落点、不同起跳位置或不同进入条件不能无条件视为同一条边。

完整物理状态至少包含位置、速度、朝向和地面/空中模式。
只用一个BlockPos会丢失“当前速度是否足以跨过沟”的信息。
但把全部普通搜索节点扩成位置乘速度乘朝向会明显扩大状态空间。
本方案只在跳跃动作内处理这些状态：满足进入条件时直接执行；
不满足时，仅允许在已验证的安全支撑上对齐、制动或助跑，相关成本明确计入动作。
不能保证安全进入该状态的候选不进入可执行边集。

这是对受支持控制过程的工程抽象，不是任意三维跳跃的完备性证明。
若两个动作需要不同且不能互相恢复的落地状态，不能仅按同一位置合并它们；
首候选优先使用落地后能接回普通步行的动作，避免额外铺开全局速度状态。
完整物理最优、任意动作组合完整和有限动作集最优也不能混称。

### 身体碰撞

固定姿态下，将身体包围盒B从障碍物O中消去，可将禁入参考点集合表达为：

```text
C_obstacle = O MinkowskiSum (-B)
```

这个角度解释了为什么不能只检查脚底或落点。
也可以等价地保留真实身体，对运动扫过的区域进行碰撞检查；
本项目选择后者，以便复用VoxelShape和实体碰撞规则，不实际构建整份膨胀世界。
已有拓扑几何若已按体型处理，不能再重复膨胀一次。

### 离散物理

普通干燥环境中、没有额外状态干预时，竖直部分可按实际游戏tick顺序理解为：

```text
y_next  = y + v_y
v_y_next = (v_y - gravity) * verticalDrag
```

这只描述简化自由飞行阶段。起跳、水平加速、地面/空中阻力、碰撞裁剪、
落地、特殊方块和Forge钩子仍按实际规则处理。
不用连续抛物线替代游戏离散过程，也不把水平路程简单等同于速度乘飞行时间。
普通模型可先由该递推估算可达高度与落地tick区间，排除显然不可达候选，
再重放少量固定控制模板；不对每个格子运行通用连续最优控制求解器。

## 4. 利用位图恢复成对起落点

对于选中连接的源组件成员集合S、目标组件集合T和一个允许位移d：

```text
P(d) = S intersect Shift(T, -d)
```

P(d)中每个置位p都对应唯一候选`p -> p+d`。
位移来自已有边界描述，或局部连接允许的方向、水平跨度和dy。
再与源支撑、能力和粗略净空条件相交；这些步骤依然只形成结构候选。
源起点与落点始终保留配对关系。

一个section为4096位，即64个long。
对于D种位移，位图相交主体是`O(D*64)`，之后输出K个候选还需`O(K)`；
不能把枚举全部点或真实碰撞说成O(1)。
位移必须显式处理16格行边缘、跨word、跨section与负坐标，
不能把整个4096位数组直接移一下造成行尾绕回。
跨section使用原边界mask映射及相邻section数据，不增加世界读取。

保留位移描述和mask，不一开始为每个候选分配BlockPos、List和动作对象。
源点索引使用置位图、每word前缀计数及压缩offset数组：
普通节点可先用一次bit test判断是否存在候选；命中后用popcount/rank定位描述区间。
复杂度是一次定位加该源点实际候选数量，不是所有节点扫描整组跳跃模板。
只读派生在同次宏观worker工作内完成，随后由请求持有，不形成全局完成路径缓存。

同section共享入口有更直接的资产：`LocalKernel.Row`已经保存
`targets[]`与`masks[]`，`SharedRows.query`会按本次movement能力恢复具体单元序列。
该入口直接从本次查询实际使用的体型/门处理层恢复成对候选，
不再用组件位图重新生成一遍已有点对，也不复制整个共享行库到每个请求。
在同次共享worker完成工作中输出所选路径相关的起跳行候选及配对描述，
再交给相同的详细动作验证器；未认证的候选仍不能直接发布为可执行动作。
不能错误使用基准体型层或移除门后的乐观行，代替本次体型和真实世界碰撞认证。
结果当前只含单元路径，候选描述的交付字段也需要补齐；
这一资产减少恢复工作，不表示共享入口已经具备实体跨沟执行能力。

不固定截取“最前一个”或“八个”跳跃候选后宣称整条连接无路。
同一源点到同一落点的多个动作，只有在进入/退出状态兼容、代价支配且验证成立时才可合并。
首个候选失败只否定该候选；资源上限耗尽应返回未完成/不可用，不能冒充全部无路。
普通组件走廊没有直接保存同组件内部的跳跃捷径；
共享细边入口拥有更细信息，二者覆盖不可混写，也不因此宣称全局最优。

## 5. 动作生成、验证与开销位置

### 能力输入

在主线程捕获实际体型、受支持控制器/运动模型身份、移动速度及当前speed modifier、
跳跃初速度、重力、相关效果和起落支撑条件。
当前`NavigationCapabilities`没有这些字段，必须补齐请求级输入，不能从stepHeight推断跳距。
使用纯读取接口；规划时不调用真实Mob的jumpFromGround/travel，不触发事件、瞬移或临时tick实体。
传给宏观的跳距是受支持进入条件下的结构筛选范围，不是当前站立速度下的即时跳距。
不能因实体此刻尚未助跑，就在宏观阶段剪掉能够安全助跑后通过的连接；
结构范围允许也不意味着其中每种起落高度组合均已被物理认证。

标准跳跃增益和Forge重力参数纳入模型。
特殊控制器、特殊travel/jump覆写、水流、弹跳块等不能按普通干燥地面模型硬算。
不认识的能力保留既有安全路径/不可用语义；明确记录本次新增跳跃不支持，
不得伪造跨沟路径或把“普通模型不支持”写成世界绝对不可达。
超出当前宏观结构上限的能力也必须明确，不能静默截断后称完整支持。

### 少量运动原语

使用确定的短跳控制模板，包括满足条件的直接起跳，以及具备安全支撑时的短距离对齐/助跑。
给定实际起落高度与能力参数，通过离散递推得到飞行过程、进入条件和落地条件。
普通地面高度、半砖等使用实际支撑面，不统一硬编码为整数y。
各向同性且规则相同的普通环境可复用平移和90度旋转；
材料、状态、体型或能力改变时不能假定模板仍等价。

模板是纯数值控制与相对运动数据，不是已验证过某处世界的通行证明。
首候选使用请求内按需复用；先不建设需要淘汰和失效维护的跨请求模板缓存。
模板集合只覆盖明确支持的动作，不声称得到论文中经过证明的最小控制集。

### 按需碰撞验证

普通邻接先走原来的路径；只有搜索扩展命中起跳位图，才处理相应候选。
先做能力、位移、支撑和可达区间的便宜筛选，
再对该候选按tick运动使用AABB和VoxelShape进行完整碰撞推进。
复用游戏轴顺序与接触/落地规则，不能只在几个时刻调用noCollision，也不能用一条视线当跳跃轨迹。
落地接触支撑不当作非法穿透；途中撞墙/头顶改变轨迹必须按受支持模型处理或拒绝该模板。

世界/实体语义读取留在主线程，复用现有region、未知区块保护和单次读取缓存。
worker只处理其已有不可变资产和纯数值输入，不读取live Mob或live Level。
若使用快扫掠位图优化，只有“整个保守扫掠区域已知为空且其它条件成立”才可省精查；
粗格与障碍相交只是进入精查，不能一律拒绝半砖、台阶和薄形状。
首个候选先复用原生读取，不为这一快速筛选另建大份碰撞镜像。

每次详细查询记录候选通过/失败结果，避免同一模板重复碰撞验证；
原生搜索结束即释放，与跨tick执行所需的最终选中动作分开。
验证失败就在本次邻接扩展中继续其它候选，不为每个失败重新排worker或重新跑整次A*。
这借鉴惰性验证思想，但没有照搬Lazy PRM的搜索整条路径、删边、反复全图重搜流程。

## 6. 接入当前详细搜索

沿用当前详细搜索内核及原生步行规则。
在已有邻点钩子中为当前节点追加经过验证的落点；无候选节点只走快速旁路。

需要同时完成四件事：

1. 邻居容量随受支持位移的明确上限一次性扩充，不能写越32槽，也不能静默截断。
2. 跳跃的几何长度、动作代价和range累计分别处理。
   动作代价沿边保存，包括必要准备及飞行；落点的路径类型malus仍是落点语义。
   如需将动作时间折算为现行长度单位，使用同一请求的移动速度转换，
   并保持非负、至少不小于端点欧氏距离；不按某几条fixture手调一组惩罚常数。
   该换算只是兼容当前代价体系，不称精确最短实际到达时间。
3. 只在前驱真正被接受时保存对应动作。
   同一落点被更好的普通边或其它跳跃边更新时同步替换/清除动作，
   不把边代价写进共享Node.costMalus，避免污染其它父节点。
4. 路径恢复一次性输出节点和选中的动作位置；与`NativeWalkedDistanceMixin`已有接受前驱逻辑合并。

保留当前1.5权重与目标语义，不新增路线特定启发式。
即使新增边代价满足欧氏下界，也不能把当前加权搜索宣称为严格最优A*。
宏观连接下界、固定走廊、有限动作集也限制全局最优和完备性结论。

同一次扩段或最后目标合并搜索可以包含多个跳跃动作。
不把每个跳跃强制拆成“再搜起点、再搜落点、落地重新排队”的分段流程。
中间段、合并末段、同步prepare/decision入口的能力语义必须一起对齐；
尚未贯通的入口不能先宣称可执行或canReach=true。

## 7. 路径发布与实体执行

在现有请求路径保存与节点对应的稀疏动作数组。
普通路径没有动作数据；节点与动作同次发布、替换和释放，不增加另一套请求所有者。
native trim改写/截断涉及动作节点时，必须同步校验或舍弃失效动作后重新规划，
不能按旧索引继续执行。

执行过程为：

```text
普通路径接近 -> 必要的安全对齐/助跑 -> 起跳 -> 空中引导 -> 确认落地 -> 继续原路径
```

在原导航advance/切角逻辑之前保护动作边界。
进入动作时由现有服务拥有的一份短跳状态控制导航本次输出，
通过Mob的移动与JumpControl触发真实运动，不用setPos或每tick强写位移模拟飞行。
核对原`Mob.serverAiStep`中的navigation、moveControl、jumpControl顺序，
确保后续MoveControl不会覆盖跳跃指令，也不重复发起跳跃。

已经满足起跳条件的实体直接起跳，不统一强制停下归零。
确需对齐/助跑时，该过程必须有安全支撑且已计入动作成本。
飞行中的少量控制与观测属于实体移动tick，不触发新的详细搜索排队。
落地后继续已经计算好的后续节点，不为“到对岸”自动重搜。
到达成功必须包含可靠落地/目标条件，不能只看空中blockPosition碰巧进入目标组件。

### 世界变化与失败

搜索时的有效性不能保证未来世界不变；起跳前复核动作能力、所需支撑及实际扫掠范围。
优先使用现有区块身份/变更信息判断是否需要重验；
粗粒度revision改变只触发相关动作的局部重验，不无条件撤销整条已提交宏观路线。
无相关变化时也须确认实际进入条件，不能把模板的标准初速度当成实体当前速度。

起跳前发现受阻：否定当前动作，继续已有局部候选或走现有重规划入口。
只有候选确实耗尽才能否定该请求中的对应连接；不得把一个起点失败写成全局组件对不可达。
取消、替换、死亡、卸载、能力变化沿用现有请求生命周期，
清理动作数据和控制输出；空中取消不能承诺实体立即静止，要允许物理过程落地。
飞行中突然放置障碍、击退或其它mod改变运动，仍由真实碰撞处理；
本方案不承诺这种外部干预下100%按原计划落地，更不能通过穿墙/瞬移保成功。
失败后从实际位置恢复，不回到已经跨过的旧起点。

## 8. 为什么选择这一组合

| 方法 | 能用的部分 | 本项目取舍 |
| --- | --- | --- |
| Recast/Detour独立连接 | 有向起落位置、特殊动作标记、与普通行走分开消费 | 采用表达与执行边界，不迁移整套NavMesh，也不认为Detour替我们验证了物理 |
| 运动原语/隐式状态格 | 预先表达受动力学约束的局部动作；同模型下利用平移/对称性 | 只在稀疏跳跃动作内采用，不展开整个位置乘速度乘朝向世界 |
| 惰性碰撞验证 | 避免为大量最终不用的候选支付碰撞成本 | 在本次节点扩展前验证，失败继续当前搜索；不常规反复整图重搜 |
| Baritone/Mineflayer跑酷 | 搜索与起跳控制都要实现，考虑支撑、头顶、速度、助跑与落地安全 | 参考业务结构与反例；玩家输入、冲刺距离和经验常数不能直接用于任意Mob |
| 连续轨迹优化/RRT类完整动力规划 | 能直接处理高维运动状态 | 对当前有限短跳接入过重，不选为普通详细后端 |
| 只追加远处落点 | 改动小 | 缺动作可靠性、代价、执行及失效处理，不具备完整接入条件 |

## 9. 性能模型与最低验证范围

新增成本分为：

```text
宏观结果派生 + 起跳位置索引命中 + 实际尝试动作的物理/碰撞验证
+ 最终动作数据 + 实际跳跃tick控制
```

分别记录worker与主线程工作，不把已有跳跃构图成本重复记成新增成本。
跳跃也可能改变宏观选路、详细扩展数量和行走长度，所以净收益不能只由以上局部开销相加推断。
同样不能承诺普通场景完全零开销或某个具体回退百分比。
设计目标是：无候选普通节点没有模板枚举、物理模拟、动作分配；
候选的批量派生、有效候选数、精查次数及分配均可核对。

实施顺序：

1. 在隔离候选内补能力输入、局部/跨section成对描述及稀疏索引，
   独立核对位图坐标映射、方向和原普通结果。
2. 接通同一详细搜索内的动作验证、边代价、前驱动作及发布，
   同时覆盖合并末段，不先开放一个只能规划不能执行的生产开关。
3. 接通真实实体执行，先验证原生标准地面Mob，再谈特殊控制器。
4. 正确性闭合后，只补缺失的候选性能；有效历史普通生产/原生数据直接复用。

必须新增的控制仅服务新增语义：同section与跨section跨隙、不同朝向/速度、
边界/负坐标、上升/下降、头顶/薄形状碰撞、落地余量、能力变化、
起跳前地形变化、飞行中干预、取消替换，以及含跳跃的合并末段。
同一机制可在一组控制内组合，不扩成能力乘地形乘并发的完整笛卡尔积。
既有步行、门、末段、累计距离等有效覆盖优先复用，
必要集成控制使用原接口；不修改旧fixture来掩盖未支持的跨沟语义。

普通性能沿用原高压接口、负载、并发及计量；先复用已有35ms六场作为原生产对照。
跳跃正确性没有有效历史执行证据，须补实际实体控制；
原生无法跨越的路线按到达能力比较，不能把失败的原生请求当同工作量CPU基准。
分析同时看首Path、实际到达、搜索总工作、worker派生、tick峰值及分配。
必要对齐/助跑的行走耗时不能隐藏在搜索计时之外后宣称免费。
目前没有新增性能样本，不能给出回退已受控或可生产接入的结论。
