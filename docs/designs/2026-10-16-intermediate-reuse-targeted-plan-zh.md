# 中间产物复用的针对性优化

日期：2026-10-16。用户授权结合工具栈反馈继续针对性优化。新原型目录 `.tmp/intermediate-reuse-targeted-20261016/`；上一轮源码、结果与审核全部封存，不改写。

## 要解决的问题

上一版普通单体型完整 Base +10.6%，两体型近乎持平，四体型 -26.4%；归因控制表明跨体型留存自身 -16.4%。原始行建立使用逐格取 flags 再逐位打包，且首次使用即留存整个源对象。应检验建立成本是否可以降低，并补齐实际运行时的消费关系。

先跑两组隔离服务器诊断：16 个同体型实体，及总数相同的四种体型混合实体。两组均为受控新场景，不是原 spark 实服场景的回放，不代表用户历史负载的真实复用率。场景就绪真实 30 秒后才派发；原生产调度、Base/Super 选择、真实详细寻路、自然终态保持原逻辑。

场景修订：首次混合组沿旧局部核的 `.6×1.8/.9×1.4/1.2×2.2/2×2`，后两项超出生产 `macroSupported` 的 width≤1 门限，实际只捕获两种宏观体型，且发生原生 `EXHAUSTED`，不进入正式对照。原件保留于 `capture-mixed-v2`；正式混合组改为 `.6×1.8/.9×1.4/.8×2.4/1×2.8`，派发前逐实体断言宏观支持及所需 Geometry 图冷态。此修订仅约束新实服场景，宽体型完整图正确性仍保留。

在原 runtime 实际进入 Base.build 的位置记录 work、worker、section、源 facts 对象身份、GeometryKey、中心及 halo 输入和消费时间；同键 Base 缓存命中不冒充新构建或共享行机会。源身份以对象引用分配 ID，不以 fingerprint 猜测身份。记录分 worker 的重复关系、跨体型消费与间隔；中心角色和 halo 角色区分。有界捕获不可变源输入，服务器停止后写出，供后续逐项复算及内核重放；诊断新增引用和插桩不得被当成候选内存或无插桩性能。

## 固定候选

只优化原始事实共享层，精确形状、门回退、侵蚀、组件、边、完整发布校验均保持原语义。

1. `packed`：直接读取 packed facts 的 8 字节行，以固定掩码/移位转置为四个 16 位位平面。避免旧版每格逐位拼装的建立成本；产物和身份规则不变。转置需校验 64 个单比特基向量、全 flags 组合、随机输入与完整图。
2. `admitted`：沿用 packed 表示；中心源首次消费只记录有界弱引用与该次 GeometryKey，走原行生成；同源出现另一 GeometryKey，或其原始行已因别的合法消费者存在，才建立/使用共享层。弱记录与共享缓存各限 64 源，FIFO；未晋升时不能强留源 facts。它由已发生的消费关系决定，不预测耗时，不涉及历史预算或跨 tick 偿债。

基线、旧版复用、新 packed、按需晋升按同一新冻结测量壳对照。若诊断没有足够真实构建机会，不用人工重复构建填充实服命中率，也不宣称该负载有共享收益；局部表示建立的独立结果可以保留。

## 验证顺序和门

- 冻结当前源码、旧版候选与输入，登记来源；本轮不修改生产、不提交/推送。
- 先补真实 runtime 消费轨迹，JFR 自定义事件、实际事件配置、DataLoss、线程覆盖、首次 Path、自然终态和清理完整保存。诊断时间不作净收益。
- 正确性：上一轮 50×21 fixture/Geometry 基础，增加不同 halo 独立源对象、捕获的实服输入、同体型重复不晋升、跨体型晋升、GC/淘汰/清空与代次变化。比较全部图字段与 legal/prism/volume/ground/haloUsed；精确判定次数不能被错误合并。
- JMH 1.37，固定 3 fork、3×1s warmup、5×1s measurement，关闭阶段/计数，消费真实结果；包含建立、查找、弱记录、晋升、淘汰和清空。以捕获的真实构建序列与同体型无复用对照为主，按真实 worker 隔离缓存。旧版合成 alias-halo 不作为主性能输入。
- 单体型目标：完整操作平均回退不超过 3%；3 fork 范围重叠时仅记未观察明确回退，不冒充统计非劣证明。混合轨迹须有可重复的完整成本改善，原生计数与表示建立控制支持其归因；未满足就停止该变体。
- ThreadMXBean 仅作批量 CPU/分配；已知 CPU 粒度 15.625ms。Instrumentation 分开测共享行、弱元数据、源闭包与 clear 后根；列出捕获场景最大源闭包，不能把该值当通用最坏上限。
- 只有局部门通过，才做关闭深度诊断的小范围同体型/混合体型端到端对照；独立 JVM、真实 ready 后 30 秒、首 Path、自然到达、完整 tick、失败与清理均登记。没有通过就不扩展大矩阵。

DeepSeek 用 WSL 原生 dsh，provider=deepseek、model=deepseek-v4.1-flash；每包自足 UTF-8≤6500B、本地截止900秒，保留原请求/答复/退出。新包不能假定旧无头会话上下文。结果支持到哪里就收尾到哪里，不以工具准备或局部验证冒充生产通过。

## 端到端结论边界澄清

局部JMH门通过后已按原定首Path、自然终态、完整tick及清理指标启动8个独立服务器观察；性能审查返回时已有首对同体型运行完成。原方案没有预登记整服非劣数值、GC暂停数值或复杂源最坏内存门，因此不能事后补一个数值并称预登记验收，也不将这8运行标为整服性能通过。仅报告每个独立JVM的指标、两次运行范围、失败和异常，功能/资源清理单独判定。未开标准GC日志或深度JFR的净运行，其GC归因记为未测，不能称GC已通过。

复杂几何的语义沿既定正确性集校验；真实复杂场景收益和复杂源内存最坏上限继续未知。若未来进入生产接入决策，须另行预登记这些门和更充分独立JVM设计后验证，本轮不追加成生产优化或另一个场景大矩阵。admitted只是不作为本轮首选，不能由三输入外推否决其所有负载。
