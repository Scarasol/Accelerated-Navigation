# 启动历史干预持续时间的补充对照

本补充由资格试运行触发，在主矩阵完成前登记。v2 接线 normal 首次排队 561.2875ms、总等待 758.2040ms；both 首次排队 60.6126ms、总等待 714.7908ms，第二次排队 486.6048ms。首次派发后按原计划恢复原 p95，后续真实工作债务继续存在。不能据此前移当作整体修复，故只验证“历史干预何时停止”这一因素。

## 范围

仍固定 candidate-v5、平地、Husk、Base、第 30 tick、冷态/facts/真实 query 资格。补充源码隔离在 `.tmp/cold-scheduler-causal-20261015/supplement/`，主矩阵 v2 探针、源码和原始结果不改。

同一个新探针包运行两组，均使用 both：只在首次 queued END 至多一次把负余额补至零，实际计费和后续负债保持。唯一变量为基础 p95 排除全局有效序号 1–8 的研究干预，在首次派发后恢复原值（transient），或保持至首 Path（hold）。EWMA、tail、previousFull、增长限制、haveTime、截止、最小片及原子调用保持。不得持续补零或抹掉新工作负债。

每组四个独立 JVM，共八轮，预先固定 transient/hold、hold/transient、transient/hold、hold/transient。另先两轮接线，不混入主要八轮。不得以旧 v2 both 代替同包 transient 组。以分组原始首 Path 等待为主要结果，同时列首次排队、后续排队、信用剂量、p95/EWMA 绑定及完整 tick。

源码差异仅限 SchedulerResearch 的测试属性、干预持续条件和输出元数据；重建后逐 ZIP 项核对，其余所有 class/资源内容须同 v2。新包的两组也必须同一 SHA。新增控制项在补充独立读取器核对，主机仍用未变换生产 Controller 精确重放。

## 判别与限制

若首次派发相近而 hold 后续排队缩短，支持原历史估计恢复使后续调度再受限这一机制；若无改善，报告实际绑定、授额和负债，不剔除样本或改参数。若信用后又负债，照实报告，不能把该组称为无债运行。

即使整个首 Path 更快，仍是单实体、单路线、四次重复下的研究干预，不是生产候选、长期性能、固定长时间 tick 安全性或整条到达验收。尤其不能从此直接批准跳过真实高负载历史；正式方案还须保留过载保护并验证负载差异。持久化、生产算法与参数不改。

## 方案审核门禁

WSL 原生 dsh 的 `scheduler-hold-plan-v1` 返回 ACCEPT_WITH_GATES、本轮必须修改项无。执行时核对首次 queued END 的信用记录早于首次派发；逐轮列出实际补零次数、绝对剂量及补零后的真实负债。两组使用相同规则，但独立 JVM 的实际信用剂量不保证相等，不将其称为严格相等剂量试验。固定交替顺序并非随机，原始四轮数据、p95/EWMA 绑定与授额同时保留；解释限于与研究干预一致或不支持，不能单凭组间等待差异断言恢复历史估计造成全部延迟。
