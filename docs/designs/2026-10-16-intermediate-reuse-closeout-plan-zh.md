# packed 原始事实行复用接入前收尾

日期：2026-10-16。用户授权继续收尾，并允许双方受到相同探针干扰的对照方法。仅操作 `.tmp/intermediate-reuse-closeout-20261016/`，生产代码只读，不提交推送。上一轮证据保持封存。

## 固定范围

候选为上一轮 packed，原行逻辑 baseline 作对照。不恢复持久化、历史预测、偿债、预算调参或 Portal 支线。先查复杂源内存边界；若强引用缓存超过下面的门，原版本明确失败，可在独立版本中仅修改源持有方式，再重新验证，不能把旧性能数字转记为新版本结果。

1. 用 Instrumentation 测量 palette=4096、每个非保留 shape=64 boxes 的合法上限源，分别测单源、64源缓存及 clear。缓存新增强可达内存门为每 worker ≤8 MiB；多 worker 总量按实际/配置数量乘算。允许弱键变体，但必须证实无强引用绕路、FIFO≤64、GC 与 clear 释放，以及同输入正确性。
2. 真实服务器包含平地同体型和复杂几何混合体型两个受控场景。复杂场景含 Minecraft slab、stair、fence、wall、trapdoor、door，保证通路；诊断证实实际读取 Exact 格及门回退，不能仅凭场景布置宣称覆盖。
3. 冷图校验提前到 ready+29 秒；真实请求在 ready+30 秒后另一个 tick 派发。记录校验遍历量、耗时及 tick；完整 tick 不裁掉派发工作。剩余探针代码、配置、采样位置两侧一致，分别记录观察探针调用次数/耗时。共同探针下数据支持相对对比，不认证无探针的生产绝对耗时。
4. 每场景每模式4个独立 JVM，配对交错顺序 AB/BA/AB/BA。每次16实体，自动宏观/详细寻路，自然终态，无 whole fallback，清理归零。只在场景就绪30秒后派发。失败保留，不以实体数充 JVM 样本量。
5. 首 Path 为 tick 末首次观察到 nodes；按 JVM 算中位数后比较。预设工程筛选门：候选/基线的4对均值比≤1.10、配对均值差单侧90% t 上界≤基线均值20%；完整 tick p99 均值≤基线×1.10+1ms、max 均值≤基线+10ms；每 JVM >50ms tick 数均值不多于基线+1。只作本场景小样本接入筛选，不作普遍统计保证。
6. 双方同开低开销 GC 日志，记录 ready/提交/结束的 JVM uptime；只统计真实请求窗口与暂停交集，根 GC 不重复累计。候选每 JVM 暂停总量均值≤基线+5ms、最大暂停均值≤基线+5ms；未发生 GC 只能表明该窗口无事件。深度 JFR 与逐格计数另跑诊断，不进入净对照。
7. 若改变缓存持有方式，重跑已有正确性及三个既有 JMH 输入（3 forks，3×1s warmup，5×1s measurement），完整操作含建立/查找/clear。平均耗时≤baseline×1.05；复杂真实捕获回放增加同配置对照，不用热内核替代整服结果。
8. 核对当前生产相对冻结输入的变化，列出移植条件；不修改另一会话的代码。按≤6500 UTF-8字节、自足摘要分包交 DeepSeek，provider=deepseek、model=deepseek-v4.1-flash、900秒本地期限，实际最终答复才记共识。

## 结果规则

任一正确性/自然终态/清理失败即停止该版本接入结论。性能或内存门失败如实登记；不测后改门、不调预算/JVM救结果。可补做定位，但补充结果与固定矩阵分列。报告区分旧强键 packed、新版本（若有）、诊断和净对照，并明确“可开始移植”和“生产已验收”之间的差别。
